# 사후 실행 점검 기록

사전 고정 12건 × 4조건의 첫 결과를 본 뒤 작성했다.

- 규칙 선별 Top-1은 2/12, 단순 수치 변화 기준점은 11/12였다.
- 모델 digest, 익명 ID 채점, 실제 응답 및 생성 종료 상태를 확인했다.
- 한 사례의 기록만 조건에서 `[S01,S02,S03]`을 그대로 출력하는 현상을 확인했다.
- 실제 12건을 다시 묻거나 프롬프트/규칙/모델을 바꾸지 않는다.
- 별도의 합성 입력 두 개를 같은 모델·프롬프트·설정에 제공한다.
  6개 서비스 중 하나만 CPU 변화 점수 100이고 나머지는 0인 입력이며,
  원인으로 지정한 서비스를 S02에서 S05로 바꾼다.
- 목적은 단순한 입력 변화에도 응답이 반응하는지 확인하는 것이다.
  두 합성 입력의 성공을 실제 RCA 타당성이나 성능 개선 증거로 취급하지 않는다.
- 결과는 `smoke/posthoc-synthetic-sanity.json`에 따로 저장한다.
