# MLP 연구의 비교 기준 및 실험 진입 조건

> 후속 실행 결과: [선행조건 실제 확인 결과](mlp_prerequisites/결과_보고서.md).
> 공통입력 비교 모듈·평가기·분할을 구현하고 실제 학습12회/재검증12회를 완료했다.
> 아래 NO-GO와 모델0개 기록은 실행 전 검토 이력이다. 원 논문 전체 파이프라인의
> 성능 재현은 여전히 완료되지 않았으며, 공통입력 실행 성공과 구분한다.

## 판정

**문헌에 근거한 비교 설계는 정리했지만, 성능 비교 실행은 아직 NO-GO다.**
자체 선형/MLP 비교는 ablation이지 기존 연구 대비 경쟁력 검증의 대체물이 아니다.
이번에는 공개 코드의 평가 절차만 합성 사례와 정적 검사로 확인했다.
MLP 학습, 원 데이터 다운로드, 보호된 144건의 열람은 수행하지 않았다.

## 1. 앞선 연구 구상에서 바로잡을 점

DiagMLP는 모든 노드의 표현을 연결한 뒤 Node_Fusion_MLP로 시스템 수준 표현을
만든다. 따라서 “기존 MLP는 서비스별 이상만 독립적으로 보므로, 우리가 처음으로
사고 전체 맥락을 준다”는 주장은 성립하지 않는다.

검증할 차이는 **동일 관측에 접근하는 기존 전체-노드 MLP와 비교했을 때,
명시적 사고 내 대조 표현 및 공유 서비스 점수화가 도움이 되는가**다.
서비스별 입력만 받는 작은 MLP를 이겨도 이 질문에 답한 것이 아니다.
실험 결과에 따라 표현의 효과, 학습의 효과, 적용 조건을 축소해서 주장한다.

## 2. 비교 후보와 원래 데이터

| 역할 | 연구 | 원래 방법/데이터 | 이번 비교의 조건 |
|---|---|---|---|
| 가장 가까운 주 비교군 | DiagMLP, ICWS 2025 | 기존 Eadro/TVDiag/DeepHunt의 전처리·임베딩을 유지하고 GNN을 모달/노드 결합 MLP로 교체. Eadro의 SN/TT, TVDiag의 GAIA, DeepHunt의 D1/D2 | 일반 MLP를 DiagMLP라 부르지 않는다. 원문 구현과 공통 입력에 맞춘 변형을 구분한다 |
| 기존 다중 자료 학습 방법 | Eadro, ICSE 2023 | 로그·메트릭·트레이스 인코더, GAT, 탐지·원인 위치 공동 학습. SN/TT | 정상/장애를 포함한 end-to-end 평가와 이미 주어진 장애의 원인 순위 평가를 분리한다 |
| 강한 비학습 수치 기준점 | BARO, 2024 | 메트릭 변화점 및 중앙값/IQR 기반 원인 지표 순위화. 원문은 3개 시스템의 300개 주입 장애 평가 | 공식 알고리즘 경로를 검증한다. 서비스 단위 변환을 고정하고 임의 상한 점수를 사용하지 않는다 |
| 저널 기반 확장 비교 후보 | DiagFusion, IEEE TSC 16(6), 2023 | 다중 자료의 이상 이벤트 표현 및 그래프 학습. GAIA MicroSS(D1)와 비공개 은행 자료(D2). 서비스 그룹 예측 후 이벤트 수로 그룹 내 인스턴스를 순위화하며 장애 유형도 예측 | 서비스/인스턴스/그룹의 변환과 별도 정답 사용을 명시해야 한다. 현재는 drop-in 실행 가능하다고 확인하지 못했다 |

DiagFusion 원문의 시간순 train/test 사례 수는 D1 160/939, D2 80/79다.
GAIA MicroSS와 RCAEval RE2-OB를 같은 데이터라고 부르지 않는다.
같은 TrainTicket 명칭이어도 Eadro TT와 RCAEval RE2-TT는 동일 데이터가 아니다.

DiagMLP arXiv v2 Table I의 train/valid/test 수는 SN 316/78/169,
TT 3256/813/1744, GAIA 128/32/939, D1 63/없음/147, D2 40/없음/93이다.
이 수는 각 파이프라인의 표본 수이며 RCAEval의 독립 사고 수와 동치가 아니다.
D1/D2에는 표상 별도 validation 수가 없으므로 모든 데이터가 완전한
train/validation/test 프로토콜이라고 일반화하지 않는다.

### 출판/버전 구분

- DiagMLP 출판 서지는 Crossref에서 ICWS 2025, pp.127–129,
  DOI `10.1109/ICWS67624.2025.00025`로 확인했다.
- 방법/실험 조건을 읽은 공개 전문은 arXiv v2(2025-03-10, 6쪽)다.
  출판본과 문장별로 동일함을 검증한 것은 아니다.
- 저자 Eadro 저장소와 확인한 전처리 fork는 실제 GAT 코드를 포함한다.
  확인한 main 트리에서 DiagMLP 재현 진입점을 찾지는 못했다.
  이를 “인터넷 어디에도 구현이 없다”는 주장으로 확대하지 않는다.

### 추가 조사 범위

국내 AnoProp 관련 KCI 초록은 회귀 기반 메트릭 이상과 전파 점수,
Online Boutique 평가를 확인하는 데 도움이 된다. 다만 정확한 서지,
라벨 단위, 분할, 공개 구현은 충분히 확인하지 못해 주 비교군으로 확정하지 않는다.
검색에서 얻은 DOI `10.5626/JOK.2025.52.4.1`은 해석되지 않았으므로 인용하지 않는다.
메트릭 전용이라는 이유만으로 배제하지 않는다. 서비스 단위 변환이 가능하다면
보조 비교군이 될 수 있다. 국내/해외 문헌의 수를 맞추기 위한 추가 조사는 하지 않는다.

## 3. 실험을 세 층으로 분리한다

### A. 레퍼런스 재현/교정 확인

우선 Eadro SN/TT 등 원 데이터에서 가장 가까운 baseline의 입력·레이블·출력·분할을
확인한다. 데이터는 Zenodo에 공개되어 있으며 이번에는 파일 목록만 조회했다.
SN zip 78,753,809바이트, TT zip 48,923,113바이트다.

원본 코드 실행과 수정 프로토콜 실행을 구분한다. 오류나 누수 위험을 발견했을 때
원본을 그대로 평가에 재사용하지 않으며, 수정은 제안법과 비교법에 동일하게 적용한다.
문헌 숫자와 자체 실행 숫자를 하나의 직접 경쟁 표에 합치지 않는다.
원문의 수정된 분할을 얻지 못했다면 새 분할을 “원 논문 재현”이라고 부르지 않는다.

### B. 동일 과제에서의 전체 방법 비교

주과제는 **주어진 사고 구간에서 원인 서비스 하나를 순위화하는 것**이다.
같은 사고, 후보 집합, 사용 가능한 관측 구간과 정답 경계를 적용한다.
원시 자료 접근은 공정하게 하되 각 방법의 고유 전처리/인코더는 유지한다.
제안법의 간단한 특징을 모든 기존 방법에 강제로 넣고 원 방법이라고 부르지 않는다.
BARO가 원래 메트릭만 쓰는 것은 허용하며 모달리티 사용량을 표에 표시한다.

현재 RCAEval RE2-OB/TT 180건은 동일 과제 비교를 위한 후보 자료다.
보호된 144건의 원자료를 열기 전에 그룹 단위 분할을 고정한다.
이미 확인한 개발 36건은 최종 시험에 재사용하지 않는다.
같은 주입 서비스·장애 종류·조건의 반복을 서로 다른 분할에 섞지 않는다.
정확한 manifest와 클래스 지원 범위는 아직 만들거나 검증하지 않았다.
기존에 보던 원인 서비스 평가와 학습에 원인으로 없던 서비스 평가는 별도로 보고한다.
제안법의 장점을 겨냥한 후자만으로 주결론을 내리지 않는다.

### C. 공통 표현에서의 구성요소 실험

동일 특징/분할에서 선형↔MLP, 대조 정보 유무, 품질 정보 유무를 비교한다.
기존 전체-노드 MLP에도 사고 전체 정보에 접근할 기회를 준다.
입력 차원/정보량/파라미터/학습 예산을 기록하여 추가 정보의 효과를
특정 아키텍처의 효과로 오인하지 않는다.
공통 특징으로 바꾼 DiagMLP 등은 `adapted/common-input`으로 표기한다.
이 층의 결과만으로 원래의 전체 방법보다 우수하다고 주장하지 않는다.

## 4. 결과를 보기 전에 고정할 평가 계약

| 항목 | 계약 |
|---|---|
| 입력 경계 | 사고 구간·정상 기준·모달리티·토폴로지·서비스 ID·관측 지연의 접근 조건을 방법별로 기록 |
| 후보와 정답 | 모든 방법에 같은 서비스 후보. 정답/주입 유형으로 후보를 미리 줄이지 않음 |
| 라벨 사용 | root 정답은 학습/검증의 정해진 역할에만 사용. 추가 장애 유형/정상 라벨은 별도 표시 |
| 전처리 학습 | 정규화·임베딩·임계값·어휘 등 학습 파라미터를 시험 자료에 맞추지 않음 |
| 분할 | 사고/반복 그룹을 보존하고 가능한 경우 원 연구 분할도 별도 평가 |
| 모델 선택 | 원 방법 권장 설정을 존중하고 비교 가능한 튜닝 예산 제공. validation만으로 선택 |
| 점수 | 사고 단위 Top-1 주지표, Top-3/MRR 보조. window 결과는 별도 표시 |
| 동점/결측 | 사전 고정 규칙을 공통 적용. 실패 사례를 조용히 제외하지 않음 |
| 통계 | 같은 사고를 기준으로 paired 비교. seed/window를 독립 사고로 세지 않음 |
| 비용 | 전처리·임베딩·학습·추론 비용을 구분. 일부 단계만 빠른 것을 전체 속도로 주장하지 않음 |
| 해석 | 사전 지정한 주비교와 조건 전체 보고. 유리한 시스템·장애·분할만 사후 선택하지 않음 |

시험에서 개선이 없으면 방법을 기각/축소한다. 시험 결과를 보고 특징·분할을
다시 고친 뒤 같은 시험을 확증 평가로 재사용하지 않는다.
과거 서비스별 원인 빈도 기준점은 추가 진단 통제로 유지하되 문헌 경쟁자의 대체물이 아니다.

## 5. 공개 코드 준비도 검사 결과

원 저자 저장소 고정 커밋:
`BEbillionaireUSD/Eadro@82ff9c9a7a58a9cd2b713aa78754a73c543a15db`.

`verify_reference_protocol.py`는 원문의 특정 함수 AST만 검사하고,
평가 함수에 한해서 모델/텐서 의존성을 합성 fixture로 공급한다.
실제 모델·PyTorch·DGL·전처리를 실행한 검사가 아니며 NDCG 구현도 검증하지 않는다.
다운로드한 두 소스는 Git blob 해시와 대조한다.

확인된 결과:

1. `fit`은 `test_loader`의 HR@1로 최적 checkpoint를 고르는 경로를 가진다.
2. `get_basic`의 단위 간격 겹침 window와 `split_chunks`의 무작위 chunk 분할이
   결합된다. 길이 10인 인접 두 window는 관측점 9개를 공유할 수 있다.
   실제 원 자료의 분할 간 누수율을 측정한 것은 아니다.
3. 정답 원인을 1위로 맞힌 장애 하나에서 HR@1=1.0,
   정확히 정상으로 판정한 정상 window 하나를 더하면 HR@1=0.5다.
   이 분모는 이번 과제의 “장애 사고만을 대상으로 한 원인 Top-1”과 같지 않다.
   이를 근거로 모든 논문 결과가 무효라고 주장하지 않는다.

DiagMLP v2 §IV-A Notes (3)도 Eadro의 window 분할 누수 위험 수정과
검증 집합 추가를 명시한다. 따라서 위 원 코드 상태를 DiagMLP의 수정된 평가와
혼동해서는 안 된다.

검증 명령:

```sh
python3 research/verify_reference_protocol.py
```

이번 실행: **exit 0**, 원인 순위 분모 예제 및 정적 조건 확인.
파일 LSP diagnostics: **없음**.
학습 모델 **0개**, 읽은 실제 사고 **0건**.

## 7. 사용자 제안에 대한 제한적 반박

- 최신/저널/국내외 여부만으로 적합성을 보장하지 않는다. 같은 정답 단위, 입력 조건,
  학습 자료 접근권과 실제 재현 가능성이 먼저다.
- 모든 방법에 같은 가공 특징을 강제하는 것은 전체 방법 비교에서는 오히려 불공정할 수 있다.
  원시 자료 경계와 고유 전처리를 보존한 비교, 공통 표현 통제를 분리한다.
- 기존 방법 비교만으로 내부 기여를 알 수 없다. 문헌 경쟁자와 자체 ablation 둘 다 필요하다.
- 최신 방법 전부를 재현할 필요는 없다. 다만 선별한 비교군만 평가했다면 SOTA 전체를
  능가했다고 확대하지 않는다. 광범위한 최고 성능 주장에는 더 넓은 최신 비교가 필요하다.
