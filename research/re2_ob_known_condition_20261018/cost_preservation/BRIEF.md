# 로그 전처리 비용 재검토 — 특징값 보존 우선

## 승인 범위

사용자는 템플릿을 바로 줄이지 말고 비용 추정·병목과 **기존 특징값을 유지하는**
중복 계산 제거·캐시 재사용을 먼저 확인하라고 지시했다.
가능하면 원래48/24 기준선·오류 분석으로 이어가되, 입력 표현 변경이 필요하면
변경 규칙·비용·영향을 먼저 보고하고 적용하지 않는다.

이 단계에서는1025차원,48/24,모든사건/창,정상TRAIN 템플릿,상대시각,
seed42,초기 baseline0.2,solver·정규화·학습 계약을 그대로 유지한다.
템플릿 삭제·통합,시각 반올림,빈 이벤트 의미 변경,iteration 축소,근사해 허용은 금지한다.
신경망 학습·모델 평가·특징 제안 대조는 아직 수행하지 않는다.

## 이미 확인한 비용 근거

- 실제 solver는 **HawkesADM4**다. 다른 Hawkes 알고리즘으로 바꾸지 않는다.
- 전체143,822 case/node/window 위치 중52,762개는 실제 로그가 없어0벡터다.
- 나머지91,060개는 기존 정확한 knot-key 캐시로80,028개 입력으로 중복 제거됐다.
- 기존3개 표본시간11.4102/14.2781/43.5264초의 평균 외삽은
  `80,028 × mean(seconds) / 4 ≈ 128.22시간`.
- 16작업자의32.06시간은 단순히4배의 완벽한 가속을 가정한 값이다.
  실제 병렬실측·전체 입력 분포의 표본평균·신뢰구간이 아니다.
- 정상TRAIN 템플릿과72건의 매칭 산출물은 이미 계산됐고 새로 적합하지 않는다.
- 이전 producer 중복 실행을 정리했고 현재 그 두 profile PID는 종료됐다.
  모든 이전 결과와 실행 실패·복구 기록은 그대로 보존한다.

## 병렬 확인 구성과 소유권

1. `cost-accounting` / quick:
   기존 profile·supplement·preflight로 비용 산술과 실제 측정 범위 확인.
   COST_ACCOUNTING.md만 쓴다. 새solver 실행 없음.
2. `cache-audit` / quick:
   기존 캐시 키·적합 조건과 저장 matched/cache 재사용 가능성 확인.
   CACHE_AUDIT.md만 쓴다. 같은 raw 로그를 재매칭하거나80,028입력을 재적합하지 않는다.
3. `numerics` / deep-high:
   installed tick의 실제 반복·선형대수 병목을 제한된 계측으로 확인하고,
   입력 의미를 보존하는 연산 최적화가 가능한지 증명·대조한다.
   수학적 불변성과 유한정밀도 결과가 모두 필요하고 기존 패턴이 없어 이 경로를 선택한다.
   equivalent_backend.py, test_equivalent_backend.py, benchmark.py,
   benchmark.json, NUMERICS.md 및 이 폴더의 probe 산출물만 쓴다.
4. `verify` / unspecified-low, 앞3개 모두 의존:
   COST_REVIEW.md, VERIFICATION.md를 작성한다. 계산·등가성·범위·비용을 교차검증한다.

wave폭3→1. 원래prepare.py/native_data.py/설치된tick·NumPy/캐시·원본은 수정하지 않는다.
이 검토에서 원래 코드의 해시가 바뀌면 승인된 최적화라고 취급하지 않는다.
운영 전처리에 적용하는 변경은 별도 실제 검증 완료 후 주 담당이 결정한다.

## 수치 최적화의 제한과 판정

우선 병목을 실제로 계측한다. 현재 소스는 ADM4 iteration마다 핵노름 prox에서
SVD와 `u.dot(diag(s)).dot(v)`를 계산하며 objective 기록에도 SVD를 사용한다.
이것이 실제 비용의 주원인인지 계측 전에는 확정하지 않는다.

후보가 있다면 **정확히0인 행/열의 SVD 계산 축소 후 원래 크기로 복원**,
0인 특이값의 곱셈 생략과 같은 동일 연산만 검토한다.
0 근처 값을0으로 만들거나 작은 특이값을 임의로 버리면 정보/알고리즘 변경이므로 금지한다.
seed42의 랜덤 초기 adjacency도 유지한다. 템플릿 순서를 바꾸고 결과를 공유하려면
초기 adjacency·regularization·종료 조건까지 같은 결과임을 입증해야 한다.
시간축·후보·템플릿을 바꾸는 것으로 캐시 적중률을 높이지 않는다.

원래 `_solve`의 반복/종료/기록 주기·objective 값은 바꾸거나 가짜로 채우지 않는다.
설치 파일 수정 대신 별도 프로세스의 명시적 객체/서브클래스만 사용할 수 있다.
동일한 수학 연산이라도 실제 저장값이 바뀌면 이번 “값 보존” 검토에서는 통과시키지 않는다.

검사는 작은 행렬의 완전/0행/0열/모두0/범위·positive 처리와 실제 캐시3표본을 포함한다.
최종 모델 입력인 **float32 baseline vector의 원소별 정확한 동일성**,
iteration 수·경고·float64 차이를 모두 기록한다. 기준을 결과 후에 느슨하게 바꾸지 않는다.
첫 사례 밖 허용TRAIN 사례의 서로 다른2개 조합을 해시 순으로 먼저 선택해 추가 확인한다.
추가 원형 reference fit은 최대3회(계측1+추가2), 각 프로세스 제한180초,
검토 단계 총 실제 solver 벽시계 예산15분 이내로 제한한다.
이미 저장된3개 원형 baseline은 재사용한다. 참조코드/knots/hash/shape를 일치시킨다.
모든 표본을 같은 방식으로 보존하며 차이가 난 표본을 제외하지 않는다.

대표 표본 통과는80,028개 전체의 비트 일치 실측을 뜻하지 않는다.
불변성 논증과 검증 범위를 분리하고, 전체 적용 시 필요한 검증 범위를 제시한다.
동등성이 깨지거나속도개선이 예산에 부족하면 **불통과/근거 부족**으로 보고한다.
그때도 원래표현을임의축소하거나전체장시간계산을시작하지않는다.

## 실제 검증과 인계

새 코드에는 집중 검사·명시적 타입 검사·실제 benchmark exit0와 경고 기록을 붙인다.
명령은 monitor로 실행하며 완료 알림 전에 producer를 성공으로 반환하지 않는다.
백그라운드 시작 응답은 완료가 아니다. 원형산출물은 SHA256로 전후 불변을 확인한다.
최종 검토는 “기존 값 보존 가능 여부 / 실측 가속 / 기존 예산 내 가능성 / 남는 한계”를
명확히 판정한다. 입력 변경이 필요하다면 규칙·예상 영향·미측정 비용만 제안하고 멈춘다.
