# 257차원 입력 제한 비용 점검 — 2026-10-18

## 사용자 승인과 종료선

이번 승인은 **비용 점검까지**다. 전체 전처리, DiagMLP 학습·추론,
최종 시험, 새로운 방법 비교는 실행하지 않는다. 기존48/24 사건과 모든 창,
모델 구조·원형 solver·원자료·보호18건을 유지한다.
이 폴더 밖의 코드·설정·캐시·결과는 읽기 전용이다.
보호 사건의 관측·예측 및 raw 데이터는 열지 않는다.
기존 정상TRAIN48에서 만든 템플릿과72건의 매칭 캐시만 활용한다.

## 결과 전에 고정하는 규칙

1. 후보는 새 TRAIN48로 적합한 기존 frozen Drain snapshot의1024개
   템플릿이다. 새로 Drain을 적합하거나1024상한을 바꾸지 않는다.
2. 빈도는 **frozen matcher로 이미 매칭된 TRAIN48 로그 중
   timestamp < inject_time인 행 수**다. 온라인 cluster.size는
   LRU 퇴출과 템플릿 변화의 영향을 받으므로 빈도 대용으로 쓰지 않는다.
   validation 로그·정답·예측·적합시간은 순위에 쓰지 않는다.
3. 빈도 내림차순, 동률은 원래 cluster_id 정수 오름차순으로256개를
   선택한다. 선택된 template의 새 feature id는 원래 cluster_id
   오름차순으로1..256을 배정한다. 나머지768개와 기존unknown0은 새0이다.
   결과는257차원이다. 매핑과 해시를 저장한 후 validation 집계를 연다.
4. 모든 로그 행·원래 시각·소유 서비스를 유지한다.
   기타는 삭제가 아니라 합병이다. 바뀐 이벤트 id로 원형 make_knots를
   다시 호출한다. 원래 tie jitter와 빈 차원 초기 knot도 유지한다.
   로그가 전혀 없는 window/node만 원래처럼0벡터다.
   기존1025차원 baseline을 잘라 쓰거나 합산하지 않는다.
5. 기존 solver HawkesADM4(decay3), seed42, baseline_start .2,
   native random adjacency, max_iter50, tol1e-5, EM 및 기록 규칙을
   그대로 쓴다. 이전 compact-SVD 후보는 적용하지 않는다.
   설치 수치 모듈은 수정하지 않는다. 기존 설치의 전이 import는
   수치 계약 변경으로 오인하거나 제거하기 위한 별도 작업으로 확대하지 않는다.
6. 모델은 학습하지 않는다. 향후257입력으로 계산할 경우 입력 너비는
   바뀌지만 encoder/heads/loss 등의 구조를 바꾸자는 승인이 아니다.

## 제한 표본과 비용

- TRAIN의 각 root service별로
  SHA256(`re2-ob-257-cost-v1|case|` + case)의 값이 가장 작은 사건1개를
  고른다. 현재5개 root이면5개 사건이다.
- 각 사건에서 완전 정상창(start+9 < injection)과 나머지 장애창에서
  각각 SHA256(`re2-ob-257-cost-v1|window|` + case + `|` + start)의
  값이 최소인 창1개를 선택한다. 총10개 창, 각14개 서비스 전체를 포함한다.
  없는 층은 임의 대체하지 않고 누락으로 보고한다.
- 선택 manifest와257 매핑을 solver 실행 전에 해시 고정한다.
  선택된 비어 있지 않은 고유 knot만 최대140회 적합하고 정확히 같은
  입력은 한 번만 적합한다. 원형1025 재적합·validation 적합은 없다.
- 최대4 worker, 각 BLAS/native thread1. 개별 fit 프로세스60초,
  전체 benchmark 벽시계900초 상한. 통과시키기 위한 재표본·예산 연장 없음.
  이 제한 점검의 집계+benchmark 실행은 합계1800초 이내로 제한한다.
  이전 원형 전체 전처리 예산7200초보다 작게 제한하며 이전 지출과
  이번 증분 지출을 분리한다. 기존 중복 producer의 미확정 지출을 숨기지 않는다.
- 시간은 실제 solver/프로세스/전체 wall을 분리한다. finite/nonnegative,
  반복 수, 상한 도달, 경고, timeout/실패를 모두 기록한다.
  반복상한 미도달만으로 최적해 수렴이라고 단정하지 않는다.

## 서비스별 기타 범위

모든72건의 기존 매칭 캐시에서 새 매핑을 **집계만** 한다.
TRAIN/validation 및 주입 전/후를 분리하고14서비스 전부를 표시한다.
서비스별 총 로그 수, 유지256에 속한 행, 새로 기타에 합쳐지는 행,
기존unknown 행, 합친 기타 비율, 합쳐지는 서로 다른 template 수와
빈도가 큰 template id/안전한 짧은 template 설명을 기록한다.
원문 로그나 식별 토큰을 대량 보고하지 않는다. 로그가0인 서비스는
분모0과 결측 비율을 명시한다. 각 행의 귀속이 정확히 한 곳이고
집계 전후 건수가 보존되는지 검사한다. validation 집계로 규칙을 수정하지 않는다.

## DAG와 파일 소유권

독립 두 갈래 → 비용 측정 → 종합 검증. 작업 폭2→1→1.

- origin / quick: 기존 기록에서1024상한+unknown1의 출처, 실제 생성·퇴출,
  상한의 경험적/설정상 근거와 미확인을 추적한다. ORIGIN.md만 작성한다.
- mapping / unspecified-low: 좁은 범위지만 누출 경계·빈도·보존 집계가
  연결되어 있으므로 해당 경로가 mapping.py/test_mapping.py,
  mapping.json/selection.json/coverage.json/MAPPING.md를 소유한다.
- benchmark / deep-low, mapping 의존: 원형 함수와 저장 입력의 계약을
  연결하는 수치 실행·프로세스 제한이 필요하다. benchmark.py,
  test_benchmark.py, benchmark.json, fits/, BENCHMARK.md만 소유한다.
- verify / unspecified-low, 모두 의존: 독립 산술·경계 검증과 가능성 판단을
  통합한다. VERIFICATION.md/REPORT.md 및 필요시 verify.py만 소유한다.

각 경로는 source/JSON/NPZ hash와 실제 exit를 남긴다.
검증은 새 집중 테스트와 저장 산출물 독립 집계만 수행하며 실제 적합을
중복 실행하지 않는다. 수정된 검사만 다시 실행한다.
모든 소스 생성·수정은 apply_patch, 실행 산출물은 배타 생성한다.
동일 코드/결과의 재실행 덮어쓰기, 원래 pipeline 변경은 없다.
