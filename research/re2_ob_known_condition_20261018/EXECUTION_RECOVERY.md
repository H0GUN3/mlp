# 전처리 실행 연결 복구

## 현재 상태

입력 producer가 템플릿·비용 프로브를 백그라운드로 시작한 뒤 완료 응답을 반환했고,
후속 검증은 완성 bundle이 없어 FAIL을 기록했다. 실제 feature 준비가 완료된 것이 아니다.
producer 재개 과정에서는 RPC child가 응답 없이 종료된 오류가 발생했다.
이 상태에서 모델 학습은 시작하지 않았다.

## 재사용 가능성 확인

- preflight에 고정된 모든 소스 해시와 현재 파일 해시가 일치했다.
- templates.json의 입력 바인딩과 preflight의 입력 바인딩이 일치했다.
- drain.snapshot의 SHA256이 templates.json 기록과 일치했다.
- 새 TRAIN48의 주입 전 로그 **4,237,203행**을 적합했고 validation 적합 행은 **0**이다.
- 템플릿+미지 bin 차원은 **1,025**, 적합 시간은 **626.0463초**다.
- 실제 사전 검사:72사례/10,273창, TRAIN6,817창·validation3,456창, 후보14개.
- 교차 파트 관측 시간 겹침은0이며 보호/원시/기존 학습 상태 파일 open은 각각0이다.

이것은 템플릿·사전 검사의 근거이지 전체 Hawkes feature나 모델 실행 완료 근거가 아니다.
비용 프로브와 완성 입력 bundle은 아직 확인되지 않았다.

## 후속 연결

최초 PID의 종료를 부모 monitor `mon_07QXDBVPJH5C4TRZ` / `bash_10`이 구독한다.
이 monitor는 프로세스 소멸과 profile.json 존재 여부만 알리므로,
**그 알림 자체를 원래 명령의 exit0 증거로 바꾸지 않는다.**
원래 실행 종료 기록과 profile의 내용·해시를 확인한 뒤 다음 단계로 이어간다.
원래 종료 기록을 복구할 수 없다면 이미 완성된 새48/24 템플릿/profile을 해시 검증하여
재사용하는 CLI 경로만 별도로 실행해 그 재사용 검증의 exit를 기록한다.
이를 원래 최초 실행의 종료 기록이라고 주장하지 않는다.

입력 manifest 파일 대기 monitor `mon_3W78YN18PYBKW1N6`은 기본 대기 시간으로 만료됐다.
이는 최초 프로세스 실패나 완료를 뜻하지 않는다. 원래 프로세스나 producer를
다시 시작하는 근거로 쓰지 않는다.

완성 input.json/bundle.npz와 실제 준비 종료 증거가 생긴 뒤 입력 검증만 다시 수행한다.
그 PASS를 읽기 전에는 seed 학습을 시작하지 않는다.
