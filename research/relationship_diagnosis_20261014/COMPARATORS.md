# 문헌 비교군 shortlist — root-service RCA

## 결정

우선순위는 **(1) DiagMLP, (2) BARO, (3) Eadro**다. 세 방법은 각각 가장 가까운 지도학습 MLP, 비신경 통계 기준, 다중모달 그래프·탐지 통합 기준을 대표한다. 이는 다음 공정 비교 후보 선정이지, 현재 연구 자료에서 성능이 확인됐다는 뜻은 아니다. 내부 Local/Global 대조군은 문헌 비교군이 아니며 여기서 비교하지 않는다. 수치 오류 분석은 부모 보고서에 맡기고 중복하지 않는다. 별도 네 번째 후보는 이번 root-service 질문의 결정이나 최소 비교 설계를 바꾸지 않아 추가하지 않는다.

## 실제 비교 전 최소 계약

1. **사고 단위·후보·정답 고정:** 같은 incident group을 모든 방법의 단위로 유지한다. 후보는 사건별 root-service 후보 inventory와 동일한 서비스 ID 순서로 매핑하고, root label도 같은 service로 변환한다. 각 사건은 한 번만 집계한다. 미관측 후보 처리 및 root가 후보에 없을 때의 처리도 사전에 정한다.
2. **누수 방지·비용 경계:** 학습 가능한 encoder, template/Hawkes, static graph, 공유 변환, 후보 사전과 튜닝은 TRAIN 정보만으로 적합한다. 허용된 full-case offline query에서 case-local 변환을 쓸 경우 그 조건을 모든 방법에 동일하게 적용·명시한다. 원자료 준비/파싱/전처리, 학습·validation 선택, 새 incident 전처리, 추론 시간과 peak memory를 분리 기록해 end-to-end 비용도 보존한다.
3. **BARO 집계 동결:** 원 공식코드 signed-score 경로인지 논문식 absolute-score 경로인지 먼저 선택해 버전 고정한다. metric 점수에서 service 점수로 가는 함수(예: service 내부 metric 최대값)를 validation 전에 정하고 고정한다. metric 개수 차이가 순위에 미치는 영향도 기록한다. 점수를 본 뒤 서비스별 집계나 metric 열을 선택하지 않는다.
4. **시점·탐지 모드 분리:** onset이 benchmark 경계로 주어진 **oracle fault-conditioned/scoring-stage** 진단과, 모델이 onset을 찾아야 하는 **end-to-end** 비교를 따로 보고한다. BARO scorer에 알려진 onset을 제공한 결과를 BARO 전체 pipeline 성능이라 부르지 않는다. Eadro의 root 조건부 순위와 detector gating 포함 결과도 별도 산출한다. 정상 사건/창의 detector 성능을 root-localization 정확도와 합치지 않는다.
5. **선택 예산·평가:** validation 기반 탐색 budget, checkpoint 기준, seed와 중단 규칙을 방법별로 사전 고정하고 모두 공개한다. 동일 epoch 수를 기계적으로 강제하거나 강한 방법을 3,361 parameter 정도로 줄이는 것은 공정성 계약이 아니다. 보고 지표는 사건 동등 가중, incident-level Top-1/Top-k/MRR 등으로 하고 동점은 균등 기대 credit으로 계산한다. 창 단위 수치를 독립 사건 수처럼 취급하지 않는다. 이전 window split 점수를 새 CV 결과와 한 표에서 직접 순위 비교하지 않는다.
6. **두 비교 질문을 분리:** (a) **공유 정보/구성요소 비교**는 현재 허용된 7개 메트릭+trace duration/count 등의 동일 입력을 각 구현에 주는 adapted 비교이며, 원 모델 충실도/전체 성능 주장이 아니다. (b) **방법별 전체 pipeline 비교**는 각 원 방법에 필요한 입력과 전처리를 보존한다. 현재 허용 bundle만으로는 raw logs/Hawkes 및 native static graph가 없어 Eadro 전체 pipeline 비교가 불가능하고, DiagMLP의 원래 세 modality embedding 입력도 충족하지 않는다. 승인된 개발 모달 자료 접근 범위 안에서 이 입력들과 동등한 사건·서비스 adapter 및 label mapping을 준비한 뒤에만 실행을 계획한다. 이 자료/adapter의 이용 가능성과 결측처리는 아직 검증하지 않았다.
