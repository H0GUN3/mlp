# 로그 효율 비교 계약 — 설계안, 실행 전 동결 필요

**상태:** 제안 설계. 본 문서는 문서·소스 점검만으로 작성했다. 학습, 추론,
특징 생성, 데이터/NPZ/체크포인트/예측 배열 접근, 비용 측정은 수행하지 않았다.
아래의 실행 절차는 향후 별도 명시적 승인과 사전 동결을 전제로 하며, 현재 실행
승인이 아니다.

## 1. 연구 질문과 진입 조건

연구 진입은 오답의 존재 하나로 정당화하지 않는다. 먼저 아래 세 문제를 분리해
근거와 비용을 확인한다.

| 축 | 질문 | 현재 판정 |
|---|---|---|
| 효율 | 로그 특징의 상시 준비 비용, 요청 후 비용, 저장·메모리, 실제 예측 지연 중 무엇이 병목인가? | **미확인.** 이번에 허용된 자료에는 234.81초/209.71초의 원 측정 범위와 산식이 없다. 두 수치를 비교 결과나 온라인 절감량으로 인용하지 않는다. |
| 안정성 | 고정 템플릿 어휘와 관측 누락이 서비스·창에 따라 얼마나 흔들리는가? | **미확인.** 원자료 및 보호 관측을 읽지 않았다. |
| 구조 제약 | 고정 서비스 슬롯·정적 그래프·모델 입력 폭이 실제 배포 제약과 맞는가? | 현재 소스의 구조는 확인했으나, 가변 서비스 수·새 서비스에서의 운영 요구와 성능은 **미확인**이다. |

오답 양상은 위의 질문을 보조하는 진단 자료이지 연구 진입의 필수조건이나
효율성의 대리변수가 아니다. 위치, 그래프 부재, 군집 시각화만으로 성능 원인을
단정하지 않는다. Eadro의 Eadro 기반 DiagMLP와 TVDiag 기반 GAIA는 서로 다른
방법이며, 문제 해결 파이프라인의 앞단에 둔다는 사실과 앞단 배치가 필요한
이유·효과는 별도 주장이다. 현재 소스 점검은 이들의 실제 배치 필요성을
검증하지 않았다. (근거: `BRIEF.md` 요구사항 1–2; `fidelity_audit.md`
“Fusion boundary”, “Native input”; `native_models.py` `NativeReference`.)

## 2. 비교 순서와 공통 고정조건

### 단계 0 — 비용 경계 확인 (측정 금지, 향후 승인 필요)

실험 전 문서·운영 경로에서 다음 비용 항목을 분리해 정의하고, 각 항목에
포함되는 처리·서비스·창·캐시 상태·측정 단위를 기록한다.

1. 공통 입력 준비/공통 모델 비용과 로그별 추가 비용.
2. 배치 템플릿 학습·Hawkes 적합·캐시 생성 비용과 캐시 hit 조회 비용.
3. 상시/주기적 처리 비용과 요청 후 처리 비용.
4. 온라인 지연과 오프라인 준비 시간, 평균과 P95, 피크 메모리와 저장량.
5. 고유 창/서비스별 작업, 중복 창·공유 연산, 재사용 가능한 산출물.
6. 학습·검증 비용과 추론 비용.

총비용 비교 시 같은 캐시 정책과 중복 제거 정책을 양쪽에 적용한다. 공통항목을
빼고 로그 비용만 비교한 값은 “증분 비용”이라 부르고, 전체 경로 비용과
혼동하지 않는다. 234.81초/209.71초는 본 문서에서 **미확인 출처·범위의
기존 숫자**로만 취급한다. 이를 분해하거나 비율을 계산할 근거가 없으므로
계산값을 만들지 않는다.

### 단계 1 — 첫 실험: F 대 고정 저비용 L

- **F:** 현재 Hawkes 표현을 고정해서 사용한다. 지정된 native 소스에서
  HawkesADM4의 baseline 반환값을 로그 입력으로 전달한다
  (`native_data.py` `train_templates`/로그 처리 경로;
  `native_models.py` `LogModel`). TT 프로토콜은 Hawkes 60차원 입력을
  명시한다 (`TT_PROTOCOL.md` 입력 계약).
- **L:** 동일한 고정 템플릿 어휘별 관측 횟수로 만든 고정 log-count 표현.
  한 창은 10초이므로 count-rate는 count에 `1/10`을 곱한 결정적 변환이라
  새 정보를 추가하지 않는다. 다만 `log1p(count)`와 `log1p(count / 10)`은
  로그 변환 뒤 상수배 관계가 아니므로, 한 표현만 사전 선택해 고정한다.
  count-rate를 별도 정보나 독립 비교군으로 세지 않는다.
- 어휘·순서·차원은 F와 L에서 동일하게 유지한다. 알려진 템플릿에 더해
  unknown bin 하나를 두고, 실제 F 어휘와 unknown-bin 처리의 대응을
  데이터 접근 전에 동결한다. 템플릿 생성 규칙, 희소/미출현 템플릿 값,
  어휘 상한 및 초과 처리도 미확정 항목으로 명시해 선행 동결한다.
- 고정 폭의 10초 창에서 서비스별 이벤트가 없으면 count는 0이고 L은
  `log1p(0)=0`이다. 이는 “수집이 정상 작동했고 실제 이벤트가 없었다”는
  의미와 같지 않다. 원래 관측 상태, 요청 없음, 추가 마스킹은 서로 다른
  상태로 보존·보고해야 한다. 상태 구분을 제공할 기존 메타데이터 범위는
  **미확인**이다.
- F와 L은 입력표현만 다르고 나머지 후보, 관측 창, split, metric/trace
  표현, encoder/fusion/head, loss, 최적화기, checkpoint 선택 규칙,
  seed 및 학습 예산을 같게 해 **각각 처음부터 재학습**한다. 공통 초기값과
  창 순서를 seed별로 맞춘다. 이는 학습된 모델 대조다. 기존 checkpoint에
  입력0만 교체하는 추론 ablation은 대체 방법의 비교로 인정하지 않는다.
- 지표·트레이스 scaler가 필요하면 TRAIN에서만 적합하고 양쪽에 동일 적용한다.
  F/L 로그 특징에 데이터 기반 정규화가 추가로 필요하면 통계·정책 역시
  TRAIN 전용으로 사전 동결한다. 검증/시험 통계를 특징 생성·어휘 구축에
  누수시키지 않는다.
- fixed10s count-rate가 단순 스케일 중복이므로, 기본 L은 `log1p(count)`로
  고정하는 안을 제안한다. 로그 밑, unknown 구성, 희소 템플릿 정책, 창 경계와
  이전 창 이벤트 포함 여부는 공개된 현재 근거만으로 완결되지 않아 **실행 전
  미확정 결정**이다. 이 결정을 결과를 보기 전에 기록해야 한다.

### 단계 2 — L/F 결과 조합 진단, 선택기 여부 결정

각 평가창에서 정답을 기준으로 다음 네 경우를 같은 주지표 정의로 분류한다.
정상창은 별도 탐지 결과로 집계한다.

| L | F | 해석 |
|---|---|---|
| 정답 | 정답 | 둘 다 성공 |
| 오답 | 정답 | F의 관측된 보완 사례 |
| 정답 | 오답 | L의 관측된 이점 |
| 오답 | 오답 | 둘 다 실패 |

네 조합을 전체 및 사건별로 보고한다. L의 예측 불확실성은 L 출력만으로
계산하고, F의 추가 효용은 paired 결과로 측정한다. 둘은 같은 양이 아니다.
정답을 선택기 입력으로 쓰지 않는다. 실제 선택기를 검토할 때도 추론 시점에
비싼 F 특징을 먼저 계산해야만 얻을 수 있는 정보를 선택 입력에 넣지 않는다.

`항상 L`, `항상 F`, 비용을 맞춘 무작위 선택, 사전 동결한 단순 L-불확실성
임계값을 비교군으로 둔다. 모든 창에서 정답이었을 방법을 고르는 oracle은
가능성의 상한을 보는 사후 진단일 뿐 배포 가능한 방법도, 성능 추정치도 아니다.

**중단 규칙:** L이 사전에 합의할 품질 기준을 만족하고 F의 추가 이득이
실제 증분 비용을 정당화하지 못하면 L에서 멈춘다. 선택기/cascade를 기본
목표로 만들지 않는다. 품질 허용손실과 최소 비용 절감 기준은 현재
**미합의**이며 결과를 본 뒤 정하지 않는다.

## 3. 후속 cascade 계약 (조건부, 아직 미승인)

단계 1의 paired 네 조합 분석을 마친 뒤에만 cascade를 검토한다. F는 L에서
사전 정의한 불확실 조건에 해당하는 경우에만 계산한다. 실제 비용은 다음처럼
계상한다.

> 전체 비용 = 공통 처리 + L + 선택기 + 실제 전환 시 F 추가분 + 중복 비용

L 비용을 F 비용으로 대체 계산하거나, 캐시·공유 연산을 한쪽에만 반영하지
않는다. 선택기 검증·추론 비용과 학습 비용을 따로 보고한다. 비교군은
`항상 L`, `항상 F`, 예산을 맞춘 무작위 호출, L 점수만 사용하는 단순 임계값이다.
F를 호출하지 않는 경우와 호출하는 경우 각각의 평균/P95 지연, 피크 메모리,
학습 비용 및 실제 생략한 F 비율을 기록한다. 이 항목들은 설계 요구이며
현재 측정값이 아니다.

선택기를 학습할 필요가 있으면 TRAIN 안에서만 out-of-fold(OOF) 방식으로
각 창의 L 예측 및 L/F 결과를 생성해 메타 학습 자료를 만든다. OOF fold 생성,
seed 대응, 그룹 단위 분리, fold별 중복 방지 규칙은 실행 전 동결한다.
이때 F 학습·OOF 추론·선택기 적합 비용을 모두 학습 비용에 포함한다.
검증 자료는 임계값·선택기 설정 및 개발 진단에만 쓰며 최종 시험으로
재사용하지 않는다. 현재 허용 경계에는 보호 시험 자료를 여는 일이 포함되지
않으므로, 최종 시험 결과를 요구하거나 추정하지 않는다.

## 4. 관측 상태와 대안 B/C의 위치

“현재 관측된 sparse 입력”은 실제 수집 과정에서 들어오지 않은 값이 있는
상태이고, “완전 입력”은 모든 기대 채널이 실제 관측되었다는 주장이다.
완전 입력에서 값을 인위적으로 가린 추가 마스킹은 이 둘과 다르다. 자연 결측,
요청이 발생하지 않아 값이 없는 경우, 실험자가 추가로 가린 경우를 가능한
한 별도 표시한다. ARMOR v3의 결측 처리 범위와 기존 local/relative 표현의
mask 지원을 지정된 자료에서 확정하지 못했으므로 **미확인**으로 남긴다.

- **B는 후순위 후보:** 동일한 missing augmentation을 적용한 Diag+mask
  통제다. 자연 관측 상태는 그대로 유지하고, 추가 마스킹 규칙·확률·적용
  단위를 사전에 고정한다. 두 조건 모두 같은 mask 정보와 학습 예산을 쓴다.
  B는 F/L 첫 대체 비교를 대체하지 않는다.
- **C는 별도 구조 가설:** node-fusion만이 아니라 위치 임베딩, modality
  encoder, 정규화, 출력 크기, 파라미터 공유 여부까지 함께 명세한다.
  고정 서비스 수/슬롯에서의 결과와 가변 N 실행 가능성, 파라미터 공유,
  비용, 새 서비스 정확도는 서로 다른 평가 질문이다. 순서 오입력을 약한
  baseline으로 만들지 않도록 올바른 고정 순서 기준을 둔다.
- 고정 슬롯+mask가 운영 조건에 더 맞으면 이를 C와 비교한다. 단순
  DeepSets 교체는 DiagMLP 후속 제안과 겹칠 수 있으므로 그 자체를 신규성으로
  주장하지 않는다. 두 대안 모두 첫 단계 결과와 필요성이 확인되기 전에는
  실행하지 않는다.

## 5. 데이터 경계와 점수 계약

현재 이 문서가 참조하는 TT 실행 계약은 허용 개발 창 **3256 TRAIN / 813
validation**을 고정하고, **1744 test + 1 unassigned**를 보호한다.
같은 사건의 서로 다른 창이 train/validation에 존재하므로 사건 일반화
성능으로 표현하지 않는다 (`TT_PROTOCOL.md` 분할 설명; `tt_runner.py`
`selected_positions`). 기존 TT 보고서의 3-seed 평균은 Eadro 복원본
validation Top1 79.64%, DiagMLP 수식 복원본 98.64%였으며, validation
선택 checkpoint 결과라 독립 최종시험 점수가 아니다
(`INTERIM_REPORT.md` §1–2). 이 숫자는 새 L/F 성능이나 효율의 근거가 아니다.

RE2의 기존 경계는 54/18/18로 유지하고 새 분할을 만들지 않는다. 최종
telemetry는 닫힌 상태다. 특히 허용된 설계 작업은 이 데이터를 이용해 특징을
만들거나 split을 재조정하는 권한을 주지 않는다. RE2에 18개 평가 사례가
있다면 한 사례가 전체의 `1/18 = 5.56%`에 해당한다 (**계산값**, 사례 수
18이라는 기존 경계에 대한 산술). 따라서 seed나 창을 독립 사례처럼 취급해
품질 보존의 정밀도를 과장하지 않는다. 허용 손실과 최소 절감률은
**제안/미합의**로 남긴다.

주지표는 TT 계약과 정합적인 **고장 창 conditional Top-1**이다. 탐지 gating을
적용한 end-to-end Top-1, 탐지 precision/recall/F1은 보조로 분리한다.
정상 창을 root 정답률 분모에 넣지 않는다. 창별 Top-1 평균, 사건별 창
credit 평균, 사건 단위 확률 평균은 서로 다른 점수이며 서로 대체하지 않는다.
사건별 창 평균은 부가 분석으로만 보고한다. 점수 동률은 동률 후보 간 균등
기대 credit으로 처리한다 (`TT_PROTOCOL.md` 지표 계약; `tt_runner.py`
`score`). paired 결과는 창/seed와 사건 수준을 구분하고, 반복 seed·창을
독립 사건 수로 부풀리지 않는다. 시험자료 접근, 최종 임계값 선정 및 최종
재학습 절차는 이 설계 범위에서 **미확정이며 실행 금지**다.

## 6. 실행 가능한 향후 순서와 중단점

아래는 승인 후 수행할 순서이지 현재 작업 지시가 아니다.

1. **비용 경계 동결:** 시간·비용 숫자마다 원 로그/문서의 출처, 범위,
   cache 상태, 온라인/배치, 고유/중복 작업, 지연 통계와 메모리 단위를
   연결한다. 출처를 찾지 못하면 미확인으로 둔다.
2. **비교 조건 동결:** 허용 split·관측 정의·템플릿/unknown 규칙·L 변환·
   공통 encoder/head·학습 예산·seed·checkpoint·점수·비용 산식을 명시한다.
   미합의된 허용손실/최소절감률은 승인 없이 채우지 않는다.
3. **사전 점검:** 비보호 개발 입력 범위와 출처가 허용되는지 확인하고,
   특징 차원·어휘 순서·빈 이벤트·TRAIN 전용 통계·공통 초기화/학습 절차를
   문서 수준에서 검증한다. 보호 split은 읽지 않는다.
4. **승인된 경우에만 F/L 재학습 비교:** 동일 예산과 paired seed로 각 arm을
   독립 학습하고, validation 선택을 기록한다. 이 문서만으로 실행을 시작하지
   않는다.
5. **네 조합과 실제 비용 비교:** 네 정오 조합, oracle 상한 진단, 평균/P95,
   메모리·학습 비용 및 절감된 실제 연산을 함께 보고한다.
6. **진입/중단 판단:** L이 충분하면 종료. 그렇지 않고 F에 paired 증분
   효용이 있으며 실비용 통제군 대비 이득이 남을 때만 별도 승인 후 cascade를
   설계한다. B/C는 별도 필요성·가설을 동결한 뒤에만 후속 검토한다.

호출 경로는 후보 정보를 제공할 수 있지만 GNN 사용이나 인과관계의 증거와
동일하지 않다. 적절한 기준을 만족하지 못하면 “미확정/추가 근거 필요”로
종료하며, 미리 정한 개선 주장을 위해 비교군·분할·임계값을 바꾸지 않는다.
