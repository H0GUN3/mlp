# 로그 처리 효율 설계 제안

## 결정 요약

**제안:** 현재 증거는 Hawkes 로그 변환의 배치 비용 비중이 크다는 점은 보여주지만, 온라인 병목이나 로그 특징의 예측 기여를 보여주지 않는다. 따라서 실행 승인을 요청하거나 cascade를 목표로 삼지 않는다. 향후 별도 승인과 사전 동결이 이뤄질 때만 비용 경계를 확인하고, 동일 템플릿 기반 고정 저비용 로그 표현 L과 Hawkes 표현 F를 먼저 공정하게 비교한다. L로 충분하면 여기서 종료한다. L/F 결과와 공정 기준선에서 F의 추가 가치가 남는 경우에만 조건부 선택기를 검토한다.

**현재 상태:** 문서와 코드의 기존 근거를 종합한 설계 checkpoint다. 새 실험은 하지 않았다. 새 정확도, 지연, 메모리 또는 비용 절감 측정은 없다. 이 문서는 학습·추론·특징 생성·벤치마크·원자료/NPZ/체크포인트/예측 배열 접근의 허가가 아니다. TT 보호 평가 1744개 창과 미배정 1개, RE2 최종 telemetry는 계속 닫혀 있다. 제안의 신규성이나 성능 우위를 보장하지 않는다.

## 문제, 목적, 기존 방법, 가설, 근거, 상태

### 문제

로그 입력 경로는 로그 이벤트를 템플릿에 대응시키고, 비어 있지 않은 창-서비스 그룹마다 Hawkes 적합을 수행한다. 기존 배치 실행에서 이 단계의 벽시계 비용은 준비 전체 비용의 큰 부분이었다. 그러나 확인된 수치는 기존 입력 번들을 바탕으로 한 오프라인 준비 실행이다. 상시 수집 비용, 요청 후 새 창의 지연, 캐시 miss와 hit, 여러 요청 사이의 공유 계산은 측정되지 않았다. 그러므로 현재 문제는 “온라인이 느리다”가 아니라 “기존 배치 준비에서 Hawkes 계산 비용이 컸으며, 그 비용과 예측상 필요성을 분리 검증할 필요가 있다”로 한정한다.

효율 문제는 위 배치 비용으로 확인됐지만, 운영 비용 병목은 미확인이다. 안정성 문제는 템플릿 어휘의 변동과 관측 상태 차이가 실제 입력 및 결과에 미치는 영향으로 정의할 수 있으나, 이번 자료로 빈도나 효과를 확인하지 않았다. 구조 제약은 고정 서비스 슬롯, 정적 그래프 및 입력 폭이 운영 요구와 맞는지에 관한 질문이며, 실제 가변 서비스 수나 새 서비스 요구는 미확인이다. 이 세 질문을 오답 개수 하나로 대체하지 않는다.

### 목적

다음으로 확인할 질문은 두 가지다. 첫째, 동일 로그 템플릿 관측을 더 단순한 count 표현으로 바꿔도 기존 Hawkes 로그 입력의 예측 기여를 유지할 수 있는가. 둘째, 그 대체가 공정한 캐시와 중복 제거를 적용한 기준선보다 실제 비용을 줄이는가. 답이 충분하면 복잡한 선택기 없이 고정 대체에서 끝낸다.

### 기존 방법

- **Eadro 기반 DiagMLP**와 **TVDiag 기반 GAIA**는 구분되는 방법 및 입력 기반이다. DiagMLP 논문은 Eadro의 SN/TT와 GAIA의 TVDiag 조건을 각각 비교하며, DiagMLP의 노드 융합과 위치 임베딩, 그리고 노드 수에 따른 연결 크기 문제를 기술한다. 앞단 파이프라인에 놓인다는 사실은 해당 위치가 반드시 필요하거나 성능 원인임을 입증하지 않는다. 위치, 정적 그래프의 부재 또는 군집 시각화만으로 원인을 단정하지 않는다. 출처: [DiagMLP 원문 v2](https://arxiv.org/html/2501.02766v2), §III-B, §III-C, §III-D, §IV-A, §IV-B, §IV-C 및 [fidelity 감사](../native_reproduction_20261013/fidelity_audit.md) “Fusion boundary”.
- **Hawkes 로그 표현 F**는 Eadro 계열에서 템플릿화된 이벤트의 발생 동태를 표현한다. 제안할 **L**은 동일한 템플릿별 단순 count를 쓴다. 고정 10초 창에서 count-rate는 count의 상수배라 독립된 정보 대조군으로 세지 않는다. 이 설계는 대체의 우열을 미리 가정하지 않는다. 출처: [Eadro 원문](https://arxiv.org/html/2302.05092v1), §IV-A.1, §IV-B; [선행연구 점검](PRIOR_ART.md).
- JMLR의 feature-cost cascade와 AAAI의 confidence calibration cascade는 계산비용을 고려한 단계형 추론과 겹친다. TraceDiag와 MicroHECL의 graph/candidate pruning, UniSage의 분석 후 보존용 sampling, ARMOR의 missing-modality 처리는 질문과 다르며 하나의 “로그 계산 생략” 근거로 합치지 않는다. TraceBudget은 저자 확인 가능한 1차 원문, 심사 및 실험 신뢰성이 확인되지 않아 방법이나 결과를 근거로 쓰지 않는다. 관련 출처와 겹침 범위는 [PRIOR_ART.md](PRIOR_ART.md)에 기록했다. 선행연구와의 유사성 검토는 신규성 보증이 아니다.

### 개선 가설

**가설, 미검증:** 동일한 로그 관측과 템플릿 어휘를 쓰는 count L은 Hawkes F보다 계산이 단순할 수 있다. L이 요구된 품질을 만족하고 공정한 기준선보다 비용을 줄이면, F를 모든 창에 적용할 이유가 줄어든다. 이 가설은 실제 정확도나 비용 절감 결과가 아니다. 코드 경로는 실험 후보를 알려줄 뿐 GNN의 필요성, 인과관계 또는 온라인 절감 효과를 증명하지 않는다.

## 향후 비교 설계

현재 실행이 아니라, 별도 승인 후 사전 동결할 제안이다.

### 0단계: 비용 경계와 공정 기준선

먼저 원문 관측 처리부터 후보 순위 산출까지 포함 경계를 문서화한다. 앞단 공통 처리, 템플릿 및 특징 준비, 요청 후 계산, cache miss/hit, 중복 제거와 요청 간 공유를 분리한다. 배치 1회 비용과 요청 단위 새 창 비용도 섞지 않는다. 동일 입력 버전, cache policy, warm-up, worker/thread 예산을 F와 대체안에 적용한다. 기존 bundle 생성이 범위 밖이면 선행 비용으로 따로 적는다.

비용 항목은 다음과 같이 분리해 보고한다.

> 전체 비용 = 공통 처리 + L + 선택기 + 실제 전환 F 추가분 + 중복 비용

고유 창/서비스 및 실제 계산 횟수, 중복 요청·관측, cache hit/miss, task CPU 합과 실제 wall latency를 따로 기록한다. 평균/P50/P95 지연, 단계별 지연, 메모리와 cache 크기, 학습 비용을 구분한다. 기존 234.81초/209.71초를 새 실행의 기준 측정치로 가장하거나 온라인 지연으로 바꾸지 않는다.

### 1단계: 고정된 두 arm

| 조건 | F, 기존 표현 | L, 저비용 대체 |
|---|---|---|
| 로그 특징 | 동일 template set에 대한 기존 Hawkes 표현 | 같은 관측 창, 템플릿과 템플릿 순서의 단순 log-count. count-rate를 별도 arm으로 중복 계산하지 않음 |
| 공통 조건 | 동일 관측·10초 창·분할·후보 서비스·metric/trace 입력·나머지 encoder/fusion/head·loss·seed·학습 예산·checkpoint 규칙 | F와 동일 |
| 모델 비교 | 로그 입력만 F로 두고 처음부터 학습 | 로그 입력만 L로 바꾸고 처음부터 학습 |
| 별도 ablation | 동일 checkpoint에서 inference 입력만 0으로 둔 결과는 필요 시 별도 진단 | 대체 모델의 재학습 비교로 세지 않음 |

어휘 생성 및 정렬, unknown template 처리, 희소/미출현 값, 로그 변환, 창 경계 규칙은 데이터 사용 전 동결한다. 기존 Hawkes의 60차원 입력과 L의 어휘 차원이 맞지 않는 경우에도 양쪽의 입력 의미와 encoder 용량을 사전에 공정하게 정해야 한다. 검증·시험 자료로 어휘나 정규화 통계를 만들지 않는다. 실행 전에 해결할 설계 선택은 아래 unresolved 목록에 남겼으며, 이 보고서가 임의로 채택하지 않는다.

저비용 L이 품질 기준을 만족하고 공정한 캐시/중복 제거 기준선 대비 추가 비용 이득이 충분하다면 L에서 끝낸다. 선택기나 cascade는 만들지 않는다. 반대로 L이 부족하다는 이유만으로 cascade를 자동 승인하지 않는다.

### 2단계: 정오 조합과 선택 가능성

첫 비교의 paired 평가에서 각 창을 다음 네 조합으로 분류한다. 주 점수 정의는 두 arm에서 동일하게 적용한다.

| L 결과 | F 결과 | 해석 |
|---|---|---|
| 정답 | 정답 | 양쪽 성공 |
| 오답 | 정답 | F가 보완한 관측 사례 |
| 정답 | 오답 | L에서만 맞은 관측 사례 |
| 오답 | 오답 | 양쪽 실패 |

L 자체의 예측 불확실성과 F의 paired 증분 효용은 별개로 보고한다. 정답이나 먼저 계산해야 하는 비싼 F 특징을 선택기 입력에 넣지 않는다. 모든 창의 정답을 사후에 알고 고르는 oracle은 가능성 점검용 상한 진단일 뿐 실행 가능한 선택기나 성능 추정치가 아니다.

선택기가 필요하다고 증거가 나올 때에만, 비교군으로 항상 L, 항상 F, 같은 예산의 무작위 선택, 사전 정의한 단순 L 임계값을 둔다. 실제 F 호출 비율과 실제 생략량, 평균/P95 지연, 메모리 및 학습 비용을 보고한다. 선택기 학습이 필요하면 TRAIN 안의 OOF 예측으로 학습하고, 검증은 개발 및 설정 선택에 한정한다. 최종 시험 접근과 재학습 정책은 별도 승인 전까지 미정이며 시험 보호 경계를 바꾸지 않는다.

### 후속 후보 B와 C

B와 C는 첫 대체 비교에 포함하지 않는다. 현재 관측된 sparse 입력을 완전 입력으로 간주하지 않는다. **B**는 후순위 결측 처리 후보이며, 같은 missing augmentation을 적용한 Diag+mask 통제를 둬야 한다. 자연 결측, 요청 없음, 실험자가 추가로 가린 입력은 분리한다. **C**는 node-fusion만이 아니라 위치, encoder, 정규화, 출력 크기와 파라미터 공유를 함께 명세해야 한다. 고정 슬롯+mask가 적절한 운영 조건이면 그 대안과 비교할 수 있다. 가변 N 실행, 파라미터 공유, 실제 비용, 새 서비스 정확도는 서로 다른 질문이다. 순서가 잘못된 입력을 baseline 약점으로 만들지 않으며, 단순 DeepSets 교체만으로 신규성을 주장하지 않는다. ARMOR v3와 기존 local/relative의 mask가 같은 의미라는 근거도 아직 없다.

## 평가, 경계와 중단 기준

- 점수는 혼용하지 않는다. 창 Top1, 사건별 창 credit 평균, 사건 확률 평균 순위는 서로 다른 점수다. 주 점수와 보조 점수를 실행 전에 고정하고 각 정의와 집계 단위를 밝힌다.
- 기존 TT 개발 계약은 3,256 TRAIN과 813 validation 창이며 1,744 test와 1 unassigned를 보호한다. 해당 계약의 기존 출처는 [TT_PROTOCOL.md](../tt_re2_baselines_20261017/TT_PROTOCOL.md) “입력·분할·보호 경계”이다. 이 설계에서 보호 경계나 분할을 바꾸지 않는다.
- 기존 RE2 분할 54/18/18은 유지하고 final telemetry는 열지 않는다. 18개 사건 기준 `1/18 = 5.56%p`는 **계산**이며, 작은 표본에서 품질 보존의 해상도가 제한적임을 설명한다. 독립성, 신뢰구간 또는 정확도 측정이 아니다. 출처 경계: [BRIEF.md](BRIEF.md) 요구 11–12, [INTERIM_REPORT.md](../tt_re2_baselines_20261017/INTERIM_REPORT.md) “RE2에서 진행된 범위와 현재 상태”.
- 허용 품질 손실과 최소 비용 절감은 **제안/미합의**다. 임의 기준을 채우거나 결과를 보고 정하지 않는다. 기준에 합의하지 못하면 성공/실패를 선언하지 않고 비용-품질 tradeoff만 기술한다.
- 호출 경로는 후보 정보를 줄 수 있지만 GNN 사용이나 인과 증명과 같지 않다. 위치, 그래프 부재, 군집 시각화는 원인 증거가 아니다.
- 진입은 비용 경계 확인, 고정 L/F 비교, 네 정오 조합과 증분 효용 분석 순이다. L로 충분하면 중단한다. F의 증분 가치가 공정 비용 기준선 뒤에도 남고 사전 합의한 품질/비용 문턱을 충족할 때만 cascade를 별도 승인 대상으로 제안한다. 조건을 충족하지 않으면 cascade를 강제하지 않는다.

## 미해결 결정

1. 요청 단위, 온라인 경계, 고유 window/service identity 및 재사용·중복의 운영상 정의.
2. cache key, freshness, invalidation, cold/warm 상태와 통제 가능한 동시성.
3. L의 템플릿 어휘·unknown bin·미출현 값·로그 변환·창 경계 및 60차원 F와의 입력 공정성.
4. 자연 결측, 요청 없음, 수집 실패와 추가 마스킹을 구분할 수 있는 관측 메타데이터의 범위.
5. ARMOR v3의 결측 규약과 local/relative의 기존 mask 의미가 실제로 대응하는지 여부.
6. C가 필요할 운영 조건, 고정 슬롯+mask의 적합성, 가변 N 및 새 서비스 평가 범위.
7. paired 평가의 고정 주지표, 사건 집계, OOF/개발 예측 생성 규칙과 최종 재학습/시험 절차.
8. 허용 품질 손실과 최소 비용 절감 기준. 현재 미합의이며 승인 없이 결정하지 않는다.
9. TraceBudget의 저자 검증 가능한 1차 원문, 심사/출판 상태와 실험 신뢰성.
10. B/C 후보를 검토할 별도 필요성, 비교 계약과 승인. 첫 단계 결과 전에 구현하지 않는다.

## 범위 및 검증 상태

이번 보고서는 지정된 기존 문서와 소스 설명, 작은 실행 요약을 근거로 작성했다. 원자료, 보호 telemetry, NPZ, checkpoint, prediction array를 읽지 않았고, 연구 코드를 import/run하거나 preprocessing, 학습, 추론, benchmark, package 설치를 하지 않았다. 기존 artifact는 수정하지 않았다. 이 보고서만 새로 작성했다. **측정값은 기존 실행 기록뿐이며, 계산값은 명시한 산술뿐이다. 나머지는 설계 제안 또는 unknown이다.**
