# SN–TT 조건 비교: 진단 정확도 관점

## 결론 먼저

SN과 TT에서 따로 학습한 결과는 같은 조건의 성능 비교가 아니다. 특히 **SN200 DiagMLP의 조건부 95.38%**, **TT50 DiagMLP의 조건부 98.64%**, **교정 SN의 창 단위 23.59%**는 입력 자료, 분할, 평가 단위 또는 학습 절차가 달라 서로의 증감으로 읽을 수 없다. 이 숫자들은 각자 해당 조건에서 관측된 결과일 뿐, SN이 본질적으로 더 어렵다거나 TT의 방법이 SN에 그대로 통한다는 증거가 아니다.

비교 근거로 가장 가까운 것은 같은 SN 자료·전처리·창 분할·모델·seed에서 수행한 **SN50 대 SN200**이다. 검증 JSON은 각 모델/seed의 첫 50 epoch 손실·점수·업데이트 이력이 두 예산에서 정확히 같다고 확인한다. 따라서 SN50과 SN200의 같은 validation 지표는 연장 구간을 비교하는 데 조건상 짝지을 수 있다. 다만 둘 다 창 무작위 분할이고 같은 장애 사건의 창들이 분할을 가로지를 수 있어, 미학습 사건 성능 비교가 아니다.

### RE2 travel/food 오류 근거의 경계

`INTERIM_REPORT.md` §2의 travel/food 혼동은 **최근 TT native-input 50-epoch 실행**의 DiagMLP 검증 오답이다. 이를 RCAEval의 17-feature 로컬 adaptation 오류로 부르면 안 된다. `TT_CONFUSION_PROBE.json`의 `seed_window_errors=24`, `unique_windows=15`, `windows_both_counts_zero=13`, `windows_with_different_candidate_counts=2`는 이 TT native 검증 혼동만을 요약한다. Probe의 `scope`는 인과 주장이 아님을 명시하고, `records[]`에는 root·예측 후보·event·seed·window이 기록돼 있다. `probe_tt_confusion.py`의 `main()`은 `TT_RESULTS.json`을 확인하고 선택 validation 예측 및 준비된 `TT.npz`의 invocation counts를 대조한다. 따라서 이 분석은 새 추론이나 원인 검증이 아니며, 24개 seed-window 평가도 독립 사건 24개를 뜻하지 않는다.

별개로 `native_reproduction_20261013/error_analysis.md` 첫머리의 **“Local DiagMLP-common error analysis”**는 RCAEval train-service/delay_2 사례를 포함한 17-feature adaptation 분석이다. 그 문서는 한 incident에 대한 세 seed의 예측으로 한정하며 original DiagMLP가 아니라고 명시한다. 이 오래된 RCAEval 분석은 위 TT native-input 결과의 조건·관측이 아니며, TT50/TT200 점수를 대체하지 않는다. 마찬가지로 `TT_DIAGNOSIS.json`의 root trace 결측은 관측 현황이지 결측이 오답의 원인이라는 증거가 아니다.

## 수치가 말해 주는 범위

1. **SN50 → SN200**은 네이티브 보정 실험 안에서 예산 차이를 살피는 가장 잘 맞춰진 짝이다. 검증기는 6개 실행 각각에서 같은 입력·split·scaler와 첫 50 epoch 이력 동일성을 확인했다. 다만 50/200은 서로 다른 epoch 선택점수이므로 “학습량 효과”와 validation checkpoint 선택 변화는 구분해야 한다.
2. **TT50 ↔ SN50/200**은 같은 native trainer·seed 분할 규칙·optimizer/loss/checkpoint 원칙을 공유하지만, 입력/후보 수와 자료 크기, fault-window 수가 다르고 사건의 중복 구조도 다르다. 시스템 간 관측차를 조건 효과로 분해할 수 없다.
3. **SN corrected 점수**는 낮아 보이지만, 원인이 split만인지, 사건당 집계인지, 새 scaler 적합인지, 입력 경로/자료 구성이 다른지 분리하는 통제 비교가 아니다. 같은 corrected 고정 예측의 창 동일가중 점수는 Eadro 9.948718%, DiagMLP 23.589744%; 사건별 창 적중률의 사건 균등 평균은 11.154000%/25.265319%; 사건당 확률 평균 순위는 9.259259%/25.000000%다. 출처: `WINDOW_RESCORE.md` “Results” 표. 이 차이는 채점 단위 자체가 수치에 영향을 줌을 보여주되, 과거 calibration과의 차이를 채점만으로 설명하지 않는다.
4. **SN200 95.38% vs TT50 98.64% vs corrected SN 23.59%**는 각각 SN native validation fault-window conditional Top-1, TT native validation fault-window conditional Top-1, corrected SN 사건분리 평가에서 저장 예측을 창 단위로 다시 채점한 3-seed 평균이다. 조건/분모/분할이 다르므로 하나의 순위표나 일반화 결론으로 만들지 않는다.
5. 이 자료로 “SN은 반드시 실패한다”, “trace 결측이 원인이다”, “전파/그래프가 원인이다”라고 단정할 수 없다. 관측 오답과 원인 가설은 분리한다. SN200의 9회 seed-오답은 8개 고유 창이고 세 seed가 모두 틀린 동일 창은 없었다(`sn200_error_note.md`; `sn200_error_windows.json` `models.diagmlp.distinct_root_error_windows`, `root_error_windows_in_all_three_seeds` 요약). 반복 후보쌍이 확인됐다는 기록도 현재 참조된 요약에 없다.

## 논문 수치와 재구성 수치

- `CALIBRATION_PROTOCOL.md` “Purpose and limits”: SN/TT는 공개 Eadro 자료에서 실행한 native reference calibration이며, private DiagMLP wiring/차원과 원본 split identity를 복구하지 못했으므로 정확한 원논문 재현이라고 하지 않는다.
- `TT_PROTOCOL.md`: TT50도 “공개 설정을 참고한 고정 조건 기준선”이며, 원논문 split identity·모델 통합·checkpoint 규칙과 전처리 차이가 남는다.
- `PLAN.md` / `REPORT.md`: corrected SN은 사건 분리 평가의 로컬 재구성이다. 평가 단위도 native calibration과 다르다.
- 따라서 위 점수는 **저자 논문 점수로 인용하지 않는다**. 원문 성능과 비교하는 표가 아니라, 서로 다른 로컬 실행조건의 비교가능성 표다.

## 최소 공통 원칙 및 남은 증거 공백

추가 split·예산을 정하지 않고, 이미 검증된 산출물만 재사용하는 가장 작은 공통 비교 원칙은 다음이다.

- 시스템별 독립 학습을 유지한다. SN 자료로 TT 모델을 학습하거나 입력/후보를 억지로 합치지 않는다.
- 한 시스템 안에서는 같은 입력 표현·TRAIN 전용 scaler·train/validation 행·후보 집합·seed·손실·validation 선택 규칙·채점 분모를 고정하고, 방법끼리만 짝지어 본다.
- 평가 단위를 명시한다. 기존 native calibration은 장애 **창** conditional score, corrected 결과는 사건당 **하나의 순위**다. 한 값을 다른 단위로 환산하지 않는다.
- 기존 유효 artifact와 verifier 결과만 인용한다. 보호 test 결과를 개발 결과에 섞지 않는다.

현재 공백은 구체적이다. (a) 세 계열을 같은 SN 사건 또는 같은 창 분할로 연결하는 검증 점수는 없다. (b) TT200의 숫자 요약은 여기 읽은 `tt200_summary.md`에 없으므로 수치 비교를 보류했다. (c) root→오답 후보의 반복 혼동쌍을 세 계열에 걸쳐 일관된 평가 단위로 보여주는 허용된 집계 근거는 확인되지 않았다. 개별 SN 예시의 후보명은 있어도 반복 혼동 패턴의 충분한 증거로 승격하지 않는다. (d) seed 변동은 독립 사건 반복이 아니며, 창/사건/recording 상관을 제거하지 않는다. (e) 원논문과 정확한 모델·분할·평가 동등성은 미확인이다.

그러므로 다음 허용 분석은 **새 학습이 아니라** 이미 승인된 명시적 요약/오류 JSON에서 사건·창 단위가 보존된 오답 후보 집계를 확인하는 것뿐이다. 그 파일에 필요한 root와 예측 후보가 없으면 혼동쌍 주장을 보류한다. 새 split이나 예산은 이 문서에서 제안하지 않는다.
