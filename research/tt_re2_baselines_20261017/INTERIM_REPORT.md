# 중간 결과 보고 — 사용자 확인 전 RE2 중지

2026-10-17. 사용자가 “RE2 바로 진행하지 말고 중간에 결과 보고해줘.
확인 후 진행하게”라고 지시했다. 모든 RE2 작업을 중지했으며,
명확한 재개 지시 전에는 추가 조사·변환·학습을 실행하지 않는다.
TT 중간 결과에 대한 확인을 받기 전에 RE2 입력 준비까지 진행한 상태를
아래와 같이 구분해서 보고한다.

## 1. TT에서 완료한 일

준비된 지표·로그·트레이스 입력을 사용해 Eadro와 수식 기반 DiagMLP
복원본을 각각 seed 11/23/37로 학습했다. 조건은 두 방법 모두
Adam 0.001, batch256, 50epoch, 실행당650update다.

기존 학습3256창/검증813창을 유지했다. 같은81개 장애 사건의 서로 다른
창이 양쪽에 포함된다. 따라서 새 사건 일반화가 아니라 기존 창 단위
개발 기준선이다. 후보27개, 검증 장애686창이 원인 점수의 분모다.
정상127창은 원인 적중률에 포함하지 않았다.

| 방법 | 학습 Top1 평균 | 검증 Top1 평균 | 검증 Top3 평균 | 선택 epoch |
|---|---:|---:|---:|---|
| Eadro 복원본 | 83.91% | 79.64% | 98.98% | 48 / 50 / 46 |
| DiagMLP 수식 복원본 | 99.64% | 98.64% | 100.00% | 27 / 23 / 24 |

모두3seed 평균이며, validation joint loss로 선택한 checkpoint의 결과다.
검증 집합을 모델 선택에도 사용했으므로 독립 최종시험 성능이 아니다.
정확한 저자 모델 통합·분할 identity를 복원한 원논문 재현이라고도 하지 않는다.
이번 결과는 새 개선 기법의 성과가 아니다.

## 2. 핵심 발견과 판단

- 현재 고정 조건에서는 DiagMLP가 더 잘 맞혔다.
- Eadro는 학습 자료부터 Top1이83.91%이고 최선 epoch가 예산 끝에 가깝다.
  50epoch가 충분했는지 아직 확정하지 못했다. 이 격차를 곧바로
  GNN의 근본적 한계나 충분히 수렴한 두 방법의 최대 성능 차이라 할 수 없다.
- DiagMLP의 검증 오답은 seed별8/9/11개 창이며 travel/food 서비스 혼동이 주를 이룬다.
- 그 혼동24개 seed-창 예측은 고유15창이다. 13창에서 두 후보의 호출 수가
  모두0이고 차이가 있는 창은2개뿐이었다. “호출 수를 추가하면 이 혼동이
  해소된다”는 가설은 현재 근거가 부족하다. 추가 채널·새 모델은 학습하지 않았다.
- DiagMLP 오답의 metric/trace는 모두 각 TRAIN 채널 범위 안에 있었다.
  TT 오답을 전반적으로 정규화 극단값 탓이라고 설명할 근거도 없었다.
  이는 별도 SN 자료의 가설을 검증한 결과는 아니다.

현재 판단은 **TT 기준선과 제한적인 실패 분석을 확보했지만, 새로운 개선
기법을 정당화할 근거는 아직 확보하지 못했다**는 것이다.

### 높은 기준선 성능과 연구 필요성

학습량 부족 가능성은 Eadro에 대한 미확인 설명이지, DiagMLP의 높은
성능을 설명하는 가설이 아니다. 현재 DiagMLP 검증 Top1은98.64%로,
이 검증 점수에서100%까지 남은 폭은 약1.36%p다.
Eadro만 개선해도 이미 높은 DiagMLP보다 유용한 방법이 된다는 보장은 없다.

따라서 다음 연구 판단은 “Eadro를 얼마나 개선할 수 있는가”보다
“강한 기준선으로도 해결하지 못한 중요한 문제가 실제로 남아 있는가”에 둔다.
연구 필요성을 만들기 위해 새 환경·미지 고장 일반화나 더 어려운 분할을
임의로 추가하지 않는다. 현재 높은 점수만으로 연구 문제가 해결됐다고
확정할 수도 없다. 모델 선택에 사용한 검증 결과이며, 독립 최종시험 성능과
오답의 실제 중요성은 아직 확인하지 않았다.

이 해석 보완은 추가 실험이나 보호 시험 접근, RE2 재개를 의미하지 않는다.

## 3. 검증과 실패 이력

6개 완료 모델, 24개 저장 예측의 재추론·독립 NumPy 채점·해시·최소손실 선택·
공통 초기값을 검사했고 실제 exit0/PASS를 확인했다.
실행 전6개 fixture, 추가 진단 및 호출수 검사도 통과했다.

첫 학습 모니터의 시간 제한으로 Eadro seed11/23은 중단됐다.
부분 산출물을 보존하고 동일 seed로 재시작했으며, 중단 전 epoch 수치의
정확한 재현도 검사했다. seed37은 이미50epoch를 마쳐 가중치를 재사용하고
후처리만 복구했다. 완료6회와 중단2시도를 구분한다.

## 4. RE2에서 진행된 범위와 현재 상태

기존에 허용된 train54/validation18만 다뤘다. 보호 test18은 열지 않았고,
제안했던30/30/30 새 분할도 적용하지 않았다.

| 단계 | 실제 상태 |
|---|---|
| 72사례 파일 형식·단위 검사 | 완료 |
| 원형 시계열과 로그 이벤트 중간 변환 | 완료: 10273창 |

| RE2 모델 학습·성능 평가 | 시작하지 않음 |

TT용 로그 마스킹을 그대로 적용하자, 첫 TRAIN 사례에서 생성된 템플릿이

완성하면 안 된다고 판단해 전체 처리를 중단했다.

TRAIN 일부에만 적용한 형식 규칙 후보에서는 생성 템플릿1715→113,
별도 TRAIN 표본의 미분류 로그422/5000→23/5000으로 줄었다.
이는 **형식 안정성 점검이지 진단 정확도 개선 결과가 아니다**.
후보 규칙은 최종 채택하지 않았고, 전체 TRAIN 재적합도 하지 않았다.

frontend와 frontendservice의 정확한 수집 버전별 별칭 관계도 미확인이다.
이를 임의 병합하지 않고 원본 식별자를 중간 파일에 보존했다.
현재 중간 파일을 최종 모델 입력 준비 완료로 간주하지 않는다.
