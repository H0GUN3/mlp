# TT 기준선 → 단일 실패 진단 → RE2-OB 비교

사용자 실행 승인: 2026-10-17 “진행해”.
목표는 같은 시스템에서 학습하지 않은 관측의 원인 서비스를 찾는 것이다.
새 시스템·운영환경·고장 종류 일반화를 추가하지 않는다.

## 의존 순서와 범위

1. TT 준비 완료 입력과 기존 창 분할을 재사용해 두 기준선을 실행한다.
   세부 고정 계약은 TT_PROTOCOL.md다. 원자료 재전처리를 반복하지 않는다.
2. 선택/최종 모델의 TRAIN·validation 점수, 손실, 입력 범위를 대조해
   실제 실패 하나를 좁힌다. 정상 창을 원인 적중 분모에 섞지 않는다.
3. 관측 근거가 있으면 변경 하나와 반증 조건을 먼저 명시하고 같은 예산으로
   비교한다. 근거가 없으면 기법을 발명하지 않고 그 결과를 기록한다.
4. RE2-OB는 기존 train54/validation18/test18 경계를 보존한다.
   입력 변환 계약을 별도로 고정하고 허용 부분만 준비·검증한다.
   조건부 원인 진단의 공식 관측 구간 규약과 실제 고장 활성 구간 증명을 구분한다.
5. 각 시스템 안에서 기준선/단일 변경을 비교한다. 검증 집합에서 선택·진단한
   수치를 최종시험 성능으로 부르지 않는다. 최종시험 접근은 별도 확인한다.

## 보존·복구

기존 자료/코드/산출물/분할은 수정하지 않는다. 프로젝트 commit, 설치,
추가 다운로드는 하지 않는다. 새 파일은 이 디렉터리에만 만든다.
학습 출력은 실행별 독점 디렉터리다. 기존 출력이 있으면 재실행으로 덮지 않는다.
실패 시 원래 로그와 부분 산출물을 보존하고 실패한 단계만 원인을 확인한다.
완료 판정은 실제 exit0와 검증 증거로 한다.

## 점검

입력 hash/원본 index/서비스 순서/라벨, 보호 행 배제, TRAIN-only scaler,
정상 제외·동률 채점 fixture, 두 모델의 공통 초기값/배치 순서,
선택 checkpoint의 재추론 일치와 별도 NumPy 채점을 확인한다.
이미 유효한 TT 전처리·Hawkes·원자료 검수는 다시 수행하지 않는다.

RE2-OB 계약 확인은 별도 읽기 전용 작업으로 병렬 수행한다.
후속 가설과 RE2 구현 계약은 실제 확인 결과에 따라 구체화하며,
학습 시작 후 TT_PROTOCOL.md와 해당 실행 source는 바꾸지 않는다.
