# SN 사건 분리 평가 실행 계획

2026-10-17. 사용자는 SN 진행 및 원인/비원인 후보 구분에 동의했다.
이번 요청의 산출물은 **구체적인 실행 계획**이다. 아직 새 학습을 실행하지 않았다.
SN 선택 질문은 해결됐으므로 다시 묻지 않는다. 아래 세부 규칙은 실행 전에 고정할 제안이다.

## 1. 이번 단계에서 답할 질문

**같은 SN 시스템의 학습에 포함되지 않은 장애 사건에서, 기존 Eadro 앞단을 보존한
Eadro와 DiagMLP 복원본이 원인 서비스를 얼마나 정확히 찾는가?**

먼저 신뢰할 비교 기준과 실제 실패를 확보한다. 이번 단계에서 새 기법의 우위를
주장하거나 상대공유·Transformer·GraphRAG를 추가하지 않는다.

- 정답: 장애 사건별 원인 서비스1개.
- 후보: 원형 순서의 서비스12개 전체. 관측이 없다고 후보를 빼지 않는다.
- 나머지 서비스: 비원인 후보. 전부 피해 서비스로 라벨링하지 않는다.
- 대상: 발생한 장애의 위치 진단. 장애 탐지·발생 예측·고장 종류 분류·복구는 주 과제가 아니다.
- 사건 구간은 제공하되 원인 서비스·고장 종류·주입 설정은 진단 입력으로 제공하지 않는다.

## 2. 사용할 자료와 접근 경계

| 구분 | 범위 |
|---|---:|
| SN 공개본의 장애 사건 | 36 |
| 원인 후보 서비스 | 12 |
| 고장 종류 | CPU부하 / network delay / network loss |
| root×고장 종류별 사건 | 1개 |
| 현재 허용된 개발 창 | 394개 |
| 그중 장애 / 정상 창 | 325 / 69 |
| 기존 시험 / 미배정 창 | 169 / 1, 계속 제외 |

기존 개발 창의 사건/episode 정보를 재사용하되, 과거 무작위 창 분할과 가중치는 재사용하지 않는다.
정상 창도 연결된 episode와 함께 배정한다. 같은 사건에서 만든 창을 양쪽으로 나누지 않는다.
사건 ID뿐 아니라 원관측 시각·중복 identity의 기존 검사와 창 출처도 대조한다.
분할 사이에 같은 원관측이 실제 공유되면 묶음 규칙부터 재검토하며 임의 행 삭제로 숨기지 않는다.

입력 준비:

1. 허용된 SN bundle의 original index·episode·시각·후보 순서를 기준으로 명세를 만든다.
2. 원형 입력은 `metrics[N,10,7]`, `traces[N,10,2]`, `logs[N,E]`다.
   trace둘째 채널0을 몰래 호출 수로 바꾸지 않는다. SN 로그 E=7을 검증한다.
3. 기존 원형 캐시에서 허용된394행만 배열로 복원하는 선택 로더를 사용한다.
   혼재된 시험/미배정 행은 해석·검사·학습·정규화·추론에 넣지 않는다.
   압축 스트림 순회와 허용 관측의 실제 디코딩을 구분해 접근 기록을 남긴다.
4. 안전한 부분 복원과 출처 확인이 불가능하면 중단한다.
   가짜0로그나18개 요약 특징을 원형 입력이라고 대체하지 않는다.
5. 기존 원자료/캐시/분할/모델/결과는 수정하지 않는다.
   새 파일은 `research/sn_corrected_20261017/` 아래 독점 생성한다.

## 3. 사건 단위 학습·검증·외부평가

기존에 검사한 episode 3묶음을 사용한다. 모델 점수로 묶음을 다시 고르지 않는다.

| 묶음 | 사건 | 전체 창 | 장애 창 | 정상 창 |
|---|---:|---:|---:|---:|
| G0 | 12 | 132 | 108 | 24 |
| G1 | 12 | 122 | 98 | 24 |
| G2 | 12 | 140 | 119 | 21 |

각 묶음은12개 root가각1사건씩 있으며, 세 고장 종류가각4사건이다.

| 순환 | 학습 | 모델 선택용 검증 | 외부평가 |
|---|---|---|---|
| 0 | G2 | G1 | G0 |
| 1 | G0 | G2 | G1 |
| 2 | G1 | G0 | G2 |

모든 사건이 외부평가에 딱 한 번 들어간다. 순환마다 모델과 optimizer를 새로 만든다.
외부평가 사건을 본 다른 순환의 가중치를 가져오지 않는다.
외부평가는 과거 봉인된169창이 아니라 **기존 개발 자료 내부의 새 사건 분리 평가**다.

중요한 해석:
- 각 root의3사건은 고장 종류가 서로 다르므로, 알려진 서비스·고장 종류의
  미학습 조합을 평가한다. 같은 root×종류의 새로운 반복 사건을 따로 검증하지는 못한다.
- 같은 recording의 다른 사건은 양쪽에 남는다. 새로운 수집환경 독립성은 주장하지 않는다.
- recording을 통째로 나누면 root3개가 학습 정답에서 사라지므로,
  이번 알려진 서비스의 새 사건 문제와 섞지 않는다.
- 이미 연구자가 분석했던 자료다. 새 맹검 최종시험이라고 부르지 않는다.

## 4. 전처리에서 유지할 것과 다시 맞출 것

### 유지
- 확인된 공통 시간 정렬과10초 stride10 창.
- 원형7metric, 서비스별 지연시간열, Drain/Hawkes 로그 처리.
- 서비스12개 순서, 원형 정적 그래프24간선.
- 명시된 원형 인코더와 공동학습 head/loss.
- 기존 라벨의 정수화/포함형끝점 규칙. 경계에 걸친 장애37창은 표시하고 임의 삭제하지 않는다.

### 순환마다 새 적합
- metric/trace 스케일러는 해당 순환의 **학습 창만**으로 계산한다.
  원형 방식대로 정상+장애 학습 창의 평균/표준편차를 사용한다.
- 검증·외부평가 값을 바꿔도 학습 통계와 학습 입력이 불변인 검사를 둔다.
- 원형의 상수 채널/epsilon 정책을 공통 적용하며, 점수를 유리하게 만드는 clipping을 추가하지 않는다.

### 재사용 가능한 캐시의 조건
- 정규화 전 시계열처럼 학습 분할에 의존하지 않는 변환은 hash·계약 확인 후 재사용한다.
- 기존 Drain 템플릿은 별도 정상 로그3기록만으로 만들어졌다는 출처를 확인한다.
  그 기록은 각 순환에 공통 제공되는 외부 정상 학습참고자료로 선언한다.
  장애 검증/외부평가 로그로 템플릿을 다시 학습하지 않는다.
- 각 입력 창만으로 계산한 Hawkes baseline은 전 데이터의 정상 통계 적합과 다르다.
  템플릿·시각·horizon·solver가 같으면 해당 창의 캐시를 재사용할 수 있다.
- 기존 18특징 x와 과거 스케일러를 새 분할에 그대로 사용하지 않는다.

## 5. 비교 모델

1. **Eadro 공개 수리 포크 기반 복원본**: 기존 모달리티 encoder, GLU, GAT/pooling, head 유지.
2. **DiagMLP 수식 기반 복원본**: 같은 모달리티 encoder, 위치 정보와 전역 concat fusion.
3. **학습 사건의 root 빈도 기준선**: 진단 신호 없이 label prior만으로 얻는 점수 확인.
   이 분할에서는 각 root가 학습1사건씩이므로 동률이다.

원형 Eadro/DiagMLP가 관측·후보·분할·head 목적·학습 기회를 공유하도록 한다.
현재 구현의 Eadro dropout0 / DiagMLP0.1 등 모델별 설정은 그대로 명시한다.
GLU 교체 범위·노드 위치·그래프 처리도 다르므로 격차를 GNN 하나의 순수 인과 효과로 부르지 않는다.
두 복원본의 이전 checkpoint를 불러오지 않는다.
DiagMLP의 노드 위치는 원형 구조의 일부로 유지한다.
후보 식별 정보를 제공하는 것과 정답 서비스/주입 정보를 노출하는 것은 구분한다.

Eadro 원논문과 공개 포크, 정확한 저자 DiagMLP 통합 코드가 동일하다고 주장하지 않는다.
사용 source/config hash와 재구성 선택을 실행 기록에 고정한다.

## 6. 학습 기회와 모델 선택

| 항목 | 제안 규칙 |
|---|---|
| 기본 학습량 | 각 실행200epoch |
| optimizer | Adam, lr0.001, betas(0.9,0.999), eps1e-8, weight_decay0 |
| batch | 32 |
| seed | 11 / 23 / 37 |
| 실행 수 | 2방법×3순환×3seed=18 |
| 학습 목적 | 기존 joint loss: 탐지CE0.5 + 위치CE0.5 |
| 학습 순서 | 같은 순환·seed의 두 방법에 같은 창 배치 순서 |
| 선택 기준 | 검증 사건별 평균예측확률의 원인 cross-entropy 평균 최소, 동률은 이른epoch |

탐지 head는 원형 보존을 위해 학습에 남지만, 주 평가의 원인 순위를 탐지 결과로 차단하지 않는다.
평가 대상이 이미 장애로 주어진 조건부 진단임을 명시한다.

batch32에서200epoch의 실제 업데이트 수는 순환0/1/2가1,000/1,000/800이다.
같은 순환의 두 방법은 동일하다. epoch만 적고 업데이트 수를 숨기지 않는다.
공통 encoder/head 초기값의 일치를 확인하고 구조가 다른 fusion 초기화는 구분한다.

### 학습 한계 점검: 결과를 보고 무한 연장하지 않음

- **각 순환 내부에서만**, 6실행(2방법×3seed) 중 하나라도200epoch의
  검증 최선epoch가180이상이면 해당 순환의6실행을 전부400epoch까지 한 번 연장한다.
- 판단에 다른 순환의 검증/외부평가 결과를 사용하지 않는다.
- optimizer·모델·난수·배치순서 상태를 보존해 이어 학습하며, 재개 동등성을 먼저 검사한다.
- 400이상 자동 연장하지 않는다. 400끝에서도 최선epoch가360이상이면
  예산 제한을 명시하고 충분히 수렴한 최고 성능 비교라는 주장을 보류한다.
- 이 규칙을 쓰더라도 수렴이 수학적으로 증명되는 것은 아니다.
- 모든 순환의 설정·checkpoint 선택이 고정되기 전 외부평가 점수를 열지 않는다.

## 7. 진단 시점과 사건 점수

이번에는 **사건 관측 구간이 주어진 사후 진단**으로 제한한다.
최초10초 즉시 진단이나 장애 사전 예측으로 주장하지 않는다.
span 시작이 창 안에 있어도 종료가 이후일 수 있고 실제 수집 도착시각도 검증되지 않았기 때문이다.

이전 결과의 '창 정확도를 사건별로 평균'과 혼동하지 않도록,
이번 주 평가는 **사건당 한 순위**를 만드는 것으로 정의한다.

1. 해당 사건의 허용된 장애 창마다12개 후보의 예측확률을 계산한다.
2. 창의 확률을 서비스별로 평균한다.
3. 그 평균으로 사건당 서비스 순위 하나를 만든다.
4. 사건의 정답이 첫 번째인지/세 번째 안인지 채점한다.

사건 확률과 cross-entropy는 log-softmax/logsumexp 등 수치적으로 안정된 연산으로 계산한다.
점수 상한이나 반올림으로 인위적인 동률을 만들지 않는다.

모든 비교 모델에 동일한 창과 평균 규칙을 적용한다. 잘 맞은 창만 선택하지 않는다.
정상 창은 root 순위 분모에서 제외한다.
동률은 임의 ID/이름순으로 깨지 않고 동률 그룹에서 무작위 순위를 가정한 기대 credit을 준다.
점수를 반올림하거나 자르지 않은 값으로 순위를 계산한다.

- **주지표:** 사건 Top-1,36사건 균등.
- **보조:** 사건 Top-3.
- seed별36사건 결과를 먼저 계산하고3seed 평균/변동을 보고한다.
  108개의 예측을108개의 독립 사건으로 세지 않는다.
- 사건별 짝지은 차이·win/tie/loss와 recording별 결과를 남긴다.
- 불확실성 부록에는4recording cluster의 고정예측 paired bootstrap
  5,000회(seed20261017)의2.5/97.5백분위 범위를 항상 보고한다.
  작은4cluster와 공유학습/환경에 조건부인 탐색적 범위이며,
  독립 운영 모집단의 유의성 증명으로 쓰지 않는다.

기존 창 정확도나 창 정확도를 사건별로 평균한 수치와 이번 사건 단일순위 점수를
직접 빼서 개선량이라고 하지 않는다. 같은 새 규칙으로 평가한 방법끼리 비교한다.

## 8. 이전 실수를 막는 실행 전·후 검사

| 위험 | 중단/검사 조건 |
|---|---|
| 같은 사건 창이 양쪽에 들어감 | train/validation/evaluation 사건·episode 교집합0 |
| 정상 참고창이 경계를 넘음 | 정상 창의 episode 귀속과 분할 일치 |
| 학습에서 본 적 없는 root 문제와 혼합 | 각부분12root·3종류 지원, cold-root0 |
| 전체 자료로 정규화 | held 값 변경에 학습 통계/입력 불변 검사 |
| 기존 가중치/옛 특징 재사용 | 새초기화, 새스케일러, 허용된원형입력만 사용 |
| 피해 라벨을 임의 생성 | 원인/비원인 후보만 사용 |
| 관측 누락 사례·후보 삭제 | 36사건·12후보 유지; 필요한 행 누락은 실패로 보고 |
| 정답 정보가 입력에 포함 | 파일명/사건ID/type/주입설정/정답은 분할·채점에만 사용 |
| 정상예측으로 root점수 증가 | 장애 사건만 root분모, 별도 탐지점수와 혼합금지 |
| 과소학습한 비교군과 비교 | 동일 예산·선택 규칙, TRAIN/검증의사건오류·loss/epoch/update/경계선택 기록 |
| 계산/저장 오류 | 합성 채점검사, checkpoint 재추론, 독립 사건집계 |
| 불리한 결과를 보고 변경 | 외부평가 전에 규칙/선택 고정; 결과를 보고 같은평가를 재튜닝하지 않음 |

특히 모든 점수가 같을 때12후보의Top-1=1/12,Top-3=3/12가 나오는 채점 fixture를 둔다.
모델별 결과와 정답 매핑·서비스 순서·window→event 집계가 동일한지 별도로 확인한다.
TRAIN 사건도 잘 맞히지 못한 상태를 곧바로 관계 추론 구조의 결함이라고 해석하지 않는다.

## 9. 실행 순서와 산출물

1. **명세 고정:** 이계획, 입력hash, 36사건/394창/episode/후보 manifest.
2. **안전 입력 준비:** 허용행의 원형3모달 입력과 순환별 스케일러 생성·검사.
3. **실행기 검사:** 분할·누출·loss·동률·정상제외·재개 fixture, 작은 실행 비용 점검.
4. **본학습:** 18실행 및 사전 규칙에 따른 순환별 연장.
5. **선택 잠금 후 외부평가:** 고정 checkpoint만 추론하고 독립 재채점.
6. **실패 분석:** 사건별 오답, 종류별 양상, 관측 누락/경계/입력단서 검토.
7. **개선 결정:** 확인된 실패 하나와 대응되는 관측 하나가 있을 때만 다음 실험을 제안.

원인·피해 후보 구별에 필수인 정보가 현재 앞단에 없으면 최소한의 보완을 검토한다.
앞단에 이미 정보가 있으면 함부로 전처리를 다시 설계하지 않는다.
근거가 없거나 기존법으로 충분하면 제안 가설을 버린다.

산출물에는 manifest/config/history/checkpoint/외부예측/사건집계/검증/보고서를 포함한다.
기존 결과를 덮지 않으며 실패·중단·재시도 이력도 보존한다.
허용 입력 접근·수치·분할 검사가 실패하면 학습을 멈추고 보고한다.
