# 연구 방향 재정리: 기존 방법을 이해한 뒤 작은 개선을 검증하기

2026-10-14 · 조사·설계 보고서 · 모델 실행/새 학습 없음

## 1. 연구 과제

**AIOps → 마이크로서비스 장애 진단 → 원인 서비스 순위 개선**을 유지한다.
입력은 장애 전후의 서비스 관측 자료, 출력은 원인 후보 서비스의 순위다.
네트워크는 여러 고장 유형 중 하나이며 연구 분야를 네트워크 자체로 바꾸지 않는다.
자동 복구·전체 AIOps 플랫폼·원인 코드 한 줄까지의 설명은 범위 밖이다.

우리의 목표는 “MLP가 GNN보다 항상 좋다”가 아니다.
**비슷한 방법론의 충분히 강한 기준 모델이 어떤 조건에서 틀리는지 확인하고,
그 조건에 대응하는 한 부분의 변경을 정량적으로 입증하는 것**이다.

## 2. 장애를 만드는 방법과 찾는 방법

두 가지를 구분해야 한다.

- **장애 주입:** 정답을 아는 실험을 위해 CPU 자원을 소모시키거나,
  메모리를 압박하거나, 패킷을 지연/손실시키는 것.
  Eadro는 Chaosblade로 CPU·지연·손실을, BARO는 stress-ng/tc 등으로
  CPU·메모리·지연·손실을 실험했다. 주입 도구 자체가 원인 진단 모델은 아니다.
- **장애 진단:** 주입 대상이라는 정답을 모델에 알려주지 않고,
  관측 자료에서 원인 후보를 찾아 순위를 만드는 것.
  통계적 변화 점수, 인과/의존 그래프, 다중 자료 학습 등이 여기에 속한다.

주입 기록과 실제 장애 효과는 같지 않다. 따라서 데이터 정답의 대응뿐 아니라
관측 가능한 효과가 있는지도 별도 확인해야 한다.

## 3. DiagMLP는 무엇을 했나?

“원자료 → 단순 MLP”가 아니라 다음 구조다.

```text
로그·지표·트레이스 원자료
    ↓ 기존 연구의 전처리·시간 정렬·입력 표현
    ↓ 기존 연구의 모달별 인코더
서비스별 metric/log/trace 벡터 + 학습 가능한 서비스 위치 벡터
    ↓ Modal Fusion MLP
서비스 1 벡터 | 서비스 2 벡터 | ... | 서비스 N 벡터
    ↓ Node Fusion MLP
전체 시스템 벡터
    ↓ 기존 과제별 head
원인 서비스 점수 / 장애 탐지 / 장애 종류 분류
```

두 Fusion MLP는 각각 `Linear → LayerNorm → ReLU → Dropout`인 단층 블록이다.
위치 벡터는 모달 결합 **전에** 이어 붙인다. Node Fusion은 모든 서비스의 정보를
함께 받으므로, DiagMLP를 “서비스를 각각 보고 전체 관계 정보는 전혀 못 보는 모델”로
설명하면 틀리다. 명시적 그래프 연산을 뺀 것이지 모든 서비스 간 정보 이용을 없앤 것이 아니다.

Eadro backbone의 예에서는 지표·트레이스 시간열의 convolution 인코더와
로그 event의 Hawkes 기반 표현/선형 인코더 같은 앞단이 남는다.
다른 backbone은 다른 표현·인코더·과제를 유지한다. 이들 모두가 하나의 동일한
전처리나 추가 계층 설정을 쓴다고 말할 수 없다.

이 설계는 전처리/인코딩의 기여를 제거하지 않고,
**그 뒤에 복잡한 그래프 모델링이 꼭 필요한가**를 시험한 것이다.
논문 방정식과 로컬 재구현의 hidden width·GLU 교체 경계·split은 구분해야 한다.

## 4. 비슷한 방법론의 비교군 선정

| 방법 | 핵심 방식 | 이번 연구에서의 역할 |
|---|---|---|
| **DiagMLP — Eadro backbone** | 기존 다중 자료 인코더 + 위치 벡터 + 모달/노드 MLP fusion | **가장 가까운 중심 기준 모델** |
| **Eadro** | 같은 계열의 인코더 + GLU + GAT/attention pooling + 공동 탐지/위치 head | **동일 backbone의 문헌 비교군** |
| TVDiag | alert/FastText 표현, 모달별 GraphSAGE, task/cross-modal 대조학습 | 관련 방법·기존 구성요소 확인. 현재 최소 실행 비교군으로 확대하지 않음 |
| DeepHunt | 요청 개수 등을 포함한 특징, graph autoencoder 재구성, root feedback ranking | 관련 방법·count/masking 선행성 확인. supervision/head 차이를 지운 동일 모델 비교는 금지 |
| BARO | 정상 대비 metric 변화 점수와 변화점 탐지 | 필요할 때의 **비학습 통계 보조 기준**, 같은 MLP 계열로 부르지 않음 |

핵심은 **DiagMLP와 Eadro 두 모델**이다.
임의 수치 특징만 넣은 작은 자체 MLP와 복잡한 native Eadro를 비교하거나,
parameter 수만 맞춰 강한 방법을 줄이는 방식은 사용하지 않는다.
같은 사건·후보·관측 시간·자료/라벨 예산·학습 선택 기준을 맞춘다.

TVDiag에는 이미 공유 노드 scorer와 관측 비활성화 augmentation이 있고,
DeepHunt에는 request count·feature masking·공유 scorer·ranking loss가 있다.
“공유 MLP”, “count 추가”, “마스킹”, “모달 gating”을 각각 새로운 발명처럼
소개하지 않는다. Eadro에도 GLU가 이미 있다.

출처와 정확한 입력/비용/구현 계약은 [METHODS.md](METHODS.md)에 정리했다.
이 선정은 비교 가능성에 따른 것이며 현재 조건의 성능 순위를 측정한 결과가 아니다.

## 5. DiagMLP의 GNN 비교 결과는 실제로 어땠나?

직접 교체한 backbone은 Eadro(SN/TT), TVDiag(GAIA), DeepHunt(D1/D2)다.
DiagFusion과 CHASE는 추가 문헌 비교이며, 모두 GNN→DiagMLP 교체를 실행한 것이 아니다.
원문 Table IV의 직접 짝지은 Top1은 다음과 같다. 단위는 %다.

| 데이터 | 교체 전 backbone | 교체 전 Top1 | DiagMLP Top1 | 평균 차이 |
|---|---|---:|---:|---:|
| SN | Eadro | 41.8 ± 14.5 | 80.2 ± 3.1 | +38.4%p |
| TT | Eadro | 91.1 ± 2.2 | 98.5 ± 0.8 | +7.4%p |
| GAIA | TVDiag | 59.8 ± 0.8 | 61.0 ± 1.0 | +1.2%p |
| D1 | DeepHunt | 79.8 ± 0.4 | 79.8 ± 1.0 | 0.0%p |
| D2 | DeepHunt | 78.9 ± 0.7 | 79.0 ± 0.5 | +0.1%p |

`±`는 원문에 기재된 표준편차이지 신뢰구간이 아니다.
Table IV 각주상 표준편차가 있는 행은 저자가 독립 실험 10회로 산출했고,
없는 다른 셀은 인용 논문에서 가져왔다.

정확한 해석은 **“이 공개 benchmark와 처리 조건에서 Eadro 대비 크게 개선했고,
다른 두 backbone과는 대체로 비슷하다”**다.
모든 지표가 개선된 것은 아니다. GAIA Top5, D1 Top5, D2 Top3는 낮다.

### 원문을 그대로 믿고 확대하면 안 되는 부분

- TT DiagMLP의 Top3가 99.7인데 Top5가 99.2로 기재되어 있다.
  같은 순위에 대한 통상적 Top-k라면 불가능하다. 표기/평가/집계 중 원인은
  미확인이고, 99.2를 임의로 고치지 않았다.
- D1 본문은 31.0을 DeepHunt 값처럼 설명하지만 표에서는 Eadro 값이다.
  직접 비교의 D1 Top1은 큰 개선이 아니라 동률이다.
- SN/TT 전처리는 저자가 재구현했고 분할 누수 위험 수정도 보고했다.
  따라서 원 Eadro 논문의 원래 성능을 그대로 재현한 비교라고 읽으면 안 된다.
- 논문은 backbone의 전처리·임베딩·학습 목적 유지라고 설명하지만,
  GLU 경계·세부 폭·정확한 split/wiring이 모두 공개적으로 확인된 것은 아니다.
  fusion·정규화·용량도 바뀌므로 인접행렬만 toggle한 실험과 동일하지 않다.

전체 수식·원문 90개 결과 셀·각주·불일치는 [DIAGMLP.md](DIAGMLP.md)에 보존했다.
이 논문 수치와 우리 사건 분할·5epoch 자체 모델 수치를 한 순위표로 섞지 않는다.

## 6. 기존 방법의 어떤 부분이 실제로 조사할 가치가 있나?

현시점에서 구분해야 할 근거는 다음과 같다.

| 관측/주장 | 확인 수준 | 연구에 사용할 수 있는 의미 |
|---|---|---|
| DiagMLP의 node concat 크기가 서비스 수에 비례 | 논문·수식으로 확인 | 구조적 제약이지만 이번 고정 후보 과제의 주 문제로 바꾸지 않음 |
| 공개 Eadro fork에서 count를 계산하고도 최종 chunk에는 latency만 전달 | **고정 공개 코드로 확인** | 구체적으로 변경 가능한 정보 전달 경로 |
| count 누락 때문에 원 DiagMLP가 오분류했다 | **아직 미확인** | 적절히 학습한 native-like 기준 모델에서 먼저 확인할 가설 |
| 로컬 자체 모델에서 희소 trace·미포함 로그와 오답을 봄 | 제한된 로컬 개발 관측 | 입력 점검의 동기. 원논문 모델 결함의 증거는 아님 |
| 로그 추가·gating·count·masking이 새로운 원리다 | 선행연구와 중복 | 그대로 새 기여로 주장하지 않음 |

공개 fork의 경로는 다음과 같다.

```text
원 span들
  → parse_spans: 서비스/초별 duration 목록
  → deal_traces: 평균 latency + invok count 계산
  → get_chunks: latency만 trace 입력으로 전달
  → TraceModel: 지연 시계열 임베딩
```

예를 들어 10초 동안 초당 10ms span이 1개씩 있는 경우와 10개씩 있는 경우는
같은 평균 지연 시계열이 된다. 관측 개수는 10 대 100이다.
이 정보 구분이 사라지는 것은 합성 예와 소스로 확인했지만,
**그 구분이 원인 순위에 유용한지는 아직 시험하지 않았다.**
다른 지표·로그가 이미 충분히 보완할 수도 있다.

## 7. 설계안: 관측 개수 보존 모듈 하나

최초 초안의 두 항목에서 **고유 span 개수 하나만** 남겼다.
관측된 초의 비율은 양수 duration 조건에서 원래 latency에서 유도할 수 있어
이번의 독립 정보 보완 가설에서 제외했다.

```text
기존 DiagMLP 입력:
metric 벡터 | log 벡터 | trace 벡터 | 서비스 위치 벡터

제안 입력:
위와 동일한 입력 | log(1 + 해당 서비스의 고유 span 수)

그 뒤의 Modal Fusion / Node Fusion / root head는 유지
```

고유 span은 같은 `(traceID, spanID)`를 한 번만 세며,
기존 latency의 중복 weighting이나 창·서비스 귀속 규칙은 바꾸지 않는다.
count=0을 정상·무요청·수집 실패로 단정하지 않는다.
독립적인 collector 상태를 관측하지 않았으므로 이 값을 “수집 신뢰도”라 부르지 않는다.

**이것은 작은 입력 표현 개선안이지 새로운 범용 진단 원리라고 확정한 것이 아니다.**
DeepHunt가 request count를 이미 사용하므로,
새 기여의 가능성은 해당 경로의 실패 조건·실제 추가 효과·비용을 얼마나
명확히 분리해 입증하느냐에 달려 있다. 이름만 새롭게 붙여 해결하지 않는다.

상세 입출력·parameter 증가·중복 처리·비교 대조는 [DESIGN.md](DESIGN.md)에 있다.
효과가 없으면 이 후보를 버리고 모델을 더 복잡하게 붙이지 않는다.

## 8. 앞으로의 진행 순서와 판정

### Gate A — 비교 기준을 먼저 제대로 세우기

원 인코더·로그 처리·task head를 보존한 DiagMLP/Eadro가
같은 개발 사건과 충분한 학습 조건에서 어떤 오류를 내는지 확인한다.
저자 코드와 동일하다고 보장되지 않는 부분은 방정식 기반 복원으로 명시한다.
현재 자체 18-feature 모델의 오답만으로 이 단계가 끝났다고 간주하지 않는다.

### Gate B — 구조적 정보 손실이 실제 오류와 연결되는지 확인

관측량이 적을 때/많을 때 기준 모델의 오류와 순위를 비교하고,
count가 이미 다른 보존 특징으로 충분히 표현되는지도 본다.
원 baseline에 유의미한 대상 오류가 없으면 설계 후보를 진행하지 않는다.

### Gate C — 변경 하나의 정량 효과 확인

같은 원자료에서 count만 보완한 paired 비교를 한다.
주 평가 사건 균등 Top1, 보조 Top3/MRR·고장 종류별 결과·관측량별 결과·처리 비용.
추가 parameter만의 효과와 서비스/recording의 고정 패턴 이용을 별도 대조한다.
모델 종류의 우위를 말하려면 Eadro에도 동일한 보완 정보를 제공한다.

기각/축소 조건은 개선 부재, 다른 장애 유형의 악화, 비용 대비 이득 부재,
용량/서비스 사전확률 대안으로 설명되는 결과다.
신뢰구간·seed별 변동과 공유 사건/recording의 제한을 숨기지 않는다.
실행 전 최소 유의미한 개선 폭·허용 비용·학습 선택 예산을 사전 고정한다.

**현재 결정:** 상위 연구 문제와 비교군은 정리했다.
관측 개수 보존은 첫 번째로 검증할 수 있는 좁은 설계 후보다.
**아직 돌파구나 논문 기여가 입증된 것은 아니다.**
이번에는 문헌·소스 조사와 설계까지만 수행했고 새 모델/실험은 시작하지 않았다.
