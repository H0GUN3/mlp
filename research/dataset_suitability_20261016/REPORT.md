173사례의 정확한 credit 합계·동점 수와 RCAEval240건의 구성 근거를 정리했다.

## 문제, 가설, 확인 방법

이전 적합성 판단에는 확인 범위보다 강한 표현이 섞여 있었다. 특히 과거의 RCABench `369/350` 제한은 전체 구성 검토를 반영하지 않은 값이다. 1,168건의 비네트워크 사례 중 설정과 정답이 충돌하는 1건을 제외하면 **1,167건은 명목상 단일 설정 표적 과제의 검토 후보**다. 이 숫자는 물리적 인과 원인이 확인된 사건 수, 완전한 텔레메트리 확보 수 또는 승인된 최종 학습 집합이 아니다.

이번에 확인한 가설은 세 가지다.

1. 관측 기반 진단 점수는 사례마다 정답 표적만이 아니라 관측된 전체 후보를 사용해 계산해야 한다.
2. 데이터 적합성은 라벨 수만으로 판단할 수 없다. 반복 조건, 사건·환경 공유, 정상/장애 구간 지원 및 실제 관측 범위를 함께 봐야 한다.
3. 메타데이터 전수조사와 관측 데이터 전수 확보는 다르다. 일부 표본의 감사 결과를 나머지 사례의 관측 품질이나 corpus 독립성으로 확대하지 않는다.

RCABench의 네 진단 기준은 점수 산출 전에 고정했다. 각 기준으로 계산한 순위는 고정한 채, 명목 설정 표적 하나를 정답으로 보는 계약과 허용된 원래 정답 서비스 집합을 정답으로 보는 계약으로 각각 채점했다. 나머지 자료는 허용된 인덱스, 분할 메타데이터, 해시 및 이전 감사 결과만 사용했다. 새 다운로드, 추가 모델 학습, checkpoint 추론, 원본 변경은 하지 않았다. RCABench에는 고정된 단순 점수기로 새 진단 순위를 계산했다.

## RCABench: 유일한 신규 점수 실험

### 표본과 계산 범위

HTTP 796건의 기존 가용성 전수 감사는 재사용했다. 이 기존 요약은 대부분 정답 표적과 상대 서비스만 상세 수치를 보존했으므로, 이를 전체 후보 순위 점수로 쓰지 않았다. 새 점수 계산은 HTTP 사례 중 **173건**에 한정했다. semantic 설정 그룹을 고정 해시 순으로 선택하고, 기존 정밀 표본 12건이 속한 그룹을 추가했다. 최종 표본은 164/759 그룹이며, 선택 그룹 전체를 포함했고 선택·미선택 그룹 간 중복은 없다. 보류한 HTTP 623건에는 새 점수를 계산하지 않았다. 이전 가용성 감사 이력이 있으므로 이 보류분도 미접촉 최종 평가 자료로 인증되지 않는다. 나머지 626건은 메타데이터만 검토했으며 HTTP 점수를 일반화하지 않는다.

각 사례의 정상·장애 trace에서 서비스별 span 행을 집계했다. 후보는 전체 관측 서비스 이름의 합집합으로 구성했고 `loadgenerator`도 포함했다. 173건 모두 사례당 49개 후보, 총 8,477개 후보-사례 쌍이다. 정상 구간은 `[시작, 종료)`, 장애 구간도 `[시작, 종료)`로 처리했다. 같은 시간 경계 행은 정상에서 제외하고 장애에서 포함했다. 알려진 HTTP 상태는 100부터 599, 오류는 400부터 599로 정의했다. 분모가 없거나 관측되지 않은 점수는 결측으로 보존했으며 정상 0점으로 바꾸지 않았다. 집계 단위는 요청이나 독립 사건이 아니라 배포된 span 행이다.

| 고정 기준 | 점수 | 결측 후보-사례 쌍 |
|---|---|---:|
| 균등 | 모든 후보 동점 | 0 |
| 장애 HTTP 오류 비율 | 장애 HTTP 오류 행 / 장애 유효 HTTP 상태 행 | 3,637 |
| HTTP 오류 비율 증가 | 장애 비율 - 정상 비율 | 3,647 |
| 장애 span 오류 비율 | 장애 span 오류 행 / 장애 전체 span 행 | 3,635 |

각 후보는 점수 순서로 평가하며 동점은 균등 무작위 순위의 기대값으로 계산했다. 결측 후보는 지원되는 점수 뒤의 별도 동점 구간에 둔다. 두 정답 계약의 결과 차이는 방법 개선이 아니라 평가 정답을 바꾼 효과다.

### RCABench 분할 지원

전체 metadata census는 1,422건, semantic 설정 그룹은 1,322개다. 사례 ID 해시로 나눈 비교 분할은 반복 그룹 45개, 130건을 여러 fold에 흩뜨렸다. semantic 그룹 해시 분할은 동일 설정 그룹의 fold 간 분리를 0으로 만들었고 fold별 사례 수는 494/480/448건이었다. 이는 반복 설정 누출 위험을 줄이는 메타데이터상 조건일 뿐, 독립 수집을 보장하지 않는다. 760개의 양의 시간 중첩 쌍 중 502쌍은 fold를 가로지르며 모든 10개 namespace도 각 fold에 나타난다. 이 분할은 건식 점검이며 최종 분할로 채택되지 않았다.

비네트워크 1,167개 명목 후보의 세 fold heldout 사례 수는 406/393/368건이다. 그룹 분할에서 TRAIN에 root 지원이 없는 heldout 사례는 fold별 2/0/0건이며, fold0의 두 사례는 모두 같은 `ts-verification-code-service` root다. 따라서 고유 root 지원 공백은 1/0/0개다. 유형 지원 공백은 0/3/2건이다. 지원 공백을 없애려고 사례를 이동하지 않았다. 이 결과도 설정 표적의 학습 후보 지원만 다루며 물리적 원인 검증은 아니다.

## RCAEval: 관련 범위는 메타데이터만 준비됨

인덱스 735행 중 trace 중심 범위로 정한 Online Boutique와 Train Ticket RE2/RE3는 240건, 78개 `(system, root, fault)` 그룹이다. 나머지 495건인 RE1 및 Sock Shop은 이번 범위에서 제외했다. 로컬 파일과 행 수의 기존 감사는 RE2 180건에 한정된다. RE3 60건은 로컬 사례 감사가 없다. RE3 자료를 내려받거나 열지 않았다.

그룹 해시 건식 분할은 78개 그룹을 모두 한 fold에 유지했다. 반대로 사례 ID 분할에서는 반복된 동일 조건 78개 중 67개의 사례가 여러 fold에 걸렸다. 동일 root/fault 조건의 라벨이 fold 사이에 공유된다는 사실만으로 독립 반복 사례들이 같은 장애 사건이거나 관측 누수가 있다고 볼 수는 없다. 사건 독립성은 이번 metadata로 확인되지 않았다. 독립된 반복 사건이라면 알려진 조건의 다른 반복을 평가하는 사례 분할도 유효한 질문이며, 같은 조건 자체를 fold 사이에서 분리하지 않는 조건 분리는 더 엄격하지만 다른 평가 과제다. 그룹 분리만으로 독립 사건, 새 원인, 관측 품질이 보장되지는 않는다. RE2→RE3 비교에서는 OB root 2개, TT root 2개의 라벨이 겹쳤고, RE3의 root/fault 쌍은 RE2에 정확히 겹치는 쌍이 없었다. RE3의 `f*` 고장 분류와 RE2 분류 간 대응 관계는 확인되지 않았다.

기존 시스템별 `54/18/18` 분할 경계는 변경하지 않았다. 이 경계가 관련 전체 240건에 어떻게 대응하는지는 확인되지 않았다. 따라서 이번 결과는 인덱스 기준 분할 가능성에 한정하며 텔레메트리 후보 inventory, RCA 순위, 모델 학습 또는 성능을 주장하지 않는다.

## Eadro: 작은 장애 사례 수만으로 부적합 판정 불가

허용된 개발 묶음의 metadata로 확인한 장애 사건은 SN 36건, TT 81건이다. 각각 4개와 9개 fault recording에 걸쳐 있으며 root 수는 12개와 27개, 고장 유형은 각 3개다. 각 root와 유형 조합은 한 번씩만 나타난다. 추가 normal-only archive recording은 장애 라벨 사례를 늘리지 않는다. 이번 확인은 특징 관측값을 읽지 않고 분할 구성과 지원만 검사했다.

기존 사건 3-fold에서는 사건 ID 중복이 없고 모든 root와 유형이 학습 및 heldout에 나타났다. 그러나 각 자료의 모든 fault recording은 학습과 heldout에서 공유됐다. 그러므로 이 분할은 이미 알려진 recording 안에서 다른 장애 사건을 보는 개발 점검이며 recording 독립 평가가 아니다.

recording 전체를 heldout하는 가상 조건은 유효한 공동 환경·새 root 스트레스 조건이다. 다만 매 holdout마다 해당 recording에 속한 root 세 개의 학습 장애 사례가 사라진다. 후보 inventory 유지와 root의 학습 지원은 서로 다른 조건이며, 이 결과는 공동 변화에서의 성능을 측정하지 않았다. 고장 유형 holdout은 root를 유지하지만 정상 창도 episode의 고장 유형을 따라 배정되어 heldout 유형의 정상 창은 학습에 들어가지 않는다. 어느 정책도 최종 분할로 채택되지 않았다.

이전에 나온 “CPU는 쉽고 network는 어렵다”는 일반화도 이번 metadata 점검으로 뒷받침되지 않는다. 특히 이전 TT 개발 결과에서 network fault validation Top1은 90.94%로 보고된 바 있어, 해당 주장은 그 과거 실험에만 한정해야 한다. 본 보고서는 그 모델을 재실행하거나 성능을 새로 검증하지 않았다.

## ops-lite: 전수 metadata와 관측 표본은 다름

전체 manifest 455건의 metadata 분포는 TrainTicket 275건, Hotel Reservation 148건, OTel Demo 32건이다. 기존 관측 감사 표본은 시스템당 10건씩 총 30건으로 의도적으로 균형화돼 전체 시스템 구성을 대표하지 않는다. 전체 metadata에는 required fault 항목이 1개인 사례 437건과 2개인 사례 18건이 있고, 표본 30건은 모두 1개다. 전체의 role 항목은 required 473, optional 81, not-effective 77이며 표본은 각각 30, 12, 3이다. 항목 수와 서로 다른 root 서비스 수는 동일하지 않다.

455건은 metadata census이지 전체 telemetry 취득 또는 감사가 아니다. 기존 관측 근거는 30건에 한정되고 나머지 425건의 관측 품질은 미확인이다. 선택 표본은 전체보다 fault type 지원도 좁다. 그러므로 전체 metadata를 층화와 후보 탐색에 쓸 수는 있지만 이를 대표성 또는 모델 적합성의 증거로 삼을 수 없다.

RCABench와의 비교에서 사례명, task ID 및 시간 metadata가 각각 197건에서 일치했다. 숫자 injection ID는 204개가 겹쳤지만, 그중 8쌍은 사례명이 달라 ID만으로 동일 사례라 판정하지 않았다. 비어 있지 않은 관측 파일의 정확한 SHA-256 일치는 80개 hash 그룹이며, 이는 ops 8개 사례 디렉터리와 RCABench 8개 사례 디렉터리에 연결된다. 일부 공유 관측 바이트는 확인됐지만, 일치하지 않은 자료가 독립이라는 뜻은 아니다. 재포맷·시간 이동 중복, publisher와 author의 연결, 라이선스 적합성은 남은 미확인 사항이다. 설정 metadata는 저장 형식이 비교 가능하지 않아 동일 설정인지 결론 내리지 않았다.

## 데이터별 다음 판정에 필요한 실험

아래는 후속 실험 권고이며 이번에 실행한 작업이 아니다.

1. **RCABench:** 주 데이터 후보는 유지한다. 우선 이미 확보한 사례에서 명목 설정 표적 순위화와 원래 허용 정답 집합 순위화 중 연구 과제를 정하고, 사용할 관측과 그룹별 학습·평가 역할을 고정한다. 그다음 같은 계약으로 문헌 방법을 비교할 수 있다. 물리적 원인 식별이나 새로운 수집 환경의 일반화까지 주장하려면 각각 추가 관측·개입 근거와 독립 수집 조건의 평가가 필요하다. 그런 강한 주장에 필요한 근거가 아직 없다는 이유만으로 현재 자료를 연구에 사용할 수 없다고 결론 내리지는 않는다.
2. **RCAEval:** RE3 접근 정책과 기존 최종 경계를 먼저 확인한 뒤, 허용된 개발 범위에서 RE3의 실제 파일·행·서비스별 관측 지원을 감사한다. 사건 식별 정보와 split manifest를 대조해 독립성 및 기존 `54/18/18` 경계의 240건 대응을 확인해야 한다. 이 확인 전에는 RE3 raw acquisition이나 최종 자료 재배치를 완료된 단계로 간주하지 않는다.
3. **Eadro:** 개발·재현 보조 역할은 유지한다. 현재 recording holdout으로도 환경 변화와 미학습 원인 조건이 함께 바뀌는 개발 실험을 설계할 수 있으나, 이번에는 성능을 측정하지 않았다. 이미 사용한 사례를 미접촉 최종평가라고 부를 수는 없다. 반복 변동을 분리하거나 환경 변화만의 효과를 평가하려면 같은 원인·고장 조건의 독립 반복 수집이 추가로 필요하다.
4. **ops-lite:** 표본 밖 사례의 관측 품질을 별도 층화 표본에서 검사하고, 중복 비교를 시간·형식 변환에 강한 방식으로 확장한다. 배포 출처와 라이선스를 확인한 뒤에야 학습 또는 독립 평가 역할을 결정할 수 있다.

**최종 결론:** 현재 근거는 각 자료의 제한된 개발·진단 역할과 남은 검증 조건을 식별한다. 어느 자료도 이 보고서만으로 완전한 인과 root 증거, 독립 최종시험 또는 전 corpus 모델 성능이 입증된 것으로 판정하지 않는다. 주 데이터 선택, 추가 취득, 분할 변경 및 후속 실험은 별도 결정 사항이다.
