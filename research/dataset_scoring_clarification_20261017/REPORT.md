# 후속 평가 준비 보완—새 모델 평가 없음

## 목적과 범위

이 보완은 2026-10-17까지 완료된 자료 적합성·준비도 결과를 이어서 정리한다. 요청된 좁은 확인은 저장된 RCABench 173사례의 Top1 산술, RCAEval trace-primary 240건의 구성, 그리고 서로 다른 RCAB 라벨 규칙의 해석 경계다. 새 모델 평가·학습·checkpoint 추론은 없으며, 원시 telemetry/archive를 읽거나 다운로드하지 않았다. 점수 입력과 기존 산출물은 읽기 전용으로 다뤘고, 보호된 native/RCAEval 최종 자료도 열지 않았다.

이번 일은 연구 주제를 새로 전환한 것이 아니라 **후속 평가 준비**다. 기존 최신 SN 결과는 이미 완료된 결과로 취급하며 재실행하지 않았다. 중단된 TT/RE2 작업은 계속 중단 상태이며 여기서 재개하지 않았다. 기존 33개 테스트 통과는 구현·계산 검증이지, 정답 의미의 동등성이나 DiagMLP 진단 능력의 과학적 증거가 아니다.

## 저장 점수의 분모·평균·동점 규칙

**네 기준 모두 N=173 사례이며 평균은 각 사례의 Top1 credit 합을 173으로 나눈 사례 균등 평균(그룹·창 가중 없음); 지원 점수의 최상위 동점 집합 T에서 허용 정답 수 g에 대해 credit=g/|T|, 지원 점수가 없을 때만 결측 후보 전체를 동점 처리한다.**

후보별 점수 결측은 해당 후보의 미지원 점수이지 사례 제외가 아니다. 따라서 HTTP 및 span 기준의 후보 결측 수가 커도 평가 분모는 173을 유지한다. credit 0/부분/1은 사례별 결과 분류이며, “부분 credit 사례 수”는 “최상위 동점 사례 수”와 같지 않을 수 있다.

| 기준 | 정답 계약 | 사례 N | credit 합 | 평균 | credit 0 / 부분 / 1 사례 | 부분 credit 사례 | 최상위 동점 사례 |
|---|---|---:|---:|---:|---:|---:|---:|
| 균등 | 명목 표적 1개 | 173 | 173/49 | 1/49 = 0.020408 | 0 / 173 / 0 | 173 | 173 |
| 균등 | 원래 허용 정답 집합 | 173 | 346/49 | 2/49 = 0.040816 | 0 / 173 / 0 | 173 | 173 |
| 장애 HTTP 오류 비율 | 명목 표적 1개 | 173 | 2,280,391/27,405 | 2,280,391/4,741,065 = 0.480987 | 83 / 8 / 82 | 8 | 8 |
| 장애 HTTP 오류 비율 | 원래 허용 정답 집합 | 173 | 2,889,077/27,405 | 2,889,077/4,741,065 = 0.609373 | 62 / 6 / 105 | 6 | 8 |
| HTTP 오류 비율 증가 | 명목 표적 1개 | 173 | 2,307,796/27,405 | 2,307,796/4,741,065 = 0.486767 | 82 / 8 / 83 | 8 | 8 |
| HTTP 오류 비율 증가 | 원래 허용 정답 집합 | 173 | 2,916,482/27,405 | 2,916,482/4,741,065 = 0.615153 | 61 / 6 / 106 | 6 | 8 |
| 장애 span Error 비율 | 명목 표적 1개 | 173 | 98 | 98/173 = 0.566474 | 75 / 0 / 98 | 0 | 0 |
| 장애 span Error 비율 | 원래 허용 정답 집합 | 173 | 99 | 99/173 = 0.572254 | 74 / 0 / 99 | 0 | 0 |

독립 재계산은 여덟 행의 정확 credit 합과 173사례 전부의 점수 순위로부터 산출한 credit을 대조했다. 사례별 저장 Top1과의 최대 절대 차이는 float 표현 기준 `5.551115123125783e-17`이었다. HTTP 장애 오류 비율의 실제 부분 credit 예는 `ts0-ts-ui-dashboard-request-delay-wcm5qd`의 1/28, `ts0-ts-ui-dashboard-response-delay-zd6lz6`의 1/27이다.

사용자가 지적한 span 산술도 확인된다: 명목 표적은 98/173 = 56.6474%, 원래 허용 정답 집합은 99/173 = 57.2254%다. 숫자가 일치한다고 각 사례에 동점이 없다는 뜻은 아니므로 사례별 동점 집계와 함께 읽어야 한다. 정답 계약이 바뀌면 같은 점수의 credit도 바뀐다. 기준 간 순서 역시 역전된다: 명목 표적 계약에서는 span 0.566474가 HTTP 장애 오류 비율 0.480987보다 높지만, 허용 정답 계약에서는 HTTP 0.609373이 span 0.572254보다 높다. 이는 허용 정답이 다른 평가 질문이며, 어느 계약이나 기준이 보편적으로 더 옳다는 결론은 아니다.

## RCABench 라벨 의미와 범위

기존 RCAB 감사에서 **1,167건은 명목 설정 표적 과제의 후보**다. 이는 물리적 단일 원인이 입증된 수, 독립 사건 수, 또는 DiagMLP 오류 건수가 아니다. 이번 재계산은 기존 저장 후보 점수의 오프라인 순위 산술을 확인했을 뿐, 그 순위를 모델 예측으로 바꾸거나 진단 성능 평가를 수행하지 않았다.

라벨 계약 사이에는 검증되지 않은 버전 연결을 전제하지 않는다. 고정 `chaos-experiment` 생성 코드의 복수 `ground_truth.service`는 설정 기반 **예상 영향 목록**이고, 현재 ops-lite 설명의 HTTP `also_accept`는 특정 경우의 관측상 대안 예측 허용이다. 두 필드가 일부 같은 서비스 이름을 담을 수 있어도 같은 라벨 규칙이라는 증거는 없다. 저장된 RCAB 아카이브가 인용된 생성 코드 revision으로 만들어졌는지, ops-lite의 현재 `main` 설명이 고정 release에 어떻게 대응하는지는 **미확인**이다. `also_accept`를 과거 RCABench 생성 규칙에 소급하지 않는다. 설정 표적 계약과 관측상 허용 집합 계약은 별도로 보고하며, 어느 쪽도 자동으로 최종 gold라고 정하지 않는다.

세부 판정과 근거 링크: [정답 의미 인계](LABEL_SEMANTICS.md), [채점 산술 인계](SCORING.md). 고정 코드 링크와 현재 ops-lite README 링크는 정답 의미 인계에 기재되어 있다.

## RCAEval 240건: 구성과 획득 구분

| 자료군 | 인덱스 사례 | 기존 감사에서 관측 확보 | 기존 로컬 사례 감사 없음 |
|---|---:|---:|---:|
| RE2-OB | 90 | 포함 | 0 |
| RE2-TT | 90 | 포함 | 0 |
| RE3-OB | 30 | 미포함 | 30 |
| RE3-TT | 30 | 미포함 | 30 |
| **합계** | **240** | **180** | **60** |

240은 90/90/30/30의 trace-primary **메타데이터 범위**다. “180 관측 확보/60 미확보”는 기존 2026-10-16 로컬 획득·준비도 감사 범위이지, 새 다운로드 집계가 아니다. 특히 60건은 인덱스에 없다는 뜻이 아니라 기존 로컬 사례 감사가 없다는 뜻이다. 240개 메타데이터 확인을 240건의 로컬 관측 확보로 표현하지 않는다. 반복 root/fault 조건은 구성의 일부이며, 240이 독립 사건 240개임을 뜻하지 않는다.

근거 집계: [RCAEval 구성 인계](INVENTORY.md), [기존 저장 인덱스 결과](../dataset_suitability_20261016/rcaeval_trial.json). 기존 다운로드 원장과 파일 인벤토리, 감사시점 및 한계도 인계 문서에 연결되어 있다.

## 기존 ops-lite 중복 근거 및 자료 역할

ops-lite **197건**은 ops-lite와 RCABench 사이의 사례 metadata 일치다. 별도로 기존 표본에서 **8사례에 연결된 80개 비어 있지 않은 파일 hash 그룹**이 관측 바이트 일치 근거다. 197 metadata 일치를 197건 관측 일치로, 또는 8사례 hash 결과를 전체 corpus의 독립성 증거로 확대하지 않는다. 비일치도 변환된 중복이 없음을 증명하지 않는다. [기존 ops-lite 감사](../dataset_suitability_20261016/OPS.md)와 [저장 비교 결과](../dataset_suitability_20261016/ops_trial.json)를 참조한다.

| 자료 | 후속 평가 준비에서의 역할 |
|---|---|
| TT | 기존 기준선 유지 |
| SN | 집중 비교 조건과 반복 오류 분석 |
| RCAEval | 후속 비교 자료 |
| RCABench | 정답 계약을 고정한 뒤 조건부 확장 |
| ops-lite | 중복을 고려해 추가 검토할 자료 |

역할 표는 자료의 확정된 성능 순위나 최종 채택 결정을 뜻하지 않는다. 최신 SN 결과는 완료된 기존 결과이고, 중단 TT/RE2 작업은 미완료·중단 상태로 남는다. 이번 작업은 그 어느 쪽도 재실행하지 않았다.

## 남은 확인 한계

본 보완은 저장된 순위와 인계 수치의 정합성을 확인했다. 정답 의미의 세대 간 동일성, 명목 설정 표적이 물리적 원인이라는 주장, 관측상 구별 불가능성의 사례별 입증, RCAEval 60건의 로컬 관측 품질, ops-lite 비일치 사례의 변환 중복 여부는 새로 확인하지 않았다. 이 한계들은 다음 평가 계약·자료 접근 범위를 정할 때 유지해야 한다.
