# 연구 타당성 압박평가: 현재 기여안은 보류, 근거 없는 설계는 폐기

판정일: 2026-10-12. 대상은 **단일 원인 서비스 진단**이며 정확도가 주목표다.
복구·응답시간 회복은 범위 밖이고, LLM은 필요성이 입증될 때만 쓰는 선택 요소다.
판정 기준은 [ADVERSARIAL_CRITERIA.md](ADVERSARIAL_CRITERIA.md)를 따른다.

## 1. 최종 판정

**현재 설계를 논문 방법으로 본격 추진할 근거는 부족하다: HOLD.**
“관계를 선별하고 작은 학습기/LLM으로 원인과 피해를 구분한다”는 설명만으로는
관측된 실패 원인, 그 실패를 고치는 기제, 선행연구 대비 기여 어느 것도 확립되지 않는다.
필수 LLM, 호출 방향의 인과 해석, 일반적인 선별·모듈 조합의 신규성 주장은 **DROP**한다.
다만 RCA 분야 전체를 폐기하거나 이 과제가 이미 해결됐다고 판정하는 것은 아니다.

현재 정당화되는 다음 행동은 **점수 포화·동점이 오순위를 얼마나 설명하는지 확인하는
작은 진단 검사**다. 이것은 새 방법 제안도, 출판 가능한 연구 주제의 확정도 아니다.
이 검사 후에도 중요한 실패가 남고, 관측 가능한 해결 단서와 다른 기제가 확인될 때만
방법 개발을 재개한다. 주제를 살리기 위해 다른 이름의 “새 연구”를 만들어 제시하지 않는다.

## 2. 중요한 배경과 실제 연구 문제를 분리한다

| 증명해야 할 층위 | 현재 근거 | 판정 |
|---|---|---|
| (a) 가치 있는 분야 | 연쇄 증상이 있는 서비스에서 원인을 찾는 RCA는 기존 연구의 실제 과제 | 배경 동기 KEEP |
| (b) 여기서 관측된 문제 | 고정 개발 자료에서 median-change의 원인 서비스 Top-1 실패 6건 | 국소 순위 실패는 확인 |
| (c) 문제를 해결하는 기제 | 실패 6건 모두 원인과 선두 후보가 상한 100에서 동점; 상한 제거 결과는 없음 | 포화·정렬 설명부터 검사; 해결 기제 미입증 |
| (d) 새로운 기여 | 방향 활용·가지치기·후보 축소·근거 카드·LLM 판단은 선행법과 겹침 | 특정 신규 기여 미확립 |

분야가 중요하다는 사실은 (b)의 실패 원인을 정하지 않고, 오답이 있다는 사실은
(c)의 LLM 필요성을 정하지 않는다. 개발 점수가 오르는 것만으로 (d)가 성립하지도 않는다.
현재 문제를 “피해 서비스의 강한 증상에 속는 인과 추론 실패”라고 부르면 증거를 앞선다.
정확한 표현은 **“알려진 시작 시각의 주입 장애 자료에서 나타난 포화 점수의 순위 불일치”**다.

원래 12건 특징·순위는 재사용 검증에서 일치했고 원래 결과를 바꾸지 않았다 [B2].
나머지 144건 telemetry는 보호되어 있으며 **자동으로 최종 시험군이 되는 것은 아니다** [P1].
본 판정 작성에서도 telemetry를 새로 열거나 새 실험을 실행하지 않았다.

## 4. 가장 강한 기각 논거

### A. 연구 난제가 아니라 점수 표현·동점 정렬 문제일 수 있다 — 치명적

median은 지표 변화량을 100에서 자르고 반올림한 뒤 서비스별 최댓값으로 순위를 만든다.
동점은 익명 서비스 ID 순서로 결정한다 [P1]. 실패 사례 원본의 점수·순위는 다음과 같다 [B3].

| 사례 | 원인 순위 | 원인 점수 | 100점 동점 후보 |
|---|---:|---:|---|
| `re2ob_checkoutservice_delay_1` | 3 | 100 | S04, S07, S11(root), S12 |
| `re2ob_checkoutservice_delay_2` | 3 | 100 | S03, S08, S10(root), S12 |
| `re2ob_checkoutservice_delay_3` | 3 | 100 | S01, S06, S08(root), S13 |
| `re2tt_ts-travel-service_delay_1` | 6 | 100 | S06, S13, S19, S43, S48, S49(root), S50, S65 |
| `re2tt_ts-travel-service_delay_3` | 3 | 100 | S07, S18, S25(root), S34, S40, S42, S46 |
| `re2tt_ts-train-service_mem_3` | 2 | 100 | S04, S15(root) |

독립 비판이 강조한 지연 5건에 더해, 사례 JSON 대조에서 mem 1건도 같은 상한 동점을 확인했다.
따라서 “비원인이 더 높은 이상점수를 받아 원인을 압도했다”는 설명은 이 저장 점수와 맞지 않는다.
그러나 **상한 제거가 정답을 회복한다는 결론도 아직 없다**. 실제 구분 신호가 부족할 수도 있다.
최소 해소 조건은 원래 결과를 보존한 별도 점검으로 잘리기 전 점수와 동점 민감도를 확인하는 것이다.
간단한 점수 처리 변경으로 오류가 사라지면 이 실패를 복잡한 진단기의 동기로 삼는 주장을 중단한다.

### B. 원인 정답이 있다고 피해·전파 정답까지 생기지 않는다 — 치명적

현재 정답은 root service다. 비원인의 순위나 지표 변화는 피해 역할의 검증이 아니다.
호출 caller→callee도 실제 장애 전파 방향과 같지 않다 [P1, P2, L1 §7].
**root-service 진단에는 edge-gold가 필요하지 않다.** 관계를 입력으로 쓰거나
root 정답으로 학습하는 것 자체를 기각하는 것이 아니라, 그것을 인과-edge 감독이라 부르는 것을 기각한다.
피해·전파의 인과 정확도를 따로 주장할 때만 그 주장에 맞는 독립 정답·개입 증거가 필요하다.
현재 과제는 root-service 정확도로 한정하고 피해 혼동을 확정 원인으로 서술하지 않는다.

### C. 복잡한 방법의 필요성과 LLM의 역할이 입증되지 않았다 — 높음

현재 LLM 조건은 1–2/12로, 수치 기준 11/12를 넘지 못했다 [S1].
이는 Qwen3:8b 고정 설정의 실패이지 모든 LLM의 불가능성 증명은 아니다 [P2].
반대로 그 실패를 “더 복잡한 추론이 필요하다”는 근거로 뒤집을 수도 없다.
입력에 정보가 없는 경우, 요약 중 손실된 경우, 있는 정보를 잘못 판독한 경우를 먼저 구별해야 한다.
LLM은 확인된 비LLM 실패에 필요한 처리 역할을 특정하고 동일 정보의 비LLM 대조보다
추가 정확도를 보일 때만 남긴다. 설명의 유창함·근거 인용·비용 감소만으로 정확도 목표를 대체하지 않는다.

### D. 선별·방향·학습기와 LLM의 결합만으로는 신규성이 없다 — 높음

검토된 출처에서 MicroHECL은 이상 연결 가지치기·역추적, EviRCA는 근거 카드와 방향 추론,
TopoEvo는 학습된 후보 위치 추정과 H-hop 부분그래프, EG-RCA는 규칙 기반 근거 선별을 다룬다 [L1].
따라서 “관련 관계만 남긴다”, “학습으로 후보를 좁힌다”, “LLM이 판단한다”는 넓은 기여는 폐기한다.
이는 모든 가능한 구체 기제가 선행연구와 같다는 증명이나 세계 최초성 검색의 완료가 아니다.
살리려면 다른 연산·학습 표적·가용 정보·실패 조건과 그 차이의 추가 효용을 명시해야 한다.
관련연구 문서 §8의 긍정적 방향 제시는 가설일 뿐, 현재 방법의 타당성 판정으로 승계하지 않는다.

### E. 개발 점수와 제한된 BARO 비교는 연구 우월성을 증명하지 않는다 — 높음

36건은 12개 반복 그룹이며 이미 본 smoke를 포함한다. 독립 시험·통계적 유의성 근거가 아니다.
median과 BARO 점수기는 전처리·정규화·집계가 함께 달라 점수식 하나의 효과로 분리할 수 없다 [P1].
10/36인 코드 정렬 재구현을 이겼다는 사실은 BARO 논문이나 최신 RCA 방법을 이겼다는 뜻이 아니다.
TORAI·EviRCA 전체 비교도 미실행이며, 더 강한 관련 기준점과 검증된 어댑터가 필요하다 [L1, B4].
알려진 주입 시각을 공통 제공한 것은 내부 비교 조건일 뿐 온라인 탐지·운영 타당성 증거가 아니다.

## 5. 아직 성립하지 않은 것

- 포화 전에도 원인이 비원인 서비스보다 불리한지, 포화 제거만으로 오류가 없어지는지.
- 오답 비원인이 실제 피해 서비스인지, 전파 방향을 맞혔는지, 인과 구분을 개선했는지.
- 새 학습기·관계 선택·LLM이 꼭 필요하며 각각 독립적인 정확도 이득을 주는지.
- 강한 관련 방법 대비 우월성, 독립 그룹 일반화, 운영·코드 결함에 대한 적용성.
- 최종 새 방법의 존재, 출판 가능한 신규성, 검증된 정확도 개선.

## 6. 정확한 범위 결정

| 대상 | 결정 | 유지·재개 또는 폐기의 의미 |
|---|---|---|
| RCA 배경, 단일 root-service 과제, 정확도 우선 | **KEEP** | 분야 동기와 평가 목표만 유지; 복구 실험은 추가하지 않음 |
| 고정 smoke와 개발 기준점 기록 | **KEEP** | 불리한 결과까지 보존; 시험 성능으로 재명명하지 않음 |
| 현재 문제 서술과 즉시 할 작업 | **REVISE** | 인과 혼동이 아니라 포화·동점 및 잔여 오순위의 진단으로 좁힘 |
| 특정 새 진단 방법·논문 기여로의 본격 진행 | **HOLD** | 아래 관문을 통과할 때만 재개; 대체 주제를 억지로 만들지 않음 |
| 일반적인 방향/선별/MLP+LLM 조합의 신규성 | **DROP** | 조합 자체는 기여로 인정하지 않음 |
| LLM 필수 채택 및 현재 LLM 파이프라인의 효능 주장 | **DROP** | 새로 확인된 역할·동일정보 정확도 이득 없이는 재도입하지 않음 |
| RCAEval 호출을 인과-edge gold로 해석하는 설계 | **DROP** | root-service 진단에 관계 입력을 쓰는 것까지 금지하지는 않음 |
| 원인-피해 혼동이 실패 원인이라는 가설 | **HOLD** | 별도 증거 전에는 관측 사실처럼 쓰지 않음 |
| BARO/SOTA 우월성·운영 일반화 주장 | **DROP** | 현재 결과의 범위를 넘는 주장 삭제 |

## 7. 판정을 바꿀 후속 검증: 세 관문, 앞에서 실패하면 뒤로 가지 않는다

**관문 1 — 실패가 남는가? 점수 표현·관측 가능성 진단**
- 개발 36건에 한해 cap 전·반올림 전 점수와 ID 동점 민감도를 점검하고, 오답 6건을 그룹별로 해석한다.
- 창·단위·결측·필터와 root 판별 정보의 존재도 함께 확인한다. 정답으로 tie-break를 정하지 않는다.
- **진행:** 단순 처리 문제를 배제해도 반복되는 실패가 남고, 입력에 구별 가능한 단서가 있다.
- **중단:** 단순 수정으로 실패가 해소되면 복잡한 방법 동기를 철회한다. 정보 부재라면 추론기 개발을 멈춘다.
- 이 검사는 진단이지 논문 방법이 아니다. 일부만 해소되면 남은 실패 범위로 주장도 축소한다.

**관문 2 — 필요한 연산이 있는가? 강한 대조와 기제 검사**
- 관문 1의 잔여 실패에서만 최소 처리 가설을 정하고, 무엇이 선행법과 다른지 명시한다.
- 수정된 단순 기준과 재현 가능한 관련 강한 기준점을 같은 입력·후보·시작 시각으로 비교한다.
- BARO는 원본/어댑터 검증 범위를 표시하고, 관계·다중관측·LLM 역할이 생길 때만 대응 비교기를 추가한다.
- **진행:** 필요한 정보와 연산이 특정되고 해당 연산을 제거하면 이득이 사라지는 개발 근거가 있다.
- **중단:** 강한 비LLM으로 충분하거나 조합 이외의 차이가 없으면 현재 기여안을 폐기한다.
- LLM은 그때 필요한 역할이 확인된 경우에만 동일정보 비LLM과 대조한다. 실패하면 LLM을 제외한다.

**관문 3 — 독립 조건에서도 남는가? 잠근 시험**
- 새 자료 평가 전에 시스템/원인/장애유형 반복 그룹 전체를 같은 분할에 두는 manifest를 고정한다.
- 개발 36건은 시험에서 제외한다. 보호된 144건은 분할·시험 잠금 전까지 열지 않는다.
- Top-1을 주지표로, 실용적 최소 개선폭·허용 악화폭·그룹 단위 paired 불확실성 기준을 사전 명시한다.
- 방법·어댑터·대조군을 고정해 독립 그룹에서 비교하고 Top-3, 실패 유형, 비용·시간도 함께 보고한다.
- **진행:** 강한 기준 대비 사전 정한 정확도 개선이 불확실성을 고려해 재현될 때 방법 기여를 다시 심사한다.
- **중단/보류:** 개선 미재현이면 현 방법 중단; 독립 그룹 부족으로 판별 불가능하면 HOLD를 유지한다.
- 시험을 보고 고친 결과를 같은 시험의 확증 결과로 보고하지 않는다. 통과해도 출판 가치를 자동 인정하지 않는다.
