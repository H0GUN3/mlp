# Dataset compatibility inventory

## Evidence

- **Local RCAEval RE2:** The metadata summary records 180 acquired cases (90 RE2-OB, 90 RE2-TT), all with paired metrics and 178 fully paired across modalities; two TT cases have incomplete modalities and one lacks logs. Twelve have all-null metric columns. It records 60 repeat groups, no identical telemetry cases, 540 decoded parquet files, and no absent-root traces. This is an acquired subset, not the entire RCAEval catalog. The split manifest gives a service-level root and fault kind, with repetition indices; its train/validation/test partitions hold out some service/fault/repetition combinations, but repetitions are not independent systems or fault mechanisms.
- **Local ops-lite:** README “Composition,” “Data layout,” “label.json,” and “How the ground truth was built” describe OpenRCA 2.0 as 455 fault-injection instances across TrainTicket, Hotel Reservation, and OpenTelemetry Demo. Ten normal/abnormal parquet inputs per case cover traces, metrics, metric histograms, metric sums, and logs. Labels are injected-fault entries with service, chaos type, and `required`/`optional`/`not_effective` role, plus service propagation edges. README states Chaos Mesh injections and a telemetry-checked propagation procedure; this is distributor-stated provenance, not independently verified causal truth or production-incident provenance. The local summary confirms 455 labels, 473 required fault entries (not distinct services/incidents), 77 not-effective, 81 optional, and 437 process-level cases. Only 30 cases’ telemetry are held locally (10 per system); sample audit confirms ten parquet files per sampled case. No identical acquired telemetry cases; some individual log files are identical. The observed required-root visibility in the 30-case sample does not establish full-dataset quality.
- **Named catalogs:** RCAEval’s Hugging Face README “Datasets” table and “Layout” distinguish RE1 metric-only from RE2 multimodal; RE2-OB has metrics/logs/traces, RE2-TT metrics/logs/traces, and the case index labels root service, fault and repetition. The catalog lists 735 cases overall; RE2 cases use three repetitions per service/fault pair. Local RE2-OB/TT must not be confused with Eadro TT: Eadro paper’s SN means SocialNetwork, while TT is TrainTicket. Locally, “180” is 90 OB + 90 TT, not an Eadro TT180 dataset.
- **Eadro:** Zenodo record 7615394, metadata/description and file list, is open access and offers `SN Dataset.zip` and `TT Dataset.zip` (about 78.8 MB and 48.9 MB). The record names the Eadro ICSE 2023 paper; the paper identifies SN as SocialNetwork and TT as TrainTicket and uses metrics, logs, and traces. These are downloadable archives, not a locally inspected/preprocessed corpus.
- **GAIA MicroSS:** GAIA README “Quick start,” “MicroSS,” and “Data layout” describe a QR-code login business-simulation system with metrics, traces, business logs, and run/system/injection records. It is distinct from Online Boutique and from RCAEval. The README reports two weeks of continuous data, later adding one month of August 2021 while omitting similar-pattern traces. Do not infer complete traces for every period/case.
- **DeepHunt:** README “Dataset” and “Demo” says D1 is a simulated e-commerce microservice deployment under real traffic; failures are replayed from real system failures, labeled to root-cause instances. Public repository `data/` lists preprocessed D1.zip and D2.zip. Samples encode graph plus node features from pod metrics, traces, logs, and node metrics; `cases.csv` includes injection time, failure level, root cause, and type. D2 is described as a commercial bank dataset unavailable due to NDA. Do not confuse DeepHunt D1 with DiagFusion D1; these are distinct dataset names/protocols.

## Answer

**Local RCAEval RE2-OB/TT supports the existing adapted experiment, not faithful reproduction of the original DiagMLP paper.** Its acquisition, quality checks and fixed split are established locally. For original-paper reproduction, select a matching paper backbone and its dataset: for example Eadro plus DiagMLP on Eadro SN/TT, or the corresponding TVDiag/DeepHunt configuration on its own data. The presence of local RCAEval metadata does not make RCAEval equivalent to those original data. On RCAEval, two incomplete-modality cases, one missing-log case and 12 all-null-metric cases require consistent handling.

**Ops-lite is a multimodal transfer test**, but it differs materially: three systems, process/edge labels, possible multiple injected faults and role semantics, and only 30 acquired telemetry cases versus metadata for 455. Its Chaos Mesh provenance is stated by the distributor, not independently established. It should test transfer only after defining a compatible target (e.g., required root services) and a leakage-safe, case-grouped protocol; its labels are not automatically equivalent to single-root RCAEval labels.

Other named catalogs can inform transfer/access planning, not serve as interchangeable replicas: Eadro is the closest additional multimodal system set but needs archive inspection and protocol mapping; DeepHunt D1 has preprocessed multimodal features and different replayed-failure labels; GAIA MicroSS is a separate simulated QR-login system with different data organization and anomaly records. No single catalog can be treated as equivalent merely because it has the same modality names.

## Unknown

- Whether the anonymous 455-case candidate matches the official OpenRCA 2.0 paper's 500-case release remains unconfirmed. This is different from local subset membership: the lead checked all 30 names in `evidence/ops-lite-sample.json` against the 455 records in `data/ops-lite/manifest.jsonl`; all 30 are present, with no missing name. This does not establish official-paper identity.
- Whether local RCAEval adaptations, preprocessing, feature selection, and exclusions exactly match DiagMLP’s original three backbones and paper protocol. Do not describe an adapted local model as the original-paper reproduction.
- Whether Eadro archives’ actual contents and splits match the paper’s detailed protocol; archives were not downloaded or inspected.
- Exact operational/production-vs-injected status beyond each distributor’s stated provenance; no independent validation was performed.
- Cross-dataset mapping of service identities, fault taxonomies, repeat dependence, missing-modality handling, and label granularity requires a prespecified protocol.
