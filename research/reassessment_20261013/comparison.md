# Comparison audit

## Evidence

**Standard.** A method-stage comparison is eligible as an original-method competitor only when the original method’s input representation/preprocessing, model-stage design, objective/task heads, candidate semantics, and selection/training protocol are preserved or faithfully reproduced. Shared labels/evaluation alone do not establish this.

**DiagMLP — adapted-component test, not an original-method competitor.** The paper defines DiagMLP as an ablation replacing GNN modules while preserving preprocessing, embeddings, downstream task modules, and training strategy (Sections III-C–D and IV, especially IV-A; Table IV reports localization). The local `DiagMLPCommonInput` reproduces the positional/modal/node fusion shape, but feeds it a single engineered 17-feature vector rather than separate metric/log/trace embeddings; it therefore has no original modality encoders. It uses local position width 32, dropout 0.1, and a root-service linear head rather than the paper’s surrounding task module. The local objective is root-service cross-entropy, not the paper’s framework-specific detection/localization/classification tasks. The fixed candidate vocabulary uses service identities and masks absent services; this is not a service-identity-generalization test. Locally both systems use train-only standardization/vocabulary, 80-epoch maximum, three seeds, and validation-cross-entropy checkpoint selection (`PROTOCOL.md`, “Common input” and “Training/selection/evaluation”; `mlp_readiness.py`, `run`/`train_one`). These establish a useful common-input architecture reference, not an original-paper comparison.

**EadroGAT — remove from the main original-method competition table.** Yes: retain it only as an explicitly labeled common-input architectural ablation (or engineering evidence), not as “Eadro.” The primary paper describes a multimodal end-to-end framework: event-occurrence/Hawkes log encoding, temporal KPI and trace encoders, gated fusion, historical-invocation graph modeling, and joint anomaly detection plus root localization (Sections IV-A–C). The local adapter retains the author `GraphModel` but replaces those encoders/fusion with the same engineered 17-vector as DiagMLP, replaces the joint detector/localizer with a local root-classification head and common cross-entropy objective, and uses externally supplied observed-call edges. Local graph widths are `[32,32]` rather than the original code constructor’s `[64,128]`; attention uses four heads and local dropout 0.1 (`MODEL_PROVENANCE.md`, “Eadro”; `mlp_reference.py`, `EadroGATCommonInput`). It thus tests a borrowed graph component under a different task/data pipeline, not Eadro’s published method. Equal local data, objective, seeds, and validation rule make it informative as an architecture ablation, but do not turn it into original-method competition.

**BARO signed score path — adapted score-path evidence, not BARO competition.** The BARO paper is metric-only and defines an end-to-end pipeline: Multivariate BOCPD detects the first change point, then RobustScorer ranks metric deviations using absolute deviation from the normal median scaled by IQR (Sections 3.2–3.4, Algorithm 1, Eqs. 3–4). The local score-path run instead uses a known injection-time normal/fault mask and skips BOCPD; its signed variant takes the maximum *signed* normalized change, then deduplicates metric ranks into services. Local preprocessing/filtering is applied (`scripts/baseline_dev.py`, `baro_preprocess`, `baro_rank`); it is not the complete original detector/scorer pipeline. Candidate inventory and rank evaluator are shared, with no tuning, but onset information and scoring rule differ (`baro_validation.json`: `method`, `policy`, `tuning_performed`, `final_test_accesses`). Retain only as explicitly controlled score-path ablation/engineering evidence, not as an original BARO competitor.

**Prior.** The train-root-frequency prior is properly retained as a simple control under the common candidate/evaluation protocol (`verification.json`, `prior_validation`); it is not a method competitor.

**Numeric evidence checked.** The local model widths and training budget above are from `PROTOCOL.md` (“Training/selection/evaluation”) and `MODEL_PROVENANCE.md` (“DiagMLP”/“Eadro”); local parameter counts, where needed, are in `verification.json`, each `comparison[].parameters` keyed by `method` and `system`. BARO’s source commit is in `baro_validation.json`, `source_commit`; this commit’s README-only change does not alter the algorithm, so the primary method description is cited below instead.

## Answer

**Remove the Eadro adaptation from the main method-competition table. Apply the same eligibility standard to all adaptations:** none of DiagMLP common-input, EadroGAT common-input, or BARO signed score path currently qualifies as an original-method competitor. DiagMLP and Eadro can remain together in a clearly titled *controlled common-input model-stage ablation*; BARO can remain only as an explicitly adapted score-path baseline. The prior remains a control. Do not compare or claim numerical superiority across these different protocols; all local neural and BARO results are validation results, and validation selected checkpoints for the neural runs (`verification.json`, `checks` includes `validation_only_epoch_selection`; `baro_validation.json`, `summary`).

**Minimum fair corrective design (model-stage question only).** Hold constant the same original benchmark examples/split, observed inputs and feature construction, candidate inventory/mask, label handling, downstream task heads/objective, evaluation, and comparable tuning/selection budget. For each framework, first reproduce its original preprocessing and modality-specific encoders; then swap only the graph/modeling stage under test (e.g., original GNN versus DiagMLP), preserving the framework’s fusion interface and detection/localization heads and joint objective. Keep train/validation/test partitions and all model-selection decisions identical and validation-only. If the aim is specifically to compare learned root-ranking stages under a new common representation instead, label every row an adapted-component ablation and do not present it as original-method competition.

## Unknown

- Whether the original Eadro and DiagMLP pipelines can be reproduced faithfully on the local RE2 data, which may not provide the original methods’ required event/log inputs, temporal windows, labels, or benchmark protocol. The named local artifacts do not establish this.
- Whether parameter- or compute-matched tuning would change the adapted ablation; the current protocol explicitly says it is not model-specific tuning/optimization.
- Whether the local BARO preprocessing and score-path implementation match all details of the pinned upstream source beyond the checked local adaptation description. The score path has no locally executed original BOCPD pipeline.
- No original-method reproduction or cross-protocol performance ordering is established here.
