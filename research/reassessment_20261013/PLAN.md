# 다섯 질문에 대한 재검토 계획

## 요청과 범위

1. 네 비교 방법의 선택 이유와 논문 설명. prior는 논문 방법이 아닌 대조 규칙임을 명시.
2. 보유 데이터와 관련 연구 데이터 재탐색. 시스템 이름, 데이터 릴리스, 표본 단위를 구분.
3. DiagMLP 한계와 원 논문 수치 대비 판단. 원형/변형/가설을 구분.
4. 변형 Eadro의 직접 비교 자격. 같은 원칙을 다른 변형에도 적용.
5. 학습 자료 및 smoke의 충분성. 실행 확인과 최종 성능 예측을 구분.

기존 코드/분할/학습결과는 읽기 전용이다. 최종시험 raw/특징/예측 열람,
새 모델 학습, 대용량 다운로드를 하지 않는다.
새 결과는 이 디렉터리에만 작성한다.

## 구성과 순서

### 근거 재점검 DAG

동시 수집6개 → 근거 검증1개. 실행 슬롯의 기본 제한을 따르며 초과분은 대기한다.

- paper_diag: quick. 정해진 한 논문의 방법/데이터/표 수치와 판본을 추출.
- paper_eadro: quick. 정해진 한 논문의 과제/방법/데이터를 추출.
- paper_baro: quick. 정해진 한 논문의 점수/데이터와 실제 구현 경계를 추출.
- data_catalog: quick. 명시한 metadata와 자료 안내에서 목록/숫자/가용성을 추출.
- comparison: unspecified-low. 몇 개의 원 코드/변형을 대조해 직접 비교 자격을 판단.
- adequacy: unspecified-low. 반복그룹/표본수/학습 이력을 함께 읽어 충분성을 판단.
- evidence_check: unspecified-low, 앞선6개에 의존. 출처/로컬 수치와 보고서 주장을 대조.

작업별 보고서 경로를 분리한다. 각 보고서는 사실·해석·미확인 항목을 분리하고,
최대 약1000단어로 제한한다. 넓은 분야 전체의 문헌 수집이 아니라 이 다섯 질문의
검증이므로 관련 없는 분야로 확대하지 않는다.

### 연구 방향 판단

주 에이전트가 검증된 보고서를 읽고 DiagMLP 약점과 점수 비교 가능성을 판단한다.
원형 한계와 우리 변형의 실패를 섞지 않는다. 기존 결과로 확인되지 않은 것은 가설로 쓴다.
다섯 질문 순서의 쉬운 한국어 답변 초안을 만든다.

### 최종 검증 DAG

수치/출처 확인, 비교 논리/쉬운 표현 확인 → 최종 검증 기록.
앞 단계에서 확인된 오류만 수정한다. 원 자료나 실험 결과를 고치지 않는다.

## 성공 기준

- 다섯 질문에 모두 직접 답한다.
- 논문의 수치는 판본·데이터·표본 단위·평가 조건과 함께 제시한다.
- 다른 데이터의 점수를 비교해 “원 논문보다 좋아졌다”고 주장하지 않는다.
- 실행용 smoke 성공을 최종 성능의 신뢰성으로 확대하지 않는다.
- 변형 방법의 직접 비교 자격에 같은 기준을 적용한다.
- 읽는 사람이 전문용어 없이도 결론과 근거를 이해할 수 있다.
