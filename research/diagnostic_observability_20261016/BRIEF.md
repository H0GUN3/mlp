# 원인 구별 관측과 교정 평가

## 요청과 범위
사용자15개 항목 및 마지막6개 감사 조건을 조사한다.
목표는 같은 시스템에서 학습에 포함되지 않은 장애 사건의 원인 서비스를 진단하는 것.
탐지·장애 예측·새 고장 종류 발견·LLM 도입을 자동으로 목표에 추가하지 않는다.
필드 존재, 실제 관측 가능성, 구별 단서, 인과적 확정을 따로 보고한다.

## 작업 순서
1. 기존 코드와 전수 검사를 재사용해 관측/라벨/후보/시간 계약을 확인한다.
2. 원문4편의 입력·분할·학습·지표를 대조한다.
3. RCABench를 단일 archive 순회로 필요한 열만 감사한다.
   기존 metadata에서 성능과 무관하게 사례를 고르고, 선택 이유/분모를 먼저 고정한다.
   HTTP796건의 필드·관측 가능성은 전수, 세부 request/로그 대조는 명시한 사례 표본.
4. 허용된 SN/TT 개발 관측에서 기존 trace 감사와 실제18특징 정보 손실을 대조한다.
5. 현재 입력에서 확인된 DiagMLP/Eadro의 한계와 미확인 가설을 구분한다.
6. 데이터·앞단·분할의 교정 평가 계약을 정한다. 선택이 실행을 바꾸면 근거와 함께 질문한다.
7. 요청된 교정 평가는 실제 실행 결과 또는 명시적인 사용자 보류 결정이 있어야 종료한다.

## 읽기·쓰기 경계
- RCABench 기존 archive 관측을 읽는 감사는 이번 요청 범위다.
- SN/TT의 이미 허용된 개발 자료만 사용한다. 봉인된 native/RCAEval 최종 관측은 열지 않는다.
- 기존 자료·코드·분할·모델·결과를 수정하지 않는다.
- 새 코드/결과는 이 폴더에만 생성한다. 다운로드·설치·프로젝트 commit 없음.
- 출력 파일은 독점 생성, 원자료 hash/사례 목록/검사 범위를 기록한다.

## 책임과 산출물
- 주 담당: 실제 자료 감사, 최소 코드와 검사, 교정 평가 및 한국어 최종 보고서.
- 독립 문헌 축: Eadro/DiagMLP의 입력/분할/핵심 보존.
- 독립 문헌 축: TVDiag/DeepHunt/GraphRAG의 그래프 용도와 지표.
- 간단한 도식은 보고서의 텍스트 도식으로 충분하다. 별도 UI/시각화 프로젝트를 만들지 않는다.

이는 현재 요청의 범위에 대한 해석이며, 문헌 조사 두 축만 독립적으로 분담한다.
