# 선행조건 실제 확인 결과

## 결론

**실행 가능한 문헌 기반 비교 모듈, 공통 평가기, 그룹 분할을 확보했고,
실제 학습 12회와 저장 모델 재검증 12회를 완료했다.**
다만 이 결과는 공통입력 변형의 검증 성능이며, 원 논문 전체 파이프라인의 재현이나
최종 시험 성능은 아니다. 제안 방법 자체는 아직 학습하지 않았다.

공통입력 수준의 후속 비교 실험은 진행 가능하다.
원 방법 전체 대비 우수성/SOTA 주장을 위한 조건은 아직 충족되지 않았다.

## 1. 실제 결과

동일 검증 자료를 사용했다. OB/TT 각각 18사고 = 6조건 그룹 × 반복3회다.
신경망은 seed11/23/37 평균이다. 세 번의 학습을 독립적인 54개 사고처럼 세지 않는다.
표의 성적은 checkpoint 선택에 사용한 **validation** 결과다.

BARO는 기존 검수된 `baseline_dev.py::baro_rank(..., "signed")`를 튜닝 없이 재사용했다.
공식 commit `582d4ead3d3301a34fea4e395bfa3f750fc9a40d`의 점수 경로에 맞춘
NumPy 재구현이지 원 패키지/BOCPD 전체 실행이 아니다. 자체 전처리를 유지했고
같은 서비스 후보·사고·동점 처리로 채점했다. 원인 점수가 누락된 사례는 0/36건이다.
기존 개발36건의 성적을 이번 검증36건의 성적과 직접 섞지 않았다.

### 실제 학습 여부

| 시스템 | 방법 | 파라미터 수 | 평균 학습 손실: 초기 → 80epoch |
|---|---|---:|---:|
| OB | DiagMLP 공통입력 | 18,095 | 2.654 → 0.319 |
| OB | Eadro GAT 공통입력 | 13,840 | 2.611 → 0.662 |
| TT | DiagMLP 공통입력 | 76,901 | 4.381 → 1.123 |
| TT | Eadro GAT 공통입력 | 15,622 | 4.465 → 0.964 |

전체 12회에서 학습 손실이 감소했다. 선택 epoch는 validation loss만으로 결정했고,
저장한 checkpoint를 새 모델에 로딩해 검증 예측이 일치함을 확인했다.
TT GAT의 선택 epoch는 60/55/47이며, 가장 마지막 epoch를 무조건 채택하지 않았다.
DiagMLP는 여섯 실행 모두 80epoch가 선택됐다. 충분히 수렴했다고 단정하지 않는다.

## 2. 세 선행조건의 확인 범위

| 조건 | 실제 증거 | 판정 |
|---|---|---|
| 비교 모델 구현·입출력 | DiagMLP 원문 식의 구조 재구현, 원 Eadro GraphModel byte 일치 확인, N=2/5 합성 forward/backward, 실제 OB/TT 학습 | 공통입력 모듈 수준 통과 |
| 공통 평가·선택 | 평가기/분할/입력 경계 10개 테스트, validation-only 선택, 12개 checkpoint 재생, 별도 순위 계산과 지표 일치 | 통과 |
| 반복 그룹 분할·자료 경계 | train108/validation36/test36, 60개 그룹 보존, 기존 개발36은 train에만 배치, 이번 최종시험 raw 접근0 | 통과 |
| 원 논문 전체 방법/성능 재현 | 원 전처리·임베딩·원 데이터·원 실험 수치까지 재현하지 않음 | 미완료 |

각 시스템의 분할은 54/18/18이다. 모든 분할에 원인 서비스5종과 장애6종을 포함한다.
그룹 배치는 metadata만 사용해 고정했고, 학습 점수로 분할을 골라 바꾸지 않았다.
최종시험36건의 관측자료는 이번 실행에서 읽거나 채점하지 않았다.

## 3. 실행하면서 실제로 드러난 문제

### 원본 공개 코드가 바로 실행되지는 않았다

고정한 원 Eadro 전체 `MainModel`은 `trace_dropout` 미정의로 생성 중 실패했다.
이 사실을 가리지 않고 원본을 그대로 보존했다. 공개 수정 fork를 별도로 확보해,
메트릭·로그·트레이스 입력에서 전체 forward/backward와 입력/모듈별 유한·비영
gradient를 확인했다.

이 성공도 합성 실행 확인이다. 수정 fork의 전처리와 원 데이터에서 논문 정확도를
재현했다는 뜻은 아니다. 실제 학습에는 정상 동작을 확인한 원 GraphModel을
공통 특징에 연결한 변형을 사용했다.

### 검증 자료에 서비스가 아닌 식별자가 섞여 있었다

첫 학습 명령은 모델 생성 전에 후보 어휘 검사로 중단됐다.
`InboundPassthroughClusterIpv4`, `PassthroughCluster`가 원인이었다.
Istio 공식 정의에서 Envoy 내부 가상 클러스터임을 확인하고, 명시적인 내부 이름4개만
모든 방법에 동일하게 제외했다. 새로운 실제 서비스는 계속 오류 처리한다.

최종 제외는 검증의 OB checkout CPU 반복2 사례에서 위 두 이름뿐이었다.
사고 자체는 제외하지 않았다. 원 특징·분할은 유지하고 계약 hash를 결과에 남겼다.
상세 근거와 회귀 검사는 `CANDIDATE_CONTRACT.md`에 있다.

### 환경 및 실행 제한도 확인했다

DGL의 미선언 packaging 의존성을 격리 환경에 추가했다.
특징 추출은 첫 실행에서 시간 제한으로 중단됐고, 사례별 cache를 추가해 완료했다.
새 Pyright 프로세스의 정적 검사는 0 errors/0 warnings였다.
기존 언어 서버 세션의 환경 캐시 문제는 `EXECUTION_NOTES.md`에 구분해 기록했다.

## 4. 결과를 어떻게 해석해야 하는가

### 확인된 것

1. 기준점이 단순 stub가 아니다. 실제 관측을 읽고 학습·선택·예측·저장·재로딩·채점했다.
2. 이 설정의 기존 DiagMLP 계열 기준점은 단순 원인 빈도보다 높다.
3. OB에서 BARO의 Top-3는 17/18이지만 Top-1은 4/18이다.
   이 점수 경로에서는 원인을 완전히 누락하는 문제보다 1위 우선순위에 어려움이 있다.
   이를 인과적인 원인/피해 서비스 혼동으로 확정하지는 않는다.
4. 그 어려움을 기존 DiagMLP 계열이 이미 상당 부분 해결한다.
   새 방법은 약한 로컬 MLP나 BARO만 이기는 것으로 기여를 주장할 수 없다.
5. TT에서는 BARO도 13/18을 맞힌다. DiagMLP의 평균81.5%만으로
   안정적인 우월성을 주장할 수 없다. seed 범위는72.2–94.4%다.

### 아직 말하면 안 되는 것

- “제안 방법이 기존 방법보다 우수하다”: 제안 방법을 넣지 않았다.
- “DiagMLP 원 논문을 재현했다”: 수치 요약 입력으로 바꾼 구조 재구현이다.
- “Eadro 전체보다 MLP가 낫다”: 원래 로그/시계열 인코더와 공동 학습을 공통입력판에서
  제거했다. 정보 표현·학습 설정이 달라졌다.
- “같은 hidden32이므로 공정한 모델 용량 비교다”: TT에서는 파라미터 수가
  76,901 대15,622로 다르고, DiagMLP는 명시적 위치 임베딩을 사용한다.
- “검증 정확도가 최종 성능이다”: validation으로 checkpoint를 선택했고,
  시스템별 독립 조건은6개뿐이다.

**따라서 낮은 GAT 성적을 그대로 제안 방법에 유리한 경쟁 기준으로 삼아서는 안 된다.**
논문 경쟁력 비교에는 원 전처리/임베딩을 유지한 방법 비교와 적절한 튜닝·정보 접근
통제가 필요하다. 현재 준비된 공통입력 경로는 구성요소 효과를 확인하는 경로다.

## 5. 확인 가능한 파일

- 실행·재검증 명령: `README.md`
- 모델 원형/변형/해시: `MODEL_PROVENANCE.md`, `model_checks.json`
- 분할: `split.json`, `split.lock.json`
- 원자료 접근 및 특징: `features.json`
- 학습 이력·선택 epoch·예측: `training_results.json`
- 12개 실제 모델 상태: `checkpoints/`
- 재로딩·별도 채점·요약: `verification.json`
- 동일 검증셋 BARO: `baro_validation.json`

재검증도 기존 결과를 덮어쓰지 않고 동일성을 확인했다.
원본 데이터와 기존 연구 결과는 수정하지 않았다.
