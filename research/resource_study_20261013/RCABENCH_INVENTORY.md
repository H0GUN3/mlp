# RCABench 1차 사건 인벤토리 도구

**후속 실행 상태:** 2026-10-14 공식 MD5를 확인하고 실제 아카이브의
메타데이터 인벤토리를 완료했다. 1,422사례 중 단일 항목 정답 369개,
복수 항목 정답 1,053개다. 관측 품질·독립 유효 사건 수의 판정은 아니다.
결과는 `../rcabench_assessment_20261013/metadata_inventory.json`에 있다.

아래는 도구를 준비할 당시의 계약과 합성 검사 기록이다.
사용자의 다운로드/검수 범위 결정 전에는 아래 실제 자료 명령을 실행하지 않는다.
후속 선택에서 `실제 사건 수 확인`을 선택하여 RCABench 확보·검수 범위는 결정됐다.
다운로드 완료·체크섬 확인 후 위 실제 집계를 수행했다.

## 입력과 출력

`rcabench_inventory.py`는 이미 확보한 로컬 아카이브만 인자로 받는다.
네트워크 요청·압축 파일 추출·기존 파일 수정·학습·분할 기능은 없다.
공식 Zenodo의13,444,974,981B 및 MD5를 먼저 검사한 뒤, gzip tar를 순차적으로 읽는다.
압축 데이터는 해제 스트림으로 통과하지만 관측행은 파싱하지 않는다.
메모리에 읽는 본문은 사례별 `injection.json`, `env.json`뿐이다.
성공 시 JSON을 stdout으로 출력하며 실패 시 종료코드1로 끝낸다.
`--report NEW_PATH`를 지정하면 새 JSON 보고서를 생성하며 기존 파일은 덮어쓰지 않는다.

출력은 다음을 구분한다.

1. 사례 디렉터리 수.
2. 단일/복수 서비스 정답 목록이 있는 사례 수.
3. 정상·이상 metric/trace 파일 및 두 JSON이 존재하고 비어 있지 않으며,
   JSON 정답과 초 단위 시각이 해석되는 **metadata 관문 통과 수**.
4. 정답·시각·고장 유형이 같은 사례 그룹: 중복 가능성 검토용이며 자동 병합하지 않는다.
5. **독립적으로 사용 가능한 사건 수: `null`(미검증).**

`metadata_candidates_not_deduplicated`를 검증된 사건 수로 인용하지 않는다.
일부 네트워크 고장의 변환 코드가 만드는 양쪽 서비스 정답과 injection 정답의
대조, Parquet schema/행 수/시간 coverage, 기존7개 메트릭 대응,
trace 연결/시간 품질, 수집 세션 독립성은 별도 실제 자료 검수 단계다.

## 오류 처리와 범위

- 공식 export 코드의 `사례명/파일명` 구조를 전제로 한다. 다른 구조면 중단한다.
- 경로 이탈·중복 파일명·링크·특수 파일을 거부하고 임의로 보정하지 않는다.
- JSON은 파일당2MiB, 전체 tar 항목은100,000개 상한이다.
- JSON 중복 키, 잘못된 정답, 중복 정답, 빈/겹치는 구간은 제외 이유로 남긴다.
- 자료 구조가 다르면 관문을 완화해 통과시키지 않고 실제 배포 구조를 먼저 검토한다.
- 체크섬 검사는 압축파일1회, 목록 검사는 다시1회 읽으므로 디스크 읽기는2회다.
  해제 파일 전체를 디스크에 저장하지 않는다.

## 실행

```text
python3 -B research/resource_study_20261013/rcabench_inventory.py LOCAL_ARCHIVE.tar.gz
```

실제 자료 없이 검수 로직만 확인하는 명령:

```text
cd research/resource_study_20261013
python3 -B -m unittest -v test_rcabench_inventory
```

테스트 fixture의 Parquet 이름 파일은 일부러 유효한 Parquet가 아니다.
파일 존재 검사가 실제 관측 품질 검증으로 잘못 표시되지 않는지 함께 확인한다.
보고서 저장 검사는 임시 폴더의 합성 자료만 사용하며 실제 관측자료에 접근하지 않는다.

## 검증 결과

- 합성 아카이브 테스트6개 통과: 단일/복수/누락 정답·파일, 동일 metadata 그룹,
  잘못된/겹치는 구간, JSON 오류·크기 제한, 중복/위험 경로·링크, 빈/잘못된 gzip.
- 보고서 생성 및 기존 보고서 덮어쓰기 거부도 합성 임시 파일로 검증했다.
- 테스트 명령 종료코드0, `Ran 6 tests in 0.087s`, `OK`.
- 두 Python 파일 LSP 진단 없음.
- CLI 도움말 정상, `/dev/null` 입력은 크기/체크섬 불일치로 종료코드1,
  stdout 보고서 없이 거부됨을 별도로 확인했다.
- 후속 실제 실행은 exit0으로 완료됐으며 사례 수는 상단에 기록했다.
  실행시간·peak RAM을 계측한 비용 실험이나 관측 품질 검증 결과로 확대하지 않는다.
