# 비용–정확도 평가 설계안 v1 — 미동결, 실행하지 않음

**현재 상태:** 사용자의 통합 피드백에 따라 사건 단위 평가→성능 개선→A/B 주장 검증의
공통 측정 기준으로 사용한다. 성능이 낮다는 이유로 별도 '경량' 주장으로 옮기지 않는다.
데이터 선정 논의가 우선이며 새 다운로드·전처리·분할·학습은 보류한다.
후속 선택으로 RCABench 확보·적합성 검수만 허용됐으며 현재 후순위 백그라운드다.
이는 이 문서의 비용 실험이나 기존 개발 자료 처리의 재개가 아니다.
아래 시간 한도와 허용 차이는 연구용 제안값으로, 운영 SLA나 사용자 승인값이 아니다.
자료와 측정 환경을 선정한 뒤, 새 성능 결과를 보기 전에 최종 동결해야 한다.

## 표현과 핵심 질문

현재 모델은 파라미터3,457개의 비교적 작은 MLP다. '경량', '고효율', '비용 우위'는
아직 확인된 결과가 아니다. MLP라는 모델 이름이나 파라미터 수만으로 판단하지 않는다.
정확도와 비용의 교환 관계를 같은 조건에서 보여주는 것이 목적이며,
모든 큰 그래프 모델의 정확도를 능가하는 것을 필수 목표로 두지 않는다.

## 공통 정보와 역할

과제는 **장애 구간이 주어진 상태에서 원인 서비스1개를 순위화**하는 것이다.
동일 사건·후보·정답·관측 시간·훈련/검증 분할을 사용한다.
전체 방법 비교에서는 각 방법의 고유 전처리를 보존하고 사용 모달리티를 표시한다.
같은 특징의 모델 구조 비교는 별도 표로 구분한다. 축소/변형한 문헌 모델을
원 논문 방법 또는 원 논문 점수 재현으로 부르지 않는다.

가까운 공개 MLP/RCA 방법과 비학습 수치 방법을 주 비교 후보로 삼는다.
자체 로컬 MLP는 내부 대조군이며 문헌 경쟁자를 대체하지 않는다.
더 큰 DiagMLP 복원본/Eadro 등은 성능 좌표로 남긴다.
같은 규모의 실제 문헌 방법이 부족하면 그 사실을 밝히고 일반 구조 대조군을
새로운 RCA 선행연구인 것처럼 소개하지 않는다.

## 측정 환경

기본 연구용 측정은 같은 호스트의 CPU, 최대2개 계산 스레드, GPU 없음이다.
프로세스별 CPU time과 wall time, BLAS/OMP 설정, RAM, OS, 라이브러리,
동시 실행 여부를 기록한다. 서로 경쟁하는 측정 작업은 병렬로 실행하지 않는다.
이는 운영 장비/SLA가 확정됐다는 뜻이 아니며 다른 환경으로 일반화하지 않는다.

| 항목 | 측정 경계 |
|---|---|
| 초기 준비 | 읽기/정렬, 정상 참조·어휘 학습, 학습용 특징 생성 |
| 모델 학습 | 초기화부터 선택된 모델을 확정할 때까지; 검증/선택 시간 포함 |
| 온라인 전처리 | 이미 허용된 정상 참조를 이용해 새로운10초 관측을 입력으로 변환 |
| 추론 | 입력 텐서 준비 뒤 점수/순위를 반환할 때까지 |
| 전체 진단 | 온라인 전처리+추론; cold load와 resident/warm 실행을 별도 표시 |
| 메모리 | 절대 peak RSS와 로딩 전 대비 증가분; 가중치 바이트와 혼동하지 않음 |
| 반복 측정 | 같은 개발 사건 순서로 충분히 반복, warm-up 횟수 명시; median/p95 보고 |

파라미터 수·저장 파일 크기·peak RAM은 각각 보고한다.
단계별 측정은 공통 데이터 파싱 비용을 숨기거나 이중 계산하지 않아야 한다.
원자료 입력 비교와 이미 캐시된 특징 입력 비교를 한 표에 섞지 않는다.
실패/초과 시간은 점수0으로 바꾸지 않고 timeout/infeasible로 표시한다.

## A. 동일 계산 예산에서의 정확도

연구용 pilot 예산 후보는2 CPU threads에서30/120/600 wall-seconds의3지점이다.
이 값은 운영 목표가 아니라 비교 곡선의 초안이다. 아직 채택된 실행 한도가 아니다.
두 종류를 구분한다:

1. **총 준비 예산:** 필요한 자료 의존 전처리+학습+검증/선택을 모두 포함.
2. **모델 예산:** 이미 각각의 특징이 준비됐을 때의 학습+검증/선택.
   특징을 만드는 비용은 별도 표시하며 총 준비 예산과 혼동하지 않는다.

동일 예산의 결과와 함께 각 방법의 권장 설정을 끝까지 실행한 성능/비용 좌표도
남긴다. 시간 제한에 걸린 원형을 완전 수렴한 원형이라고 하지 않는다.
예산별 별도 튜닝 횟수/총 계산비를 기록하고 우리 방법에만 추가 기회를 주지 않는다.
순위는 정확도–비용 곡선으로 보고하며 유리한 예산점 하나만 골라 주장하지 않는다.

## B. 비슷한 정확도에서 시간/메모리 비교

사전 비교 허용 폭의 제안은 주 분석2 percentage points, 보조 분석5 percentage points다.
이는 연구상 제안한 차이 폭이지 운영 허용 손실의 합의가 아니다.
평균 차이만으로 동등성을 선언하지 않는다. 사건 단위 paired 결과와 불확실성을
보고하고, 자료 규모/독립성이 부족해 허용 폭 내라고 뒷받침하지 못하면
판정은 inconclusive다. 동일 사건의 창이나 실행 seed를 독립 사건으로 세지 않는다.
기준 정확도에 도달하지 못한 모델의 빠른 시간을 '동일 성능의 효율 개선'이라 하지 않는다.

정확도·시간·RAM 중 모두 나쁜 선택은 제외할 수 있지만, 모든 축이 더 좋은 하나의
모델이 없으면 trade-off 자체를 보고한다. TT75.08%와98.80%는 비슷한 정확도가 아니다.

## C. 적은 학습 사례에서의 안정성

단위는 창/서비스 행이 아니라 **라벨이 붙은 고장 사건**이다.
후보 서비스가 학습에서 원인으로 등장한 적이 있는지 모든 방법에 공통 보고한다.
현재 SN/TT는 서비스당 고장3종×각1회뿐이다. 사건 fold에서 한 사건/서비스를
검증에 두면 학습에는 두 사건/서비스가 남는다. 따라서 현재 가능한 수준은
1사건/서비스와2사건/서비스이며, 다점 학습 곡선이라고 부르지 않는다.

한 사건 수준은 서로 보완적인 두 부분집합으로 만들어 선택에 따른 변동도 확인한다.
정상 기준 자료는 fold의 정상 TRAIN만 고정 제공한다.
선택되지 않은 고장 사례를 특징 표준화·모델 학습·선택에 이용하지 않는다.
초기화 seed11/23/37 및 사건 부분집합별 결과를 모두 보고한다.
더 많은 독립 반복 수집 전에는 작은 표준편차만으로 일반적 안정성을 주장하지 않는다.

## 평가/판정

주지표는 사건 균등 평균의 원인 Top-1이다. Top-3, MRR 및 사건 단위 paired bootstrap
신뢰구간을 함께 보고한다. 같은 사건의 창과 모델 seed를 따로 재표집하지 않는다.
동일 수집 실행에서 사건들이 상관될 가능성도 밝힌다. 창 단위 Top-1,
유형별 점수, 동점과 관측 누락은 보조로 보고한다.
단순 선형/수치 기준, 전체 문맥 MLP, 상대 정보 제거, 관측 표시 통제 등은
논문 경쟁자와 구분된 내부 실험으로 사용한다.
새 fold도 개발용이다. 기존 최종시험은 계속 봉인한다.
