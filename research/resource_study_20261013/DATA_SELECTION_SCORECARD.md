# 연구 데이터 선정용 평가표 v3 — RCABench 실측 관문 반영

> RCABench를 실제 검수해1,422사례/단일 항목369개/최소 양모달 관측 지원350개를 확인했다.
> 현재9채널과의 동등성·독립 사건 수는 미확정이므로 초기70점은 현 순위에서 보류한다.
> [실제 근거](../rcabench_assessment_20261013/REPORT.md). 다른 후보 점수는 기존 조건부 판단을 유지한다.
> 이10개 후보가 모든 공개 자료를 망라하거나 최종 선정을 뜻하지 않는다.

## 현재 범위

사용자 요청에 따라 **평가가 먼저**다. 별도 허용한 native 개발 스모크와
RCABench 확보·검수는 완료했지만, 이를 다른 다운로드·본실험·튜닝·최종시험 승인으로 확대하지 않는다.
평가 대상은 원인 서비스 순위화, 메트릭+trace, 사건 단위 검증, 자기 처리 시간/오류/
상대 변화 등 제안 특징의 검증이다. 자료가 많거나 현재 모델이 잘 맞힌다고 높은 점수를 주지 않는다.
아래 점수는 모델 정확도·통계적 추정·출판된 평가점수가 아니라 **근거를 공개한 수동 선정 판단**이다.

## 평가 기준: 총100점

| 기준 | 배점 | 평가 내용 |
|---|---:|---|
| 과제·정답 일치 | 20 | 단일 원인 서비스 정답, 시각/대상, 명확한 변환 규칙 |
| 제안 특징 지원 | 30 | 메트릭, 부모–자식 trace, 시간, 오류/상태, 관측 밀도, 정상 기준 |
| 사건 규모·조건 다양성 | 25 | 의미 있는 사건 수, 대상/유형/반복/수집 조건; GB나 행 수와 구분 |
| 확인 근거·재현 준비도 | 15 | 출처, 검수, 정답/시간/단위 설명, 공개 코드/사용조건의 명확성 |
| 준비 비용 | 10 | 획득·정렬·변환·전체 비교군 전처리의 예상 부담; 높을수록 부담 낮음 |

각 항목을0~5등급으로 판단하고 `항목 배점×등급/5`를 합산한다.
5=요구에 잘 맞고 근거 충분,4=대체로 적합하나 일부 제한,3=조건부 적합,
2=큰 제한/준비 부담,1=매우 제한적,0=현재 요구에 부적합.
미확인은 실제 데이터가 나쁘다는 판정이 아니다. 준비도/확신을 낮춰 표현한다.
미검수 후보의 특징·비용 평가는 메타데이터 기반이다.
RCABench의 실제 자료 census도 방법별 학습·전처리의 공정한 비용 실험과는 구분한다.
1등급 조정만으로 특징 점수6점이 바뀐다. **5점 안팎의 차이를 확정적 순위로 읽지 않는다.**

## 용도 관문: 점수보다 우선

1. **최종평가:** 이미 학습/설계에 사용한 사건을 새 미접촉 최종 사건으로 부를 수 없다.
   현재 SN/TT는 이 관문을 통과하지 못한다. 새 교차검증은 개발 평가로는 가능하다.
2. **정답 단위:** 서비스↔pod↔host를 근거 없이 합치지 않는다. Bank는 현재 서비스 매핑이 미해결이다.
3. **입력 계약:** parent ID 존재만으로 self-time이 정확하다고 하지 않는다.
   필수 채널의 실제 행·단위·관측 기간이 확인되기 전에는 모델 투입을 확정하지 않는다.
4. **자원/조건:** 전체 비교군의 전처리 비용과 이용조건이 연구 범위에서 수용 가능한지 확인한다.
   높은 종합점수로 큰 실행 비용 또는 라이선스 불명확성을 상쇄하지 않는다.

## 특징별 판단

- SN/TT는 기존9채널 처리와 source hash 검수가 되어 있다.
  하지만 SN 오류/상태 태그 커버리지는12.73%이고, TT는 태그 대부분이200이다.
  두 자료 모두 parent참조는 풍부해도 정확한 intrinsic CPU time을 뜻하지 않는다.
- RCAEval RE2/RE3는 parentSpanID/statusCode 등의 스키마가 있지만
  이번 연구의9채널·self-time·오류 해석이 전부 검증된 것은 아니다.
- GAIA는10개trace 대상 모두7월 CPU/memory/network 후보 파일이 있으나
  working-set 동일 이름이 없고 counter/단위 대응도 미검증이다.
  실제 관측 밀도가 높을 것이라고 파일크기만으로 추정하지 않는다.
- Market/Telecom은 parent 관계와 상태/성공 필드가 문서화돼 있지만
  모달리티마다 개체ID·시간 단위가 다르고 실제 행 품질은 아직 읽지 않았다.
- Bank는컴포넌트/pod 과제에는 의미가 있다. 현재 서비스 과제 점수가 낮다는 것이
  Bank 자체가 나쁜 데이터라는 뜻은 아니다.
- RCABench는 실제 UTC ns timestamp와 parent/duration/status 열을 확인했다.
  하지만 열 존재는 완전한 graph나 self-time의 검증이 아니다.
  단일 항목369개와 최소 정답 관측350개는 확인했으나 두 항목 정답의 expected-impact
  계약 및 메트릭 정보 손실로 입력 관문이 해결되지 않았다. 초기70점은 보류한다.
- LEMMA는 trace 부재가 아니라 스키마와 coverage 미확인이다.
  큰 원자료 용량을 독립 사건 수나 trace 관측 밀도의 증거로 사용하지 않는다.

## 선정 제안 — 아직 선정 확정/처리 승인 아님

1. **기존 개발 기준 유지:** SN/TT. 재수집 없이 입력·구현 회귀를 확인할 수 있지만,
   자체 방법의 주장을 이것만으로 완성하지 않는다. 새 최종평가로 재사용하지 않는다.
2. **표준 비교 후보:** RE2-OB/TT. 정답·반복·문헌 연결은 좋지만,
   Eadro/DiagMLP 고유 전처리까지 예산 안에서 유지할 수 있는지 먼저 판단한다.
   보호된36건은 개발 데이터로 전환하지 않는다.
3. **새 입력·정답 계약이 필요한 후보:** RCABench. 실제 자료의 규모는 확인했지만
   단일 원인과 expected-impact 목록, 손실된 메트릭 구분, 경계·관측 부족을 먼저 다뤄야 한다.
   과거70점으로 RE2와 우열을 비교하거나 새 최종 사건으로 자동 지정하지 않는다.
4. **독립 사건 규모 확대 대안:** GAIA7월. 점수62는 가능성 부정이 아니라
   정답 해석·실제 coverage·단위·이용조건의 불확실성을 반영한다.
   이 조건을 충족하지 못하면411을최종실험사건으로 확정하지 않는다.
5. **다른 서비스 구성/운영 조건 검증 후보:** Market. 전체OpenRCA335건이 아니라
  59개단일고장서비스후보를 기준으로 준비량과 통계적 한계를 판단한다.
6. RE3와Telecom은별도분포/보조검증, Bank는서비스 매핑 전 주실험 보류.
   LEMMA는사건 인덱스·서비스 매핑·trace 스키마·이용조건 해결 전 현 방향 주자료 보류.

한 데이터로 개발·공정 비교·독립 최종평가를 모두 해결하려 하지 않는다.
점수가 높은 자료를 자동으로 다운로드하거나, 제안 모델이 이기기 쉬운 조건을
결과를 보고 고르는 것은 하지 않는다. **현재 권고는 용도별 후보군 유지와 관문 확인**이다.

## 근거와 미확인

현재 모델의 정확도는 점수 입력으로 사용하지 않았다.
검토한 자료의 크기·주입/정답 기록·trace metadata·검수 결과를 근거로 판단했다.
정확한 크기·변환 규칙·해시·출처는:

- `storage_report.json`, `PREFLIGHT_REPORT.md`
- `openrca_gaia_audit.json`, `OPENRCA_GAIA_FINDINGS.md`
- `NEW_CANDIDATE_EVALUATION.md`
- `../native_reproduction_20261013/native_data_profile.md`
- `../native_reproduction_20261013/rca_native_cost.md`
- `../native_reproduction_20261013/data_evidence.md`

RCABench의 census 범위는 실제 검수 보고서에 명시했다.
모델용 변환·동등 비용 비교·최종 독립성은 검증하지 않았다.
입력·정답 계약을 정하지 않은 채 후속 모델 전처리·분할·학습을 자동 시작하지 않는다.
