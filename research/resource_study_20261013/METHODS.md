# 비교 연구 재선별 — 과제·입력·비용·규모·재현성

## 판정의 범위

비교적 작은 MLP의 정확도/비용과 사건·시스템 변화에서의 성능을 검증하는 후보 목록이다.
모든 RCA 논문을 망라한 목록이나 이미 실행한 공정한 새 비교 결과가 아니다.
데이터 선정 전에는 재학습·새 전처리를 하지 않는다.
기존 결과는 창 분할 개발 평가이며 사건 분리 결과로 바꿔 쓰지 않는다.

## 실제로 확인한 크기/비용은 어디까지인가?

현재 단일 실행(seed11) 기존 산출물:

| 로컬 구현 | 파라미터 | 기록된 학습+검증 시간 | 의미 |
|---|---:|---:|---|
| DiagMLP복원 SN | 75,810 | 54.74초 | 200epoch 실행, 선택epoch192 |
| DiagMLP복원 TT | 140,033 | 1,306.86초 | 200epoch 실행, 선택epoch27 |
| Eadro복원 TT | 66,178 | 1,385.42초 | 200epoch 실행, 선택epoch199 |
| 자체 local/relative | 각각3,457 | 기존12회 합계약247초 | 별도 특징·목적·배치·조기종료 규칙 |

시간 수치는 저장된 `summary.json`/자체 검증 기록에서 재사용했다.
해당 측정 경계에 원자료 전처리가 포함되지 않는다.
native 전체SN+TT Hawkes생성은 별도596초, 자체 특징 준비는 약21초였지만
사용 정보와 계산 범위가 달라 구조 하나의 효율 효과로 해석하지 않는다.
미래 예산 비교에서는 원자료 준비/모델 학습/새 사건 전처리/추론/RSS를 따로 측정한다.

**현재 구현에서는 그래프를 쓰는 Eadro의 TT파라미터 수가 DiagMLP보다 작다.**
'MLP=가벼움', '그래프=큰 모델'이라는 단정은 틀리다.
위 숫자는 정확한 저자 원형 전부의 크기나 동일 정확도 비용 비교 결과가 아니다.
DiagMLP의 선택epoch27을 사후에 알아냈다고200epoch실행 비용을27epoch 비용으로
소급해서 바꾸지 않는다. 모델 선택에 들어간 실제 비용을 보고한다.

## 선정과 보류

### 필수 비교 축

1. **가까운 신경망 비교:** DiagMLP복원본. 원래 위치 표현을 지워서 약화하지 않는다.
2. **비학습 수치 비교:** BARO scoring-stage와 사전 정의한 서비스 집계.
   prior 기준은 TRAIN root 빈도만 사용하며 신규 validation/final 정답으로 적합하지 않는다.
3. **다중 자료/그래프 성능 좌표:** Eadro복원본. 비용과 출력 과제 경계를 함께 표시한다.
4. **내부 요소 검증:** 로컬 MLP, 같은 문맥을 다른 방식으로 준 MLP, 선형 점수기 등.
   이들은 논문 경쟁자를 대신하지 않는다. DeepSets식 구조를 추가하더라도
   일반 구조 대조군이지 새로 재현한 RCA 논문 모델이라고 부르지 않는다.

### 추가로 중요한 후보

- PRISM은 전파된 외부 지연과 내부 상태를 구분하려는 문제와 비용을 직접 다룬다.
  단순히 그래프를 안 쓰는 비교군이라는 이유보다 **문제 기제가 가까워서** 검토 가치가 있다.
  다만 CPM의 내부/외부 분리 가정과 관측 충분성이 실제 자료에서 충족되는지 확인해야 한다.
  논문8.2ms를 우리 end-to-end 실행시간으로 옮기지 않는다.
  공식 코드를 확보하지 못한 상태에서 수식을 구현하면 '논문 기반 구현'으로 표시한다.
- controlled-MLP/PSC연구는 상대 특징·서비스prior·전이를 이미 다룬다.
  제안 방향의 신규성 검토에서 빠뜨리지 않는다. 동시에 미공개/별도 공개 artifact의
  결과를 실행 검증한 것처럼 취급하지 않는다.
- 관측 누락 견고성을 핵심 주장으로 삼을 때 TORAI의 조건 적합성을 더 확인한다.
  현재 단계에서 무조건 추가 실행하겠다는 약속은 아니다.

**동일한3,457파라미터의 실제 문헌 RCA모델을 확보한 상태는 아니다.**
같은 크기만 맞추려고 강한 선행법을 임의 축소하는 대신,
원형에 가까운 비교와 이름 붙인 budget/구조 대조를 구분한다.

## 원인 미학습 대상 조건의 직접 관련 후보: DéjàVu

후속 문제 재검토에서 DéjàVu(FSE2022)를 추가했다. 기존 표의 다른 방법보다
“원인 이력이 없던 대상의 진단”이라는 조건을 직접 평가한다.

- **과제:** 컴포넌트×고장 관련 지표군인 failure unit 순위화. 서비스 단위 변환이 필요하다.
- **입력:** 메트릭, FDG, 과거 장애 정답. class별 표현과 전체 unit의 집계·점수기를 공유한다.
- **비용:** 지표군 정의·호출/배포 관계→FDG 준비와 시계열/그래프 인코딩까지 포함해야 한다.
  우리 환경의 전체 비용은 미측정이다.
- **규모/학습:** GRU/CNN 표현, 다층 GAT와 공유 dense 점수기, 지도학습.
  원문4자료601건·3000epoch 설정이 있으나 파라미터 규모를 직접 검수하지 않았다.
- **재현성:** 공식 코드/README와 데이터 연결 확인, master
  `d1f082b086cef5597f5301a7b02882b5d0238ebe`. 설치·실행하지 않았다.

§5.5의 unseen은 과거에 해당 unit이 faulty 정답이었던 적 없는 경우다.
서비스의 모든 고장 유형을 제외하는 cold-root 설계와 완전히 같다고 단정하지 않지만,
**공유 scorer와 미관측 원인 대상 일반화 자체를 새로운 발상으로 제시할 수는 없다.**
상세 원문 근거·차이는 `COLD_ROOT_PRIOR_ART.md`에 기록했다.

## 원형과 변형의 경계

BARO0.2.0은 RobustScaler 적합 후 signed max를 사용한다.
논문의 절대 편차 설명과 구별하며 임의 절댓값 변경 결과를 같은 이름으로 섞지 않는다.
데이터 특화 열 제거 옵션으로 정답 후보를 사후에 줄이지 않는다.
전체 방법 비교에서 각 방법의 고유 전처리는 유지한다.
공통 특징으로 바꾼 비교는 별도의 adapted/component 실험이다.
