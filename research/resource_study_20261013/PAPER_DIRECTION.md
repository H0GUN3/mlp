# 가장 현실적인 논문 방향 제안

> **현재는 보류된 제안이다.** 사용자는 이후 `원인 진단 정확도 중심`을 선택하고
> 연구 구체화·스모크 테스트·논문형 보고서를 요청했다.
> 현 실행 계약은 `../relationship_smoke_20261013/PROTOCOL.md`이며,
> 이 문서의 선택적 진단을 현재 연구 목표로 자동 적용하지 않는다.

## 권고

현재 구현·자료·검증 상태를 기준으로, 새로운 GNN/MLP 구조를 주기여로 삼기보다
**불완전 관측 환경에서 원인 서비스 진단의 신뢰도와 선택적 진단을 검증하는
실증 연구**를 우선 후보로 제안한다.

가제:

> **관측이 부족할 때 원인 서비스 진단을 언제 신뢰할 수 있는가?**
> — 관측 품질과 진단 보류의 실증적 평가

이는 사용자가 채택한 최종 주제나 구현·학습 승인이 아니다.
현실적이라는 판단 기준은 기존 진단기를 재사용할 수 있고,
인과적 오답 기제를 먼저 입증하지 않아도 평가 가능하며,
관측 부족이라는 확인된 제약을 직접 다룬다는 점이다.
논문 게재 가능성이나 새로운 학술 기여를 보장하지 않는다.

## 좁은 문제와 출력

장애 구간과 원인 서비스 후보가 주어진 상황에서,
관측이 부족한데도 진단기가 하나의 서비스를 자신 있게 선택하는 오류를 줄이고자 한다.

출력은 우선 두 가지로 제한한다.

- 충분한 근거가 있으면 원인 서비스 후보를 제시한다.
- 근거가 부족하면 진단을 보류하고 사람의 추가 조사가 필요하다고 표시한다.

새로운 장애 탐지기, 자동 복구, 능동 trace 수집, 모든 미지 고장/새 시스템 대응,
새로운 그래프 구조 학습까지 한꺼번에 포함하지 않는다.
관계 정보는 평가할 진단 근거 중 하나이지 반드시 추가해야 할 모델 구성요소가 아니다.

## 왜 현재 상황에 맞는가?

1. 기존 상대 MLP의 개선은 있지만 강한 선행법보다 우수하거나 인과적 분리를 한다는 근거가 없다.
2. 서비스 이름 없는 공유 점수기는 DéjàVu 등과, 방향성 활용은 TraceRCA/CIRCA와 겹친다.
3. 희소 trace·부모/자식 시간 불일치·오류 태그 누락은 기존 사전점검에서 확인됐다.
4. 이 조건에서 “정답률을 조금 높이기”뿐 아니라 “잘못된 확신을 줄이는지”를 평가할 수 있다.
5. 기존 진단기와 단순 규칙을 유지하므로 새 복잡한 모델의 학습·재현 비용을 강제하지 않는다.

단, 관측이 부족하다는 사실만으로 지금 진단기가 과신하거나 제안 gate가 유효하다는
결론은 나오지 않는다. 이 인과·성능 주장은 새 평가가 필요하다.

## 선행연구와 차별성 관문

진단 보류 자체는 새로운 발상이 아니다.

- Selective Classification for Deep Neural Networks(NeurIPS2017)는
  정답을 내리는 비율(coverage)과 답한 사례의 오류(risk)를 교환하는 접근이다.
  해당 연구의 가정을 확인하지 않고 임의 분포 변화에서의 위험 보장을 가져오지 않는다.
- CoreSec의 arXiv2608.21412 초록은 noisy/partial/asynchronous telemetry를 가진
  datacenter Clos network RCA에서 명시적 abstention을 설명한다.
  원문 전체·실험·배포 주장은 이번에 독립 검수하지 않았다.
  네트워크 RCA와 마이크로서비스 service localization은 구분하되,
  “RCA에 처음 보류를 도입”한다는 주장은 불가하다.
- DéjàVu는 이미 관계 누락이 심하면 graph 집계가 없는 모델보다 악화될 수 있음을 평가했다.

따라서 기여 후보는 단순히 confidence threshold를 붙이는 것이 아니다.

> **사건 단위로 분리된 평가에서, 실제로 관측할 수 있는 자료 품질 정보가
> 진단 점수만 사용한 보류 기준보다 같은 진단 비율에서 오진을 줄이는가?**

관측 품질은 span 관측량, 필수 채널 결측, 관측된 부모 연결·시간 정합성 등
실행 시 계산 가능한 정보로 제한한다.
정답 원인 서비스의 관측률, 완전한 graph와의 차이, 미래 정보는 gate 입력에 사용하지 않는다.
현재 자료에서 계산 가능하다는 사실과 오류 예측에 실제로 유효하다는 것은 별개다.

## 최소 평가 구성 — 제안이며 미실행

진단기는 현재 공유 MLP와 실제 문헌 방법(BARO, 입력 정합성이 확인되면 TraceRCA 등)을 사용한다.
논문 원형과 공통 특징으로 바꾼 adapted 모델은 구분한다.
그래프 모델을 추가하는 것은 필요성과 재현 비용을 확인한 뒤의 선택이다.

각 진단기에 다음 기준을 비교한다.

1. 항상 답함.
2. 진단 점수·1/2위 차이 등 점수 기반 보류.
3. 관측 품질만 이용한 단순 보류.
4. 점수와 관측 품질을 결합한 보류.

모델 학습 사건·보류 기준 선택/보정 사건·평가 사건을 구분한다.
같은 주입의 시간 창을 세 역할에 나누지 않는다.
현재 사용했던 사건의 새 분할은 개발 검증이지 새 최종시험이 아니다.

주지표:

- **coverage:** 전체 사건 중 실제로 진단한 사건의 비율.
- **selective risk:** 진단한 사건 중 오진한 비율.
- 같은coverage에서의risk 및risk–coverage곡선을 주로 비교한다.
- coverage=0이면risk를0으로 표시해 성공처럼 보이지 않는다.
- 전체 사건 기준 성능·보류 수, 관측 조건별 결과, 사건 수준 불확실성도 함께 보고한다.
- 비용은 기존3축 중 특히 gate까지 포함한 전체 진단 시간·메모리를 표시한다.

100건 중80건에 답하는 조건의 예라면, 서로 답한 사건이 달라도
각 방법의80건 중 오진 수를 비교한다. 이 숫자는 설명용이지 합의된 운영 목표가 아니다.
99건을 보류해 남은1건만 맞힌 결과를 개선으로 주장하지 않는다.
threshold와 운영점을 최종 평가 결과로 고르지 않는다.
실제 수집 누락과 통제된 인위적 누락은 별도 표로 보고한다.

## 진행/중단 기준

- 단순 점수 기반 보류보다 낫지 않으면 새 gate가 필요하다는 주장을 중단한다.
- 효과가 한 자료·한seed·사후에 고른coverage에만 있으면 일반적 개선으로 보고하지 않는다.
- 현실적인 수집 조건을 근거로 만들 수 없으면 random masking만으로 운영 실용성을 주장하지 않는다.
- 기존 연구가 같은 조건·정보·결정 규칙을 이미 다루면 차별성을 다시 검토한다.
- SN36/TT81처럼 반복이 적고 이미 개발에 사용한 자료만으로 강한 결론을 내리지 않는다.
  추가 독립 사건 확보는 여전히 중요한 진행 조건이며 RCABench 유효 규모는 미확정이다.
- 단순한 비교 결과만으로 실증 논문이 자동 성립하지 않는다.
  새로운 운영상 발견 또는 재현 가능한 의미 있는 이점이 있어야 한다.
