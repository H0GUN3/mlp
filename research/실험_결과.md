# 개발 단계 실험 결과

이 문서는 실제 실행한 결과를 모은다. 학습된 제안 모델, 독립 시험 성능,
논문 방법 전체 재현 또는 새로운 방법의 우수성을 보고하는 문서가 아니다.

## 1. 실험의 공통 범위

- 목표: 알려진 장애 시작 시각 이후의 **원인 서비스 진단**.
- 데이터: 고정 RCAEval RE2-OB/TT에서 개발용으로 예약한 36건.
- 구성: 시스템×원인서비스×장애유형 **12그룹**, 그룹당 반복 3건.
- 첫 LLM 스모크는 이 중 12건이다. 12건과 36건은 독립 데이터셋이 아니다.
- 다른 144건의 관측자료는 이번 후속 개발 분석에 사용하지 않았다.
  144건을 최종 시험 집합으로 확정한 것은 아니다.
- 정답 서비스·장애 유형·사례명은 점수기/LLM 입력에서 제외하고 선택·채점에만 사용했다.
- 원본과 첫 결과는 유지했다. 결과를 보고 동일 실험의 임계값이나 프롬프트를 바꾸지 않았다.

## 2. 첫 LLM 스모크: 12건 × 4조건

사전 명세: [SMOKE_PROTOCOL.md](SMOKE_PROTOCOL.md).
메트릭 변화·트레이스 지연 요약 카드는 동일하게 유지하고 호출 쌍만 바꿨다.
로그는 사용하지 않았으므로 완전한 다중 관측자료 RCA 평가가 아니다.

| 조건 | Top-1 | Top-3 | 평균 입력 토큰 |
|---|---:|---:|---:|
| 카드만 제공 | 1/12 (8.3%) | 1/12 (8.3%) | 2,603 |
| 전체 관측 호출 제공 | 1/12 (8.3%) | 5/12 (41.7%) | 2,836 |
| 규칙으로 최대 8개 호출 선별 | 2/12 (16.7%) | 8/12 (66.7%) | 2,668 |
| 같은 개수의 호출을 고정 난수로 선별 | 1/12 (8.3%) | 5/12 (41.7%) | 2,668 |
| LLM 없는 중앙값 변화 기준점 | **11/12 (91.7%)** | **12/12 (100%)** | 해당 없음 |

모델은 로컬 **Qwen3:8b, 8.2B, Q4_K_M**, Ollama 0.9.0이다.
temperature 0, seed 20261012, think=false, context 16,384, 생성 한도 384를 고정했다.
실제 digest와 원본 요청/응답은 `smoke/model-metadata.json`, `smoke/requests/`,
`smoke/responses/`에 있다.

- 48개 응답은 유효 형식으로 완료됐다. 저장한 정답·익명 ID·순위를 독립 대조했다.
- 규칙 조건은 각 LLM 비교 조건에 대해 1승·0패·11동률이었다.
- 한 건의 차이를 통계적 개선이나 재현 가능한 일반 우위로 주장하지 않는다.
- 규칙과 무작위의 토큰 수가 같아도 이 작은 결과만으로 학습 선별의 필요성은 입증되지 않는다.
- 단순 수치 기준점과의 격차가 크므로 이 LLM 설정의 추가 가치는 확보되지 않았다.
- 사후 합성 점검 2건은 모두 맞혔지만, 실제 관측자료 해석 능력까지 검증한 것이 아니다.
- 요청당 약 1초라는 서버 기록은 전처리를 제외한다. 이를 전체 진단 소요시간으로 쓰지 않는다.
- 결과가 나온 뒤 실험용 로컬 서버를 종료해 GPU 자원을 반환했다.

## 3. 후속 수치 기준점: 개발용 36건

사전 명세: [BASELINE_PROTOCOL.md](BASELINE_PROTOCOL.md).
원래 12건의 중앙값 기준점 순위는 그대로 재사용했고 동일한 11/12·12/12를 확인했다.
새 24건에 대해서만 같은 특징 규칙을 적용했다.

| 방법 | Top-1 | Top-3 | MRR |
|---|---:|---:|---:|
| 기존 중앙값 변화 기준점 | **30/36 (83.3%)** | **35/36 (97.2%)** | 0.8889 |
| BARO 코드 정렬 점수기 재구현 | 10/36 (27.8%) | 30/36 (83.3%) | 0.5573 |
| 같은 전처리의 절댓값 최대 변화 변형 | 10/36 (27.8%) | 30/36 (83.3%) | 0.5570 |

**BARO라는 이름의 범위를 주의해야 한다.** 0.2.0 고정 소스의 알려진 시작 시각
RobustScorer 경로를 NumPy로 재구현했다. 원저자의 전체 패키지/탐지기를 실행하거나
논문의 수치를 재현한 것은 아니다. 따라서 “BARO 전체보다 우수하다”라고 쓰면 안 된다.
전처리·구간·점수식 차이는 [method-note.md](baselines/method-note.md)에 있다.

중앙값 기준점과 BARO 정렬 점수기는 전처리까지 다른 방법 묶음이다.
반면 signed와 absolute 변형은 같은 전처리를 쓰며, 이번 Top-1에서는 차이가 없었다.
따라서 “절댓값을 쓰면 문제가 해결된다”는 주장도 이 결과로는 성립하지 않는다.

### 장애 유형별 Top-1

| 장애 유형 | 중앙값 변화 | BARO 코드 정렬 | 절댓값 변형 |
|---|---:|---:|---:|
| CPU | 6/6 | 2/6 | 2/6 |
| 지연(delay) | **1/6** | **0/6** | **0/6** |
| 디스크 | 6/6 | 3/6 | 3/6 |
| 패킷 손실 | 6/6 | 2/6 | 2/6 |
| 메모리 | 5/6 | 3/6 | 3/6 |
| 소켓 | 6/6 | 0/6 | 0/6 |

여기서 지연 6건은 **독립적인 장애 조건 두 그룹의 반복**이다.
5건 실패를 서로 다른 실패 원인 5개로 세면 안 된다.

### 무엇을 추가로 따져야 하는가?

중앙값 기준점의 6개 실패 중 5개가 지연에 집중됐다. 그러나 이것만으로
“피해 서비스가 원인보다 더 강하게 변해 오진했다”고 확정할 수는 없다.
해당 기준점은 변화 점수를 100으로 자르고 익명 ID로 동점을 처리한다.
예컨대 `re2ob_checkoutservice_delay_1`에서는 여러 서비스가 100점으로 묶인 상태에서
원인이 3위였다. **점수 표현이 만든 모호성과 실제 원인 구분의 어려움을 먼저 분리해야 한다.**
전체 실패에 대한 판정은 [압박 평가](연구_타당성_압박평가.md)에서 다룬다.

## 4. 결과로 말할 수 있는 것과 없는 것

**말할 수 있는 것**
- 고정 데이터에서 관측자료를 읽어 익명 특징·원인 순위·채점 결과를 만드는 파이프라인이 동작한다.
- 이번 LLM 설정은 단순 수치 기준점보다 크게 낮았다.
- 현재 점수기들의 실패가 동일하지 않으며, 지연 그룹을 추가 점검할 이유가 있다.

**아직 말할 수 없는 것**
- 제안 방법이 기존 연구보다 우수하다.
- LLM이 RCA에 필요하거나, 반대로 모든 LLM이 불필요하다.
- 원인/피해 혼동이라는 핵심 난제를 확인·해결했다.
- 관측 호출로 실제 인과 전파 경로를 복원했다.
- 개발용 36건으로 통계적 유의성·운영 환경 일반화를 입증했다.
