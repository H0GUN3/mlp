# 스모크 테스트 사전 명세 — 2026-10-12

이 파일은 진단 결과를 얻기 전에 작성한다. 이후 변경은 이유와 시점을 별도 기록한다.

## 목표와 한계
- 대상: 한 장애 사고에서 관측된 여러 서비스 이상 중 원인 서비스를 진단한다.
- 목표 성능은 진단 정확도/입력 비용이다. 서비스 복구 또는 응답 시간 개선 실험이 아니다.
- 가설: 동일한 서비스 근거 카드에서 불필요한 호출 관계를 줄이면 원인 진단에 도움이
  될 수 있다. 효과는 아직 미확인이다.
- RCAEval에는 전파 연결 정답이 없으므로 호출을 인과 정답이라고 부르지 않는다.
- 이 스모크는 규칙 선별의 가능성 점검이다. 학습 선별기나 논문 baseline 전체 재현이 아니다.

## 데이터와 표본
- 기존에 검수한 고정 RCAEval RE2-OB/RE2-TT 180건만 사용한다.
- 각 시스템 × 장애 유형(cpu, delay, disk, loss, mem, socket)에서 1건씩, 총 12건.
- 난수 seed 20261012, 후보 이름 정렬 후 Python random.Random으로 선택한다.
- 선택 사례의 같은 시스템/원인서비스/장애유형 반복 3건은 모두 개발용으로 예약한다.
  본 실험의 최종 시험 데이터에는 포함시키지 않는다.
- 제외 없이 사전에 선택한다. 로그 누락 등은 관측 불가로 표시한다.
- 정답과 사례명은 표본 선택·채점에만 사용한다. 예측 입력은 익명 사고·서비스 ID,
  정상/장애 구간의 수치 요약, 관측된 호출 쌍뿐이다.
- 주입 시각을 알려진 장애 시작 시각으로 사용한다. 온라인 장애 탐지 실험이 아니다.

## 최소 특징과 입력
- 메트릭의 정상/장애 중앙값 차이를 정상 IQR로 나눈 절댓값을 계산한다.
  분모 하한은 max(정상 중앙값 절댓값 × 0.05, 1e-9)로 고정하고 점수는 100에서 자른다.
- 유효 관측치가 각 구간 20개 미만인 지표는 점수를 만들지 않고 관측 부족으로 표시한다.
- 서비스 점수는 가장 큰 지표 변화 점수, 카드는 상위 3개 지표명·변화 점수·증감 방향.
- 서비스별 트레이스 지연 정상/장애 중앙값 비율과 관측 수를 추가한다.
  정상 관측이 없으면 비율은 null이다. 로그는 이번 최소 스모크 입력에서 제외한다.
  그러므로 이후의 다중 관측자료 실험을 검증했다고 주장하지 않는다.
- 호출 후보는 trace ID 안의 parentSpanID/spanID 연결에서 얻는다. 서로 다른
  서비스를 잇는 쌍만 남긴다. ID 충돌 쌍은 제외하며 후보에 정답을 사용하지 않는다.
- 호출 표시는 caller→callee이다. 장애가 이 방향으로 전파됐다는 뜻이 아니라고 명시한다.
- 서비스명은 사고별 난수 순열 ID로 바꾼다. 원래 서비스명·사례명·파일경로·장애 유형은
  모델에 제공하지 않는다. 모든 관측 서비스는 선별 전후 동일하게 카드에 남긴다.

## 비교
1. **기록만:** 동일한 서비스 카드, 관계 없음.
2. **전체 관계:** 카드 + 관측된 호출 쌍 전부.
3. **규칙 선별:** 카드 + 점수 높은 호출 쌍 최대 8개.
4. **무작위 선별:** 카드 + 규칙 선별과 같은 개수의 고정 난수 호출 쌍.

규칙 점수는 두 서비스 변화 점수의 최솟값이다. 두 끝점이 모두 변한 관계를 우선한다.
동점은 익명 ID 사전순으로 결정한다. 제공되는 쌍은 익명 ID 순서로 정렬하고 점수·조건
이름을 숨긴다. 규칙과 무작위는 토큰 길이가 완전히 같지는 않아도 연결 수를 같게 한다.
추가로 LLM 없는 단순 기준점인 '가장 큰 서비스 변화 점수'의 원인 순위를 계산한다.
이 기준점은 BARO나 MicroHECL의 전체 재현으로 표기하지 않는다.

## 모델과 실행
- Ollama의 공개 Qwen3:8b 로컬 모델, 다운로드된 digest/양자화/런타임 버전을 기록한다.
- 선정 이유: 공개 가중치, 현재 자원에서 실행 가능한 크기, 동일 모델 조건 통제가 가능함.
  다른 모델보다 우수해서 선택한 것은 아니다.
- temperature=0, seed=20261012, think=false, num_ctx=16384, num_predict=384.
- 응답은 후보 ID 중 원인 순위 3개를 담는 JSON. 동일한 system prompt와 schema 사용.
- 조건 실행 순서는 고정 난수로 섞고, 모델 사전 로딩과 워밍업은 채점하지 않는다.
- 모델은 사용자 계정의 별도 포트·모델 디렉터리에서 실행한다. 외부 API에 데이터를 보내지
  않고, 기존 프로세스를 중지하거나 공용/root 계정 설정을 변경하지 않는다.

## 채점과 진행 기준
- Top-1/Top-3, 유효 응답 비율, 입력·출력 토큰, 추론 시간, 사례별 paired 승/패.
- 잘못된 JSON/후보 밖 ID/중복 ID/생성 길이 초과는 실패로 남기며 정답을 보고 재질문하지 않는다.
- 12건의 탐색 결과로 통계적 유의성 또는 실서비스 일반화를 주장하지 않는다.
- 기술 통과: 48개 요청에서 입력이 잘리지 않고 모두 파이프라인을 통과한다.
  출력 실패도 결과에 남기며 기술 미통과로 보고한다.
- 효과 신호: 규칙 선별이 전체 관계·같은 개수 무작위보다 모두 높은 Top-1을 보이는지
  확인한다. 서비스 카드만으로도 같은 성능이면 관계 선별의 추가 가치는 미입증이다.
- 신호가 없으면 특징·입력·오류 사례를 조사하는 개발 단계에 머문다. 유리한 결과가 나올
  때까지 같은 12건의 규칙을 고쳐 본 실험 점수처럼 보고하지 않는다.
- 다음 단계의 감독학습 확장은 정답 형태와 관련 연구 대비 차별성이 정리된 후에만 한다.
